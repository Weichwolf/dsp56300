Architectural DSP instruction cache

The seven cache-control instructions have explicit implementations, independent
encoding/state/sequence fixtures and separate cache-storage/integration models.
This is architectural DSP storage, separate from decoded instructions and x64
translations. clear_code_cache invalidates the host translations only; it must
not flush DSP instruction words, locks or pending vectors.

Host configuration

Options.cacheable_begin/cacheable_end declare one half-open external P interval
eligible for instruction caching when SR.CE is set. The default empty interval
keeps every supplied P word directly accessible; no derivative memory map is
invented. Options.cache_sector_words is 128 or 256, giving eight sectors and
1024 or 2048 DSP words. Reversed/out-of-address-space intervals and other
geometries are rejected at construction. The interval can extend beyond a
supplied span; requested words outside that span still fault. The host supplies
the derivative's internal/external map and cache/PRAM remapping behavior; the
library does not copy a board model or fabricate external bus/peripheral data.
Registers alone are not a cache/REP/vector checkpoint.

CE is bit 19 of SR, BE bit 10 of OMR. Storage is created lazily for enabled
cache accesses/controls. The cold object occupies 416 bytes on this Clang 19
x64 build, plus one contiguous 4096-/8192-byte word vector selected by geometry;
there is no per-hit/control allocation after creation. The usual Cpu remains
384 bytes; Core::Impl remains 131648 bytes after owner-field reordering. These
are layout/allocation facts, not cache-miss or speed measurements.
CE clearing and reset discard it. Toggling CE with BE
set or without the manual's required instruction separation is not qualified.

Qualified functional model

Eight associative tag registers and per-word valid bits select cached data.
Instruction fetch touches MRU; a word miss fills one word or the remaining words
of an aligned four-word burst. Prefetch is bounded by the declared external
interval and supplied RAM; optional unavailable burst words are not fabricated
or read outside the span. A requested missing word is still a fail-stop error.
Cache hits preserve old instruction data even after host RAM writes. A sector
miss replaces the least recent unlocked sector. Locked sectors remain in LRU
order but cannot be replaced. With all sectors locked, an absent sector fetch
uses RAM without allocating (a functional inference needing hardware confirmation); a lock/unlock miss leaves the cache unchanged.
A lock/unlock tag hit preserves valid bits/data and touches MRU. A miss allocates
an empty sector, changes its lock and touches MRU when replacement is possible.
PLOCK/PUNLOCK use memory-alterable EA modes, including long absolute, without
reading the addressed word. PLOCKR/PUNLOCKR add a signed 24-bit extension to the
instruction's own PC. Address updates and 24-bit wrap follow the ordinary AGU;
flags and unrelated registers are preserved. Immediate/reserved EA selectors
are rejected before allocating or changing a sector. Missing extension words
remain ordinary memory failures, not invented operands.
PFLUSH clears valid bits/tags/locks and resets replacement order. PFLUSHUN
preserves locked sectors, flushes unlocked sectors and resets the whole order.
PFREE clears locks without changing data, valid bits, tags or order. Reset tags
are all ones; initial order is physical sector 0 at MRU through 7 at LRU.
The model chooses the first physical sector if reset tags match simultaneously;
the actual hardware duplicate-tag priority remains unqualified.

Guest PMOVE reads use a valid cache word on hit and RAM on miss, without filling
or touching LRU. Guest P writes update RAM and, on sector hit, cache data/valid
bits without touching LRU; sector misses do not allocate. MOVEM and P-space
MOVEP use this common path. Host read/write/load access backing RAM directly,
like a noncoherent external agent. Host writes through P-aliasing X/Y spans
invalidate host translations but preserve DSP instruction contents. The same
noncoherence applies to guest data-space writes into a supplied P alias; only
explicit guest P writes perform the cache write-through operation.

With CE clear, cache controls request the common illegal vector instead of
silently acting as NOPs. EA updates are not performed in that disabled-mode
model. Requests use the explicit ILLEGAL resume convention (instruction PC+2),
coalesce/defer through REP and retain exact run budgets. Nominal instruction
base costs are retained for accounting; disabled-mode exception costs, EA
ordering and pipeline return details still require hardware qualification.
Single-word cache controls can repeat. Two-word forms cannot be REP bodies.

Execution and qualification limits

All CE-enabled instruction execution currently uses the general executor, on
reference, cached and JIT configurations. This keeps actual fetch order, word
fills, P transfers and replacement state independent of speculative translation.
A helper setting CE exits its native block before any successor; CE clearing
permits subsequent native dispatch. This is a guarded correctness fallback,
not an optimized native cache-enabled backend or a throughput claim.

The PLOCK opcode diagram incorrectly labels its row PUNLOCK; its bit pattern
and the independent authoring assembler distinguish PLOCK from PUNLOCK.
Complete instruction-pipeline prefetch, burst/bus timing and unavailable-burst
behavior, CE transition restrictions, duplicate reset-tag selection, complete
fast-IRQ/vector/event behavior, derivative PRAM remapping and exact disabled
exception sequencing remain open. Current fixtures and models qualify the
stated functional/library subset only; all seven ISA rows remain partial.
