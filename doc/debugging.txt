Functional DEBUG/DEBUGcc and host debug requests

DEBUG and all sixteen DEBUGcc encodings are implemented. A false condition
continues normally; a true condition preserves CCR/registers and requests debug.
The condition reads the current architectural flags, including fresh native ALU
results. Both instructions use the general executor and end translated blocks.
Current nominal base costs are DEBUG=1 and DEBUGcc=5. The unconditional/untaken
pipeline costs and exception overhead are not independently calibrated.

ProcessingState::debugging is an explicit halted state. run returns early and
later positive/zero budgets retire nothing, fetch no successor or invent I/O.
Core::resume_from_debug is required to continue. It clears the software occurrence
and changes only processing state; register/program edits and hidden REP/vector
continuations remain. Core::interrupt cannot replace a debug halt, including
level three. resume_from_stop cannot leave debugging, and duplicate/faulted/
reentrant debug requests or resumes are rejected. Cache clearing and register
initialization do not implicitly resume or clear the occurrence.

Qualified OnCE view

Core::set_debug_interrupt_mode configures the functional IME selection at stopped
host execution. Core::debug_status reports interrupt_mode and software_occurrence
(the qualified IME/SWO meanings), not a fabricated complete OSCR or serial JTAG
register file. Changing IME does not clear an existing SWO or convert a queued
request. Library reset clears these controls and pending work; guest peripheral
RESET preserves them in the current unchanged-core-state model.
With IME clear, a taken guest DEBUG/DEBUGcc halts and sets SWO. A completed host
DE/JTAG request through Core::request_debug halts without setting SWO. Host debug
requests can enter from running, WAIT or STOP at a stopped execution boundary;
required DE/PLL/oscillator stabilization stays with the derivative host. Resuming
does not put the CPU back into the prior WAIT/STOP state.

With IME set, a request queues a nonmaskable level-three vector at the captured
VBA bank plus offset 06 instead of halting. The request itself performs no vector
instruction. Future positive run budgets retire vector/handler instructions
exactly as with other internal exceptions. A host request retires no fabricated
DEBUG instruction and adds no guest instruction base cost. SWO remains clear
when no Debug mode is entered. The functional saved PC is the actual continuation
PC when the request is admitted, following the generic exception convention;
hardware confirmation of exact debug return/pipeline behavior remains required.

Pending requests coalesce without replacing an active vector, survive code-cache
clearing and retain the first captured vector bank even after IME/VBA edits.
They wait for REP completion and any currently active vector to finish. If that
vector entered a long handler, the nested debug frame saves that handler PC/SR;
if it was fast, it saves the post-vector foreground state. Earlier accepted
arithmetic, transfers and frames cannot be discarded. Admission starts a new
vector boundary under the existing library exclusion policy, not a calibrated
source-priority/pipeline arbiter. Invalid fetch/EA/push/I/O failures keep explicit
fail-stop errors and cannot fabricate service state or repeat requests.

Repeats and vectors

The functional model admits single-word DEBUG/DEBUGcc as REP bodies: IME-clear
execution pauses after the first taken iteration, with exact remaining LC and
instruction latch preserved across debugger resume/program edits. Remaining
conditional iterations reevaluate current flags. IME-set execution defers and
coalesces the vector until the repeat completes, including the zero encoding's
65536 iterations. These REP/debug interactions require hardware confirmation;
appendix A does not explicitly list DEBUG among prohibited REP bodies, but does
not fully specify their pipeline behavior either. No row is marked complete.

DEBUG/DEBUGcc are admitted in the qualified fast-vector subset. A halt after
the first word pauses before the second word, while the register PC remains the
foreground continuation. A halt in the second word resumes foreground code.
Host Core::interrupt returns on that halt; later run budgets finish the retained
vector only after explicit debug resume. IME requests from a vector are deferred
without replacing it. Host debug requests can likewise pause or queue behind an
already partially executed internal vector. This is a functional instruction-
boundary model, not an emulation of OnCE instruction-latch restoration.

Storage, validation and remaining work

IME/SWO/pending flags fit byte 332 of existing Cpu padding. The resolved pending
vector uses cold owner storage. Existing architectural/generated-code offsets,
actual structure sizes and limits are recorded in doc/coverage.txt; these are
layout facts, not a speed or cache-miss result.
Independent binary fixtures use a separate condition truth table, raw state,
integer ALU/rounding and bit-built frames. Version 3 explicitly records initial
IME and expected IME/SWO plus the debug processing state; older versions cannot
silently omit these expectations. Host witnesses require actual native work,
warm mode changes, resume edits, repeat/vector continuation and fail-stop cases.

The current functional interface does not implement serial OnCE commands,
OPILR/OPDBR/OPAB pipeline restoration, memory-breakpoint/trace counters, HIT/TO/
MBO status, ROM-security gating or pin-level timing. It does not fetch a successor
merely to reconstruct the hardware instruction latch before halting. Exact
prefetch/cache, simultaneous-source priority, VBA sampling, REP/fast debug return
behavior, reset/debug mode effects and all legal numerical/loop/interrupt
sequences still require qualification/implementation. Those remain part of the
complete objective; zero missing catalogue rows is not full ISA qualification.
