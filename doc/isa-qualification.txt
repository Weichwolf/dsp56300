Complete DSP56300 ISA qualification

Complete support and independent tests are a mandatory completion criterion.
The current implementation is partial. A passing CTest suite and successful
Blofeld/FFT routines prove only their tested subsets. Performance work does not
waive missing instructions, operand forms, numerical modes or observable effects.

doc/isa-coverage.tsv inventories the 117 distinct entries in the DSP56300FM
Rev.5 instruction summary (including MOVE subforms and mixed multiply forms),
plus the LEA alias identified with LUA in appendix A. These are catalogue rows,
not a count of disjoint opcodes or a percentage of full ISA support. The table
contains original project assessments and source/test pointers, not copied
manual descriptions or manufacturer programs. Detailed format expansion is
still required; a mnemonic-level list alone cannot prove encoding coverage.

Reference: DSP56300 Family Manual, Rev.5 (April 2005), chapters 3/4/5/12/13
and appendix A. Copies/extracts and private analysis remain in doc/local/.
Manufacturer URL: https://www.nxp.com/docs/en/reference-manual/DSP56300FM.pdf

Statuses:
  missing: no implementation for this instruction/family/form.
  untested: code exists, but dedicated independent qualification is absent.
  partial: linked tests cover some semantics/forms; the listed gaps remain.
  complete: all required forms/modes/effects independently qualified; no gaps.
No entry currently claims complete support. Existence of a test source is
evidence to inspect, not proof that every row/form it mentions is covered.

Audit commands:
  python3 tools/isa_audit.py
  python3 tools/isa_audit.py --require-complete
The first validates catalogue structure/evidence paths and reports the backlog.
The second deliberately fails while any row is incomplete. It is an additional
necessary completion gate, not a substitute for the semantic witnesses below.
It is not hidden behind a passing current-subset CTest result.

Before marking an entry complete, expand and qualify:
- Every documented encoding, extension width, condition and legal operand set;
  reserved selectors/opcodes remain explicitly distinguished from valid forms.
- All legal numerical modes/combinations, precision, rounding, saturation,
  flags written/preserved and old-input ordering with every parallel move class.
- Addressing and aliases, word/address wrap, short/long/immediate forms,
  register-field effects and fault/transfer boundaries without duplicate I/O.
- REP, DO/DOR/FOREVER/ENDDO/BRKcc, nesting, subroutines, stack/extension behavior,
  exact partial budgets and admitted IRQ/exception sequences.
- Core cache/control/STOP/WAIT/RESET/debug/trap behavior with explicit host/event
  contracts. Such instructions cannot be silently replaced by NOPs or invented
  peripheral replies just to pass a program.
- Documented instruction costs and architectural sequence restrictions; retain
  explicit limitations for uncalibrated pipeline/external-bus timing.
- Reproducible independently modeled binary fixtures and boundary/interaction
  tests on reference, cached and native backends in release and ASan/UBSan.
  Differential agreement alone cannot prove correctness of shared semantics.

Previous closure increment: INC/DEC now change the raw accumulator's least
significant bit (not its A1/B1 word), and CMPU compares zero-extended unsigned
48-bit operands while ignoring accumulator EXP bytes. CMPU preserves S/L/E/U,
clears V, uses arithmetic bit 55 for N, and tests low 48 bits for Z. Arithmetic
saturation is explicitly bypassed for CMPU as specified in section 3.2.3.
These additions still do not close all numerical modes or full ISA qualification.

Bit-field closure increment: EXTRACT/EXTRACTU, INSERT, MERGE and CLB now have
ordinary-mode implementations, including the specified saturation bypass.
Register and immediate control fields, aliases, extension/low-word preservation,
scaled status flags and all defined field-width/offset pairs have independent
per-bit fixtures. MERGE uses the described and diagrammed twelve-bit halves;
CLB uses the description's bit-55 polarity and explicit all-zero special case.
These resolve conflicting pseudocode indices using the manual's prose and
examples; independent hardware confirmation remains desirable. Signed EXTRACT
with zero width has no unambiguous sign bit in Rev.5 and currently returns an
explicit unsupported-mode diagnostic. This is a documented qualification gap,
not a claim that the hardware traps on this input. Undefined field ranges are
also rejected explicitly. SB/SC/DM operation, precise pipeline/event interactions
and complete ISA coverage remain open. None of these five rows is complete.

Loop-control increment: DO/DOR count operand forms, REP register/memory forms,
DO/DOR FOREVER and BRKcc now have implementations. Dedicated fixtures qualify
ENDDO too. Independent models exercise raw frames, the sixteen-condition truth
table, explicit nested execution traces and count/address coordinates. The new
LC-reading REP-zero cases distinguish architectural LC=0 on entry from the
private 65536 remaining iterations. SC and restricted count-transfer modes,
zero-DO scratch-stack hardware confirmation, stack extension, pipeline rules
and complete interrupt/event qualification remain open. In appendix A the DOR
FOREVER cost is blank; the implementation currently follows DO FOREVER's four
base cycles and does not claim independent timing qualification. No affected
catalogue row is complete.

Extended multiplication increment: four long-immediate forms, mixed MPY/MAC,
DMAC ss/su/uu and positive power constants n=1..23 have independent binary
fixtures. Signedness follows the written operand order and table 12-16/figure
3-7; DMAC follows the prose/diagram's 24-bit accumulator shift, not the short
operation notation's inconsistent 16. Explicit sign/selector encodings, arithmetic
and rounding overflow, negative discarded bits and cross-helper state are tested.
Power n=0 is still explicitly unqualified. SB/SC/DM/SM, hardware confirmation of
manual inconsistencies, full pipeline/event and other listed qualification gaps
remain open. No affected catalogue row is complete.

Address/iteration increment: LRA register/long, LUA/LEA updated/short-displacement,
DIV and NORM have independently modeled fixtures. The general AGU coordinate
and serial reverse-carry model is shared only between test generators. DIV has
a separate serial LSB-first arithmetic circuit and integer-division witnesses;
NORM has signed-coordinate shifts, flag boundaries and linear exponent updates.
The stated NORM NOP branch retains state; hardware confirmation of its complete
CCR behavior remains open. LRA/LUA destination fields are implemented according
to the explicit five-bit operand lists despite inconsistent notes. Actual manual
discussion pages correct summary-table page references for DIV/NORM/LUA. Other
modes and full pipeline/restriction/IRQ/event qualification remain mandatory.
No affected entry is complete. Section 3.2.3's SM bypass for mixed MPY/MAC and
DMACsu/uu also remains a specific unimplemented-mode gap in the previous increment.

Fast-normalization increment: NORMF now accepts all six documented source
registers and both accumulator destinations for signed counts -55..+56. It
reads the raw old source before writing the destination, performs a 56-bit
arithmetic shift, preserves C/S and sticky L, and updates the other arithmetic
flags even at count zero. The full-width right shift produces zero or sign
fill. Values outside the manual's stated source domain report unsupported_mode;
this is an explicit qualification boundary, not a claimed hardware exception.
The V description's bit-39 index is inconsistent with the stated 56-bit
operation. The implementation uses bit-55 sign changes, as for 56-bit ASL;
hardware confirmation remains required. Scaling affects E/U flag definitions
but not the raw shift width. SB/SC/DM/SM remain unsupported.
Independent per-bit fixtures cover every admitted count and raw source/dest
alias. CLB-to-NORMF chains calculate the leading run independently and assert
the final signed normalized interval, with separate aliased CLB chains. Partial
REP budgets, current-count rereads, DO-end saved LF/FV, Carry consumers and
native/helper/native prefixes exercise integration. This row remains partial;
no full-ISA, workload-performance or hardware-timing claim follows.

VSL increment: raw middle-word X stores and shifted low-word Y stores now have
independent bit-coordinate tests, including full accumulator preservation and
CCR preservation. Register/absolute EA forms, both sources/inserted bits,
qualified modifier arithmetic, REP/DO boundaries and native helper transitions
are explicit. Host tests separately qualify the library's X-then-Y callback and
partial-failure contract, source/AGU visibility, alias ordering and program-code
invalidation. This contract supplies no derivative peripheral arbitration or
atomicity beyond the documented interface; hardware confirmation remains open.
SB/SC/DM/SM, complete AGU restrictions, event/IRQ sequences and calibrated
pipeline/external timing remain qualification gaps. VSL is partial, not complete.

Reverse-carry increment: the scalar implementation now computes downward
carry/borrow prefixes directly, with a guarded nonzero-single-bit stopping-mask
path and a general fallback for zero/dense magnitudes. A serial bit circuit,
1185660 full architectural cases and the existing binary archives independently
qualify their tested operands/state; neither expectation model uses the new
prefix or stopping-mask formula. Eight binary DO cases check current-pointer
iteration and stack/CCR restoration. No instruction row becomes complete from
this optimization. Numerical modes, full AGU restrictions and pipeline/event
qualification remain open. Focused helper-loop speed is not audio/device speed.

Native multiple-wrap lowering increment: valid power-of-two rings now execute
through guarded x64 transfer code as well as the existing general executor.
Independent coordinate tests require actual native transfers, including paired
aliases, dynamic modifiers and failures before either prospective R commit.
Private source-built Comb- sample-loop expectations additionally check causal
feedback and transfer precision. This changes execution strategy for an already
implemented addressing subset; it closes no missing instruction, numerical mode,
displacement form or full-ISA catalogue row. Complete ISA qualification remains
mandatory regardless of any passing workload or performance improvement.

Displaced-MOVE increment: MOVE.X/MOVE.Y now support the separate signed seven-bit
and 24-bit-extension Rn-relative forms. They use current Mn, ignore Nn, and have
no implicit R writeback; explicit register destinations still apply after address
sampling. Long forms admit the legal on-chip register selectors, including
stack/control effects. Fixed-point transfers retain ordinary clipping/scaling
and sticky flags. Both forms use the general executor, with native helper
materialization and mode/invalidation boundaries. Long displacement takes
priority over the shared, prohibited bit-jump EA-extension slot.
Independent binary fixtures enumerate every valid encoding plus operand,
numerical-mode, alias and sequence witnesses. Directed host tests qualify I/O,
stack/memory failures, P aliases, extensions, observers and guest SR/M changes;
a private source-built sample entry now executes cursor publication and RTS.
No row becomes complete: other numerical modes, fast-IRQ admission, complete
AGU restrictions/sequences and pipeline/event qualification remain mandatory.

Selection/control increment: ANDI/ORI now include EOM, the OMR middle byte,
and are repeatable single-word instructions. Independent expectations exposed
both the missing legal selector and the incorrect REP prohibition. Exhaustive
host tests enumerate all old/immediate byte combinations for MR/CCR/COM/EOM;
reproducible fixtures enumerate every opcode and add numeric-mode/Carry consumer
chains, zero-count REP prefixes and CCR DO endings with saved LF/FV frames.
The raw register-byte matrix includes reserved/loop-bit patterns only to test
the byte operation. It does not qualify reserved-bit hardware readback, OMR
mode side effects, explicit LF/FV initialization/abort or prohibited sequences.
Legal MR REP witnesses change IPL only; DO-end witnesses target CCR only.
MAX/MAXM, NOT and TST additionally have independent full-width/per-bit models.
Signed and magnitude ties, the raw -2^55 magnitude, middle-word-only complement,
full-width TST flags, scaled E/U, preserved sticky flags, IFcc suppression and
IFcc.U updates are checked with representative legal parallel moves. Models
capture old ALU/bus inputs before writes. Tests include TST source overwrite,
clipped accumulator stores, pointer loads consumed by subsequent native code,
REP/DO boundaries and actual native/helper/native execution. Callback tests
check canonical dirty-native state, success/failure, reentry and P invalidation;
a failed transfer must not execute the ALU or retire, without promising transfer
rollback. Other numerical modes, full parallel/operand expansion, fast IRQ and
sequence/pipeline/event qualification remain open. All six rows move from
untested to partial; none becomes complete. Current catalogue totals are
15 missing, 5 untested, 98 partial, 0 complete. No speed/device claim follows.

Extended-MOVE increment: independent tests now qualify MOVE.I, MOVE.L and both
Class I/II MOVE.XR/MOVE.RY forms as partial. Every legal standalone bus-field
encoding is present, with all short immediate bytes/destinations, all eight
long registers, all valid addressing selectors and six supported numeric modes.
The authoring assembler separately validates the input words, never semantic
expectations. Signed quotient/remainder 48-bit scaling/limiting, raw field
preservation and independent ring/serial-carry models verify data/flags/AGU.
The long-load and mixed transfer failure paths now stop before subsequent
bus/destination effects; immediate selectors cannot become memory-store or L:
addresses. Independent failing witnesses precede these corrections. Host tests
qualify the explicit library I/O failure contract, including accepted first
stores, canonical native state, P aliases, wrapped extensions and no replay.
Tests cover representative old-input parallel ALUs, REP/DO prefixes/frames and
native consumers, not every legal ALU/bus/alias/sequence combination. S-scale
expectations follow the scaling-mode/rounding equations of table 5-1; that
manual's later S-bit table has conflicting scale labels. Hardware confirmation,
SB/SC/DM/SM, all IRQ/events and calibrated pipeline timing remain open.
The catalogue has 15 missing, 1 untested (RTI), 102 partial and 0 complete rows.
The completion gate must continue to fail; neither these tests nor any Blofeld
workload qualifies the complete DSP56300 instruction set or the full objective.

Return/interrupt increment: RTI gains dedicated per-bit frame and sequence
models, binary fixtures and host/native tests, moving the last untested row to
partial. Its discussion is on 13-167; the old summary-derived 13-168 reference
was incorrect. Successful frame tests use physical SP positions 1..15 and
positive SC with extension disabled; SP error-bit/extended-stack operation is
not modeled as a wrapping success case. Saved PC/SR bits, all CCR bytes,
consumer mode changes, nested frames and interrupted DO cleanup have independent
expectations. Failed RTI/RTS pops cannot supply zero return state. Failed long
interrupt fetch/EA/push cannot fabricate service state or retirement; EA rules
match ordinary control flow. Injected instructions now contribute documented
base costs to Progress, without claiming IRQ/pipeline overhead calibration.
Host tests require real native arithmetic across restored Carry/scaling/RM and
warm old-mode code. The existing post-return interrupt exclusion is qualified as
a library admission policy only. Forced missing-frame failure state is a library
contract, not hardware underflow/SE/UF/NMI semantics. Full stack extension,
automatic stack exceptions, restored-mode side effects, all legal sequences and
fast/vector/NMI/event/pipeline qualification remain open. The totals are now
15 missing, 0 untested, 103 partial, 0 complete; the full-ISA gate must still fail.

Software-exception increment: explicit ILLEGAL, TRAP and all TRAPcc encodings
now have independent state/sequence fixtures and native/vector boundary tests.
The three rows move from missing to partial: 12 missing, 0 untested, 106 partial
and 0 complete. Pending vector execution is bounded by the caller's instruction
budget; REP ILLEGAL defers and coalesces entry, whereas TRAP/TRAPcc cannot be
repeated. Native blocks stop before an outstanding vector, and cache clearing
cannot discard it. Host level-three admission shares the vector executor.
The CPU vector tables in DSP56300FM, AN1830 and DSP56303UM support VBA offsets
04/08. The ILLEGAL instruction page's 3E address conflicts with them. The model
uses the table addresses, aligned VBA banks and ILLEGAL's documented +2 return.
TRAP continuation follows the generic saved-PC convention and still requires
hardware confirmation. Literal 5/9 base costs are not a calibrated pipeline or
untaken-TRAPcc measurement. See doc/exceptions.txt for sources and contracts.
Independent models cover all CCR conditions, six supported numeric modes,
ordinary frames, service/RTI/foreground prefixes, fast one-/two-word services,
zero budgets and zero-encoded REP. Directed tests require actual native work,
fresh flags/modes, callback mutation, short/long vector calls and fail-stop on
missing operands, invalid addresses, full stacks or rejected I/O. They do not
qualify every fast/vector class, automatic illegal/stack sources, extended
stacks, VBA writable/readback masks, the ILLEGAL-at-LA pipeline anomaly, all
numeric effects or event/arbitration timing. The completion gate still fails.

Architectural-cache increment: all seven cache controls now have a functional
implementation and independent tests, moving from missing to partial. Catalogue
totals are 5 missing, 0 untested, 113 partial and 0 complete. This is not closure
of all ISA semantics or a relaxation of the full-ISA gate. The model separates
architectural tags/valid data/locks/replacement from host translation caches.
Independent map/age expectations check cache state; binary expectations use
separate opcode/EA/cost authoring, serial-carry/ring addressing and per-bit
exception frames. Host tests observe actual sector selection, noncoherent RAM,
P write-through, failure state and real native work across CE transitions.
Cache-enabled execution intentionally uses the general executor; translator
lookahead must not silently fill sectors or change LRU. Missing/invalid operands
cannot fabricate addresses or retire. Illegal requests while CE is clear use
bounded vectors/REP coalescing, with nominal base-cost and resume assumptions
explicitly provisional. The host supplies external eligibility/geometry, without
copying derivative mapping/peripherals. Full prefetch/burst/bus timing, CE-change
separation, automatic exceptions, reset-tag priority/all-locked fetch confirmation,
all modes/IRQ/events and cache/PRAM remapping remain mandatory qualification work.
See doc/program-cache.txt for the precise functional subset and primary source.

Processing-state increment: RESET, WAIT and STOP move from missing to partial;
2 missing, 0 untested, 116 partial and 0 complete rows remain. run must stop at
the first successful sleep, not continue or spin until its budget expires.
WAIT admits only a valid unmasked interrupt; STOP uses a separate host-completed
IRQA phase before normal arbitration/continuation. Guest RESET must be explicitly
accepted by a derivative callback and preserves CPU state. Missing/rejected
acceptance is a named fail-stop event error, never a silent NOP or Core::reset.
Independent state/sequence v2 fixtures record expected sleep and RESET scripts;
separate host tests require native work, complete frame/state/progress equality,
no callback replay/reentry, P mutation, all priority masks and cache retention.
The v1 bytes/limits are preserved; literal wire records and malformed v2 fields
are independently checked. Raw status copying does not qualify reserved-bit
hardware readback or every resulting mode effect. Current library reset is not
a physical RESET/boot implementation; CP/IPL defaults and held-reset behavior
remain open, alongside DE/debug/DMA wake, clock stabilization, precise pending
arbitration, full legal sequences and derivative reset side effects. Full ISA
qualification still fails by design; see doc/processing.txt for primary sources.
