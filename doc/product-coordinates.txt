Native signed-product coordinates

Scope and representation

Ordinary signed24 MPY/MPYR/MAC/MACR use exact signed64 host products. Guest raw56
accumulators remain aligned by eight host padding bits. The product therefore
needs a factor 2*256=512 before its optional accumulator addition. No public
CPU/context layout, numerical mode, native admission, event or memory contract
changes. All source words still come from the instruction's old-input snapshot.

Operand pattern      Host representation / emitted work
low-word first       SHL40/SAR31 gives signed24 *512; IMUL64 needs no final SHL9
mixed high/low       commute the product to put the low word first
both high words      existing SHL16/SAR40 on each, IMUL64 followed by SHL9
same selector        extract once, IMUL64 register with itself, then SHL9
MAC old A/B proved zero  omit accumulator read and ADD64
MAC unknown A/B      existing read/add, capture raw host OF immediately

For every signed24 x,y, |x*y*512| <=2^55, so the scaled intermediate is exact in
signed64. The low-word SHL40 isolates exactly 24 bits; SAR31 leaves exactly nine
low zeros and sign extension. A high-word SHL16/SAR31 would retain nine bits of
the OTHER low word: this transformation is intentionally restricted to low-word
operands. The both-high form stays general. Multiplication commutes within its
already captured old values; this never reorders guest transfers or callbacks.
Squaring once is exact before the existing scale. The change adds no host ISA.

The compiler's existing conservative signed-width domain supplies the zero
addend certificate. It requires an accumulating product and an old destination
width of exactly zero, before any parallel writes. New bodies start unknown;
helpers and observable transfers erase facts before/after. Other arithmetic and
mode cases retain their existing execution. The private range-disabled control
retains the accumulator load/add in the same build. Zero eliminates no guest
retirement and never substitutes a sampled register value for a proof.

Negation, wrapping accumulation, rounding, saturation and flag computation then
receive the identical aligned result. Carry preservation, raw/round/limit events,
sticky transfer flags and live false flags keep the existing contracts. A proved
zero addend cannot raw-overflow, and the independent proof still governs R10
initialization. PC/AGU/loop state, guards, exact budgets and canonical callback,
fault, invalidation, interrupt and return checkpoints are unchanged.

Independent witnesses

The new RX test passes 11217408 assertions per build. It executes all 128 ordinary
signed product forms, all six scaling/RM combinations with SM clear/set, both
range-analysis controls and four declared sequences. These are a plain product,
CLR plus product, CLR plus product with a parallel other-accumulator write, and
CLR plus product with a crossed X0/Y0 transfer. No helper executes. Every expected
complete register/CCR state comes from independent raw56 integer/rounding/table
and bus models, not the emulator. Exact instructions/cycles, native moves,
repeat/inhibit state and dirty canaries are checked.

For each code/sequence/control/mode the finite matrix uses 192 walking-bit cases
(24 bits, four rotations, complemented/ordinary words), plus 36 extrema pairs.
Words deliberately differ between upper/lower halves to expose contamination;
initial A/B include sign boundaries, extension gaps, zero and -1. Four CCR seeds
vary within the matrix. Existing native SM tests separately cover every CCR byte.
The matrix does not exhaust every word pair or complete hardware qualification.
Duplicate ALU/bus accumulator destinations remain excluded by the original move
planner; they are not claimed as qualified native encodings.

The expanded independent width matrix passes 8909837 assertions per build,
including the implication that every zero-addend certificate names an actual
old zero accumulator. Existing native accounting/alias/loop/budget/observer/IRQ
and 5120088 native SM witnesses remain. All 52 guest archives and their producers
stay unchanged. These are compiler representation improvements, not added ISA
semantics, application-specific recognition or a complete adaptive allocator.
