Native pure address updates

Design recorded before implementation

The continuous spectral stream executes 6138000 pure AGU updates inside its FFTs
and 1500 linear input rewinds per input second. Native lowering can remove
moves-only helper transitions for linear updates. This is a general opcode
optimization; programs and benchmark data are unchanged.

Admit only parallel update-group MOVE words with ALU byte zero. Four modes
select -N, +N, -1 and +1 for one of eight R registers. On every execution guard
current M low16 == ffff. Other modifiers retain general moves-only execution,
including reverse/ordinary/multiple-wrap and reserved-modifier failure. Existing
unsupported numeric-mode admission remains unchanged. Parallel nonzero ALU
updates remain in their existing path.

Value             Host location          Commit/observation
M low16           AX                     exact runtime guard, high M bits ignored
old R             CX                     CPU register load, no address dereference
N or unit         R9 / immediate         modulo24 arithmetic, signed N equivalent
next R            SI                     mask24, store to canonical R once
A/B               existing BP/BX cache   untouched; retain any dirty live value
SR/PC/counters    existing machinery     keep observer/fault publication conservative

Raw N24 add/sub followed by mask24 equals signed N24 arithmetic modulo 2^24.
No host RAM/I/O bounds apply: an address-only instruction may point beyond RAM
or into the I/O range without reading or writing either. It must not call Io.
A failed M guard must precede the R update so fallback does not update twice.

The dataflow classifier must explicitly state zero A/B/X/Y writes for pure AGU
updates. Its previous unknown-move assumption clobbers every bank, which would
otherwise discard live cached accumulators after a native address update.
Keep existing packed-retirement admission and observable-move classification;
fallback may fail and must retain precise preceding state, PC and counters.
No new public option, CPU layout or transfer-counter meaning is needed.

Independent validation must cover all indices/modes, signed N endpoints, R24
wrap, high M bits, same-code modifier reuse, no memory/I/O, mixed A/B/ALU prefixes,
callbacks, invalidation, rejection, faults, loops, budget partitions and numeric
modes. Compare full state and progress using the independent coordinate/flag
models. Keep every existing fixture archive unchanged. Use identical sustained
FIR/IIR/spectral inputs and saved baseline binary for performance comparisons.

Implementation and independent qualification

The emitted path reuses the transfer delta calculation but performs no transfer.
All other modifier values branch to the existing moves-only helper before any
R write. Data-bank liveness now explicitly preserves dirty cached A/B across
pure address updates. Numeric admission, status/PC/progress checkpoints and
packed-retirement restrictions remain conservative. No public API changes.

The new native-address-updates test performs 7096453 independent checks in each
build. Direct production-ABI generated-code probes install a rejecting helper
and no RAM, proving linear updates do not enter it. All R indices, four update
forms, six numeric modes, every CCR byte and edge R/N coordinates are covered.
Changed non-linear/reserved M values must reach the helper. Core checks cover
same-PC reuse, general fallback, dirty A/B prefixes, budget partitions, complete
callback observations, rejected I/O, code invalidation, faults and DO endings.
All 114 tests pass in release and strict, with no skips. All 48 binary archives
remain unchanged. This qualifies the stated domain, not complete ISA coverage.

Continuous matched release comparison

Saved baseline/candidate executables run identical fixture bytes pinned to the
same host CPU. Each process warms one input second and measures the next in the
same DSP instance. Order is baseline/candidate/candidate/baseline. No project
build or correctness job overlaps the capture. A formatter overlaps the first
FIR capture, so all four FIR runs are repeated after it finishes; original logs
are retained. External scheduling/frequency variation remains uncontrolled.
All compared complete states pass. No host-time overhead is subtracted.

FIR        0.306152..0.307333     0.280980..0.282056    8.22%
IIR        1.379493..1.389149     1.381854..1.386351    effectively unchanged

Candidate wall ranges are 0.283379..0.294732 (FIR), 1.498760..1.553402 (IIR)
and 1.093444..1.159071 seconds (spectral). CPU measurements better separate
executed work from the visible host scheduling variation; wall still decides
the package deadline. IIR and spectral both remain failures. This is not an
energy measurement, OS realtime guarantee or proof for other application domains.

Page-rounded generated code grows from 28672 to 32768 bytes for FIR and from
303104 to 344064 for spectral; IIR remains 45056. Reduced helper work trades
against larger generated code. This storage count is not hot-cache occupancy.
MAC/AVX2 batch and native transfer counts are unchanged.

Spectral helper retirements fall from 12483401 to 6358901. This is 6124500
instructions reclassified as native retirement, not that many removed C++ calls:
the non-linear guarded path still calls the moves-only helper. Source schedule
analysis predicts 4590000 eliminated linear transitions per measured second,
including wrapper rewind and excluding final-loop cleanup. That is source-derived
call traffic, not a measurement attributing elapsed host time to individual calls.

The default release bench remains red: FIR 0.278491 wall seconds PASS, IIR
1.401406 FAIL, spectral 1.161694 FAIL. Strict bench passes all three full-state
checks in report-only mode while retaining deadline failures. The complete-ISA
gate still fails with all 118 catalogue rows partial. Full objective remains open.
