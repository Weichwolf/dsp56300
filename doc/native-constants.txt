Guarded RAM regions with pre-use R constants

Proof extension

The region planner now records an optional 24-bit constant when an R0..R7
immediate assignment precedes the first address access through that same R.
A second constant before any such access may replace it. N-register assignments,
late R redefinitions and all otherwise unproved transfers still retain ordinary
execution. No program-specific signature, caller option or CPU layout is added.

The selector and each guarded loop header use the recorded constant for their
address range proof. They retain the original finite RAM bounds, M-profile,
nonnegative stride-N, ring and saved-PC/LC checks. The actual R assignment still
executes at its original guest instruction and retirement position. Thus the
old R may point outside RAM, including I/O, without being observed before its
replacement. Rejection changes no architectural state or memory.

State / effect                 Proof obligation
R immediate                    exact decoded low24 extension, before first use
old R                          irrelevant only where an assignment dominates use
R after prior loop body        never substituted for the next assigned constant
M/N                            original dynamic guards; no unproved N rewrite
aliased X/Y / finite bounds     original ordered transfers and combined bounds
program aliases / I/O           ordinary invalidation/callback path retained
PC / counters / flags / A/B     original complete checkpoints and flag liveness

The same generated ordinary path remains available when a bound/modifier/
stride/loop guard fails. An entry that starts after the assignment receives its
own metadata and proves the real current R dynamically. Immediate zero is a
valid known value, distinct from an absent constant. Constants neither remove
program-alias boundaries nor authorize conditional control or other modes.
The optional field is private compilation metadata; public canonical state and
memory/event/I/O contracts are unchanged.

Independent validation

A new helper-forbidden RX test passes 775408 assertions per build. It uses its
own declared transfer traces, raw arithmetic/status models and numerical AGU
walks. It covers all eight R destinations, ordinary and SM arithmetic, six
scaling/RM choices, all old CCR bytes, wrong old addresses including I/O and
upper bits, 24-bit extension masking, shortened banks and X/Y aliases. Boundary
shapes additionally cover linear unit/N/no-update and supported power-of-two/
non-power-of-two rings, zero/positive/negative N, constants at/over finite bounds,
changed modifiers, loop counts and every header return. Both progress lanes wrap
through 64 bits, including the extra word/cycle of the constant assignment.

Static witnesses retain rejection of N assignments, late R constants and P
aliases, and admit consecutive constants with the last actual value. Public-Core
checks compare every warm instruction prefix and same-PC host P-extension edit
through all three backends, block limits 1/4/64 and a disabled optimizer. They
compare complete registers, RAM/canaries, program memory and progress. Existing
region I/O, partial failure, P-edit, AGU/loop and saturation witnesses remain in
the full suite. These checks are selected domain witnesses, not full ISA or
complete numerical-mode/sequence/timing qualification.

The motivating continuous nonlinear feedback bank intentionally retains its
per-channel coefficient-base assignment. Fixture bytes, channels, inputs,
coefficients, arithmetic and guest instructions stay identical across the saved
ordinary baseline and the optimized region comparison. See nonlinear-stream.txt.
