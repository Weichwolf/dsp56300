Native status-register holding

Eligible native regions keep the DSP status word in the callee-saved host R14D
register. Arithmetic masks/merges and ADC/SBC carry reads use that value directly.
Clipped accumulator stores merge sticky S/L effects into the same host value.
This removes repeated SR loads/stores without changing flag definitions,
fixed-point coordinates, flag liveness or the order of parallel operations.
DSP arithmetic remains scalar x64; the earlier SSE2 retirement pair is separate.

Admission initially shares the guarded packed-retirement domain: optimization
enabled, at least four straight operations or a native loop continuation, every
operation already lowerable with a nonzero cost, nonempty native move plans,
and no stores through X/Y aliases of P. Unsupported modes, general-helper
regions and short straight runs retain canonical SR in memory. The admission
decision remains separate for controlled local performance comparisons. No
extra DSP instruction or numerical mode is declared implemented by this change.

Checkpoints and old-input ordering

Entry loads the complete status word. Every possible general move helper first
receives canonical SR, progress and accumulators. On return, generated code
reloads SR from Cpu before testing success or continuing. Merely preserving
R14 across a C++ call would be insufficient: a slow clipped transfer can add
sticky flags to canonical state. Reload also preserves the helper's partial
failure state. The shared exit epilogue publishes SR on normal, zero-retirement,
loop-guard, dirty-code and failure returns. Loop backedges retain current SR.

Previously R14 held the pointer to old parallel-ALU inputs. Eligible regions
instead load that pointer through NativeContext at capture/use sites. Transfers
capture both old ports before either destination commits; ALU sources still
refer to the old accumulator/data values when a move overwrites the same bank.
All address guards precede either prospective update. The noneligible path
continues using the old R14 pointer convention.

No public header, Cpu, Core owner or NativeContext layout changes are needed.
There is no new dependency, executable permission policy or virtual machine.
The ordinary single-thread ownership and callback/memory contracts still apply;
see doc/io.txt. Host observers receive state at the documented boundaries.

Independent tests

native-status-boundaries performs 196874 directed assertions. It exercises all
256 initial CCR bytes, six admitted scaling/rounding modes, four accumulator
seeds and every prefix of a chain containing NEG, ADC, ADD, MAC and RND with
clipped stores, paired accumulator loads and old-input conflicts. Independent
raw-56 arithmetic and quotient/remainder transfer models supply complete
registers and RAM. The matrix runs with native optimization enabled and disabled,
reuses warmed code and checks precise progress on every entry.

Additional cases warm native RAM paths before redirecting X to I/O. Observers
check every register, both progress fields and outgoing clipped words. Accepted
stores can add S/L before subsequent ADC/arithmetic; either store can reject.
Failure checks require the exact partial state and no replay. These new cases
do not claim to close every ordinary-MOVE read-failure or bus-error convention.
Existing native-retirement tests additionally cover SIMD-clobbering read
callbacks, rejected reads, P invalidation, counter/PC wrap and loop boundaries;
their 76931 assertions now check status-cache admission explicitly as well.

Both complete suites pass all 96 tests without skips: release 166.93 s, strict
469.07 s. All 99 project C++ translation units carry the required nonrecovering
sanitizer flags in the strict build. All 133 project C++ source/header files
pass formatting; the 40 public binary archives and quality policies are unchanged.
The structural ISA audit passes and the complete-ISA gate still fails, with
all 118 catalogue entries partial. No ISA row is completed by status holding.

Controlled workload measurements

Host: Intel Core i5-10400, Clang 19 release, CPU2 affinity, powersave governor
with dynamic frequency and a shared host. The parent is b415608. The matched
control changes only status admission to an expression false for all optimized
regions; packed retirement remains enabled. The other 38 core archive objects
are byte-identical to the candidate. There is no public control option or runtime
layout change. Text addresses are not guaranteed identical to the parent.

Each executable uses 64 warmups and nine trials. Three process runs rotate
parent/control/after order. Below are medians of their trial medians, ns/call.

Workload           Parent       Control      After        Actual MIPS
DSP FFT16           17819.31     17685.59     17664.54          63.4
DSP FFT64           83578.73     82794.91     82599.61          75.2
DSP FFT256         378088.50    385707.69    387451.12          82.8
DSP FFT1024       1759684.06   1799075.50   1793481.38          88.0

FFT16/64 are about 0.9-1.2% shorter than the parent; FFT256/1024 are
about 2.5%/1.9% longer. The matched-control FFT differences are nearly flat.
This does not establish a general whole-change speedup. Raw trials and artifact
identities remain local historical analysis.

The four cases execute the project's independently modeled DSP FFT. The
measured interval contains Core::run, timer and retirement-check overhead;
input restoration and compilation are outside. No application firmware is
used by current validation. The active target is general DSP execution.

Remaining compiler work

This optimizes state traffic within existing native-only regions. General
helpers, flag computation and dispatch remain material costs. A local,
single-step profile of the independently modeled FFT256 validates the complete
expected final state/RAM/progress and reproduces the ordinary benchmark's mix:
23808 native retirements and 8284 general helpers. ASR A/B alone account for
4096 helpers; accumulator-to-X0/Y0 register moves account for another 2048.
This identifies promising lowering work, not their elapsed-time contribution.
Single-stepping is not the benchmark, and cannot measure region/loop speed.
Native lowering must preserve rounding, carries, sticky flags, transfer
precision and every observable exit before those helpers can be removed.

The complete ISA, representative 270 MIPS, general whole-program execution,
continuous audio, fixed-load CPU/latency and energy requirements remain open.
