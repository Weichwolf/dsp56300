Native latched REP bodies

Ordinary and bounded JIT execution can run eligible one-word REP bodies directly
in emitted x64 code. The original REP instruction still establishes its genuine
count, body PC and saved LC. A zero count means 65536 iterations. Unsupported
operations/modes and owner effects retain the original executor and real I/O.

State and ownership

Entry             Source                         Result
unloaded body     pure known program metadata    no latch before actual retirement
loaded body       real retained decoded opcode   later backing-P changes ignored
accepted body     guarded ALU/MOVE/AGU           exact instruction/base-cycle progress
partial budget    remaining count and saved LC   body PC and decremented LC retained
ordinary end      count reaches zero             saved LC restored, sequential PC
DO ending         final body remains general     genuine loop-frame continuation/cleanup
rejected operand  complete pre-effect guard      no count/EA/ALU/port side effect

All native eligibility and precision guards of ordinary arithmetic, register
and X/Y transfers remain. Both data ports are checked before either changes
state; reads require actual known storage and stores obey permissions/aliases.
A late guard failure preserves the entire retired prefix. Completed accumulator
state is canonical before each backedge. No native REP data helper is called:
guard failure returns to the Core wrapper before any actual owner callback.
The wrapper updates the retained decoder only after positive retirement.

Instruction and base-cycle limits cap iterations independently. The last body
restores LC and sets the ordinary REP-completed exclusion state. Intermediate
bodies retain the instruction latch and cannot admit interrupts. Actual next
code still governs post-REP interrupt admission; unknown code is not fabricated.
A REP body at an active DO ending leaves its final instruction to the existing
executor so it performs actual frame cleanup once. This can remain an explicit
owner boundary for memory instructions in bounded execution.

Repeated-code translations use a separate cache-key namespace and compare the
actual retained/new instruction before reuse. A running old opcode cannot be
replaced by backing-P mutation, nor poison a later REP at the same PC. Restore,
program/mapping invalidation and executable storage bounds remain shared with
the ordinary JIT. One bounded negative capability entry avoids repeated code
generation/allocation for the same unsupported body and mode; explicitly disabled
lowering bypasses repeat code generation. Real general execution remains required.
CPU/public checkpoint and SDK layouts are unchanged.

Reproduction

  cmake --build --preset strict --target dsp56300_native_repeat_test
  ctest --preset strict -R '^native-repeat-bodies$'

Repeat with the thread preset for separate TSan. The independent fixture shares
arithmetic/BFU models and authored audio/image/communications programs. It covers
count/budget boundaries, zero-count expansion, retained code through changed or
unknown P and cross-backend restore, genuine RAM knowledge repair, real owner
yield/refusal, store knowledge bytes and DO-ending cleanup. No manufacturer
program, fuzzing, physical pipeline timing or connected-instrument speed is
part of this component scope. Release and separate ASan/UBSan/TSan runs pass
6536 directed checks; 23 affected groups pass in each sanitizer profile. The
same final test object rejects the old archive after its full-state check passes.
Exact evidence and remaining limitations: native-repeat-reference.json.

  cmake --build --preset release --target bench-native-repeat
  build/release/dsp56300_native_repeat_bench audio-mac

The bench supports all or a named shared domain and reports skipped domains.
It times sixteen real 65536-body REP intervals per sample, excluding REP setup
and independent full-state/progress checks. Three alternating old/new process
pairs retain nine samples/domain/library after warmup. The generic LLVM19 O3
shared wrapper measures median ratios 17.19/24.67/28.16 for MAC/add/XOR; raw
spread remains recorded. Native body counters replace 1048576 helpers per sample
with 1048576 native retirements and remove sixteen real P reads. These are
isolated arithmetic CPU programs, without data-memory traffic or a connected
instrument. Host frequency/background activity is not controlled. No device
realtime factor or general application speed follows from these measurements.
