Compile immutable MAC-entry facts once

The decoded MAC/paired-linear-load regions in mac-batching.txt and
mac-reductions.txt keep their existing dynamic admission and arithmetic rules.
Instruction-invariant planning moves from every native entry to compilation.
This applies to a decoded instruction pattern, with no application signature.

Fact                         Resolution       Representation at native entry
legal MAC/moves/mode/ending   compilation      admitted or ordinary fallback
X/Y cursor register slots    compilation      two three-bit immediate fields
A/B destination, add/subtract compilation     two immediate bits
scalar vs host-supported AVX2 compilation     regular compiled function address
PC/LA/SR/LC/current frame     every entry      current Cpu plus immutable NativeOp
budget/R/modifiers/RAM        every entry      current NativeContext and Cpu
bounds/I/O/CPU alias/state    every entry      unchanged guards before any update

MacBatchCall is a temporary compilation result: an entry pointer and one Word
of operands. The generated machine code embeds both values directly, along with
the existing immutable NativeOp address. Nothing points into this temporary.
No field is added to NativeOp, Block, Cpu, NativeContext or the public interface;
no persistent plan allocation is introduced. The block's operations are complete
before emission and remain alive until all active generated entries return.
P mutation invalidates translations and defers active-block destruction as before.

The private operand immediate uses bits 0..2 for the X cursor, 3..5 for Y, bit 6
for A/B and bit 7 for add/subtract. It does not contain RAM pointers, guest data,
a saved frame, LC or a run budget. The compiled entry decodes these small fields,
checks the current dynamic state, executes the selected numerical kernel and
commits exact state/counters. Invalid static patterns never obtain an entry.
This internal call requires the unchanged NativeOp that admitted its operands;
it is not a public interface for executing arbitrary user-supplied plans.

Host feature admission selects one of two ordinary compiled entry functions.
Requested unsupported AVX2 binds the scalar entry. The emitted call therefore
has no runtime instruction decoder, transfer planner or backend-feature branch.
Actual AVX2 guest-instruction counters retain their meaning. The host-process
feature contract is unchanged: the existing compiler CPU-feature probe already
uses process-wide detected capabilities. Numerical 16/64-window admission still
occurs dynamically, because it depends on the current accumulator and span.

Validation

All 101 release and strict correctness tests pass without skips (166.44 s and
540.01 s, respectively, under background host activity). All 112 C++ translation
units retain nonrecovering address/undefined/integer instrumentation. All 148
project C++ sources/headers pass formatting. All 41 fixture archives remain
byte-identical. Both 41-set bench targets pass, with the same three explicit
correctness-only skips (304 sampled cases). All 10368 FIR backend/case pairs
pass across the six requested configurations. No fuzz tests run and no build,
hardening or checking policy changes. ISA qualification remains 118 partial rows.

The directed batch test now performs 326635 checks. Independent raw56 arithmetic,
full flags, registers, progress and memory remain its oracle. Every supported
paired AGU combination now runs all A/B and add/subtract roles. Prepared-entry
reuse changes addresses, RAM spans/aliases, budgets, LC and the current frame;
invalid PC/LA/mode/cache/forever/LC/frame/modifier/REP/debug/processing/dirty or
missing-memory state must still reject without mutation. Boundary tests retain
1680 checks, including I/O rejection, faults and code invalidation after long
batches. Ordinary typed-core integration exercises real generated calls after
the temporary compiler/emitter has been destroyed.

Generated-code and layout evidence

The two compiled entry bodies have no calls to the instruction/transfer planners,
CPU-feature probe, batch-count guard helper or commit helper. The latter two
are explicitly inlined: the checks remain present, with fewer ABI transfers
and intermediate stack copies. Numerical scalar/AVX2 kernels are unchanged.
Clang 19 release entry text measures 1053 bytes (AVX2) and 1046 (scalar), versus
the former shared 1205-byte entry. Both copies increase total static text;
one selected body runs per policy. This is not an I-cache-miss or energy proof.
Cpu=384, NativeContext=128 and NativeOp=24 bytes remain unchanged. MacBatchCall
is 16 temporary bytes and is not a field of any persistent execution structure.
