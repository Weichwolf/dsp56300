Native address-register constants

Design recorded before implementation

Long immediate MOVE into R0..R7 or N0..N7 has no data-bank or status effects.
The continuous FFT schedule uses these constants for each group/stage, making
general execution a candidate overhead. Admit only decoded two-word parallel
MOVE, ALU byte zero, load/immediate effective-address encoding and R/N selector.
Other destinations, parallel ALU work and addressing forms retain existing paths.
Numeric-mode admission and program invalidation contracts remain unchanged.

Value/state             Host representation          Observation/exit
extension low24         embedded dword constant      source P invalidation
selected R/N            canonical Cpu slot           one exact dword store
other R/N/M             canonical Cpu slots          no writes
live A/B                existing BP/BX allocation    no data-bank clobber
SR                      existing holding policy     no flag changes
PC / retirement         existing checkpoints         two words / two base cycles

The admitted assignment cannot fault, read RAM, call I/O or alter control state.
It can share existing non-observable register-move and packed-retirement rules.
Non-unit base costs must remain exact even when common retirement is deferred.
The native move counter includes immediate register assignments, as for the
existing data-register immediate path; this is not a RAM transfer count.

Independent tests must exercise every R/N selector, both bus encodings, every
CCR byte, six numeric modes, low24 clipping, adjacent fields and A/B retention.
Direct generated-code probes must forbid helpers and supply no RAM. Mixed
arithmetic/assignment/load chains need full-state prefixes, callbacks and code
invalidation, including extension edits and aliases. Loop endings at extension
words, short budgets, PC wrap and qword counter wrap require explicit witnesses.
No fixture or benchmark program changes are needed. Compare saved parent and
candidate executables on all three continuous scenarios, retaining failures.

Implementation

A host-independent descriptor verifies the complete fixed opcode fields and
decoded word length before admitting a destination. Native code stores the
masked constant directly in its canonical R/N slot and records one native move.
No data-bank write is declared, so dirty cached A/B remain live. This path is
non-observable for flag/PC planning and can join packed-retirement regions;
the existing extra-cost publication accounts for its second base cycle.
Other selectors, modes and ALU forms keep their previous execution paths.

Independent validation

The dedicated native-address-immediates test performs 1390025 checks. Direct RX
code uses the production ABI with rejecting helpers and no backing RAM. It
checks both bus encodings, all sixteen R/N selectors, all CCR bytes, six numeric
modes, edge and oversized raw constants, PC24 wrap and qword counter wrap.
Mixed MAC/assignment regions prove cached A/B and status survive assignments;
loop guards exercise LC=0/1 and continuing bodies with differing saved targets.

Core tests independently predict every warm prefix and partition, accepted and
rejected callbacks with precise counters, successor-extension edits, cross-page
extension aliases through both X/Y, guest alias stores, wrapped P extensions,
unsupported numerical-mode rejection and final DO-frame restoration at an
extension-word ending. Reference/cached/JIT and disabled optimization are
checked. The public write API continues rejecting oversized words; raw-input
masking is tested using initial caller-owned RAM and direct generated execution.
No emulator snapshot or other DSP emulator supplies expected values.

Full qualification

All 115 tests pass in release (133.12 s, two CTest processes) and strict
ASan/UBSan (243.23 s, three), with zero skips. The 1390025 new checks pass in
each configuration. All 122 C++ translation units retain required nonrecovering
sanitizers, and all 162 C++ sources/headers pass format/tidy/Werror policies.
The six release backend variants match complete independent state for each
of the three continuous streams. Strict bench validates all three in report-only
mode while exposing deadline failures. All 48 fixture archives are unchanged.
Structural ISA audit passes; complete-ISA gate still fails with 118 partial rows.

Matched sustained comparison

The saved parent executable and candidate use identical fixtures and release
settings. Each scenario runs baseline/candidate/candidate/baseline on CPU2, with
one natural input second warmup then one input second measured in the same DSP.
No project compile/test/format process overlaps these runs. No timing overhead
is subtracted. External host scheduling and frequency are not controlled.
Every final complete state passes. Ranges retain both observations:

Whole-process host-counter cross-check

Four additional perf runs use the same alternating order and affinity for the
spectral scenario. All five user-mode counters report 100% running time. Scope
includes fixture construction, cold/natural warmup, measured work, the oracle
and final validation; it is not isolated JIT or measured-interval attribution.
All full states pass. Baseline/candidate ranges and mean reductions are:

user instructions    24.55671 / 22.48549 billion                 8.43%
user cycles          8.33830..8.35966 / 7.52660..7.54211 billion  9.76%
L1 data loads        4.10965 / 3.59824 billion                  12.44%
L1 data misses       4.58361..4.72941 / 4.15343..4.36128 million 8.57%
L1 instruction miss  5.35603..5.63730 / 5.31366..5.85264 million mixed

Reduced host instruction/load traffic supports the optimization, while the
instruction-cache observations provide no reliable improvement. Page storage
does not measure the hot working set. Neither these counters nor the timing
capture prove full cache locality, energy savings, hard realtime or the complete
ISA/general integration objective. Those requirements remain active.
