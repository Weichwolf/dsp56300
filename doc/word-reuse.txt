Pattern-selected reuse of signed24 product words

Scope and canonical state

The native compiler can retain read-through signed24 words without changing the
canonical X/Y register banks. Every guest write still updates its original
raw48 storage. The additional values contain only derived old-read data, so no
new dirty state needs publication at returns, faults, callbacks, invalidation
or admitted interrupts. Public CPU/context/API layouts, numerical-mode admission,
guest work and memory/event/I/O contracts are unchanged. Unknown/helper cases
retain the existing general path. No new host instruction set is required.

Host format             Representation and boundary
one GPR word            RCX holds one immutable sign-extended word in a pure segment
four explicit SSE words XMM8/9/10/11 hold signed64 X0/X1/Y0/Y1 read-through values
canonical X/Y           authoritative raw48 banks; all original writes retained
old parallel snapshots  existing XMM3..6 (or established bank format), kept separate
root/header/entry       compiler facts empty; first selected read populates anew
helper/observer         erase facts before AND after every possible call
GPR scratch boundary    every move-bearing instruction and native loop setup
SSE write boundary      invalidate precise written halves after current old ALU reads

These are limited representation choices from static region effects/costs, not a
complete adaptive allocator. No cache fact depends on a sampled register value,
profile guess or unexecuted predecessor. At a repeated header the same first-load
instructions execute again, including after the region preflight uses RCX. A
short budget/guard exit cannot expose stale derived data: canonical X/Y already
hold every completed guest write. Batch calls precede the empty-root loads.

SSE experiment

The four-word format uses a backward, bounded per-word future-savings analysis.
Pure signed-word reuse costs MOVQ, plus SHL9 when used as a scaled first operand.
Population costs one extra instruction for an unscaled/square role, two for a
scaled role. Only strictly greater future savings select population. Future
credit stops at helpers/observers/unknown effects and precise post-ALU writes.
A parallel move may overwrite a word before its ALU; a hit still names the old
word, and a miss uses the original latched-bank snapshot. Invalidate that old
copy only after its current ALU. Writing the other half preserves the copy.
Pure address updates and loop setups remain barriers because a slow path can
call helpers. Ordinary observable memory paths are barriers even when their
actual branch stays in RAM. Guarded helper-free RAM paths can retain copies.

The measured four-word SSE candidate saves loads but gives no robust CPU gain;
it remains a private explicit experiment. The baseline and candidate captures
are preserved with exact work counts, all timing results and cache regressions.
This does not establish that holding more state in SIMD makes execution faster.

One-word GPR alternative

RCX is unused by the qualified pure ALU/round/flag/retirement/loop-ending code.
Transfers, address work and loop setup use it, so all such instructions are
complete GPR barriers. Each straight pure segment chooses at most one word with
the greatest positive total host-instruction savings, with no eviction. This
explicit scratch rule is narrower than the SSE write policy and is independent
of whether a particular runtime transfer takes its fast path.

For a distinct pair the chosen word becomes the direct IMUL64 source in RCX;
the other word goes to RAX. If that other word is low, fold the *512 scale into
its extraction. A high other word retains unscaled extraction and final SHL9.
The first chosen read also extracts it to RDX and copies it once into RCX.
Squares use a single extraction/copy, then IMUL RAX,RCX; later squares copy RCX
to RAX. First population costs one instruction, or two for commuting a formerly
scaled low/high pair. Later reads save two or three instructions without an
extra SIMD-domain transfer or RHS copy. Nonmatching products keep the existing
coordinate lowering and leave RCX unchanged. All products still pass identical
aligned results into negation, accumulation/overflow, rounding, SM and flags.

The compiler sums first-population costs and later-use savings for each of four
word choices within the pure segment. It selects only a positive winner; ties
prefer the lower selector. This is optimal among these four single-word formats
under the declared instruction-cost model, not a claim of optimal physical
register allocation, latency or energy. Hardware measurements decide whether
the format should be selected automatically.

Independent qualification

A finite, reproducible Cartesian matrix covers every trace of length 0..5 over
nine declared read/write/parallel-old-read/barrier/no-op actions (66430 traces).
An independent forward generation model verifies the backward SSE decisions,
strict profitability and old-word identity. A separate virtual instruction
schedule enumerates no-cache and all four one-GPR candidates to verify the
selected segment and its boundaries. It does not use emulator execution to
obtain expected results. These are explicit compiler matrices, not fuzzing or
full instruction/operand enumeration.

High-XMM support qualifies correct REX and low ModRM fields for scalar moves,
packed copies, qword shifts and memory transfers. Literal bytes were checked
independently against LLVM's assembler without adding an assembler dependency.
RX witnesses cover high/low register copies, both qword lanes, shift boundaries,
walking-bit/complement values and 32/64-bit transfer semantics. The expanded
native accounting matrix executes actual automatic/vector/disabled paths with
independent full registers/RAM/flags/progress: pure repeated-product patterns,
precise parallel halves, old inputs, aliases, loop/root/budget/LC/target failures,
counter wrap/canaries and canonical I/O/P-edit/fault/IRQ/reentry checkpoints.
Callbacks deliberately clobber XMM8..11. All existing product/SM/width witnesses
remain; all 52 guest archives and producers stay unchanged. No ISA catalogue
entry becomes complete through this compiler work.
