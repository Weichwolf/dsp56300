Captured CPU planning with an empty architectural cache interval

SR.CE is an architectural status bit, not sufficient evidence that a program
cache exists. Captured PCU publication can use its existing bounded CPU-result
plan when cacheable_begin == cacheable_end, including with CE set. Keep CE in
all guest observations. A nonempty cacheable interval with CE set, or a retained
architectural cache, still uses the conservative continuation path.

A guest SR write can activate a real cache during computation. Check effective
cache activation at each new effect and stop planning there. Accepted replay
records can carry an earlier SR value; they cannot disable a later plan before
the next unaccepted effect. Fetch, repeat, vector/debug, cache-control/loop,
fixed-capacity and first-fault exclusions remain unchanged. Public SDK headers,
checkpoint layouts, instruction results, base costs and bus responses do not
change.

Independent authored checks cover literal ADD and immediate MOVEC-SR writers,
CE clear/set transitions, actual cache fill/invalidation, full register state,
held accounting, mutated caller observations and checkpoint ticket ownership.
Existing read/write/refusal continuations additionally run with CE set and an
empty cache interval. Three shared 4096-instruction arithmetic/bit fixtures also
run captured-PCU with CE set, checking independent complete results and no
implicit I/O. Their audio-MAC, image-ADD and communications-XOR labels describe
microbenchmarks, not a complete device or audio stream.

  cmake --build --preset release --target dsp56300_cacheless_plan_test \
    dsp56300_cpu_continuation_test dsp56300_external_run_test \
    dsp56300_external_run_bench
  build/release/dsp56300_cacheless_plan_test
  build/release/dsp56300_external_run_bench all captured-pcu-ce 32
  build/release/dsp56300_external_run_bench image-add captured-pcu-ce 32

The benchmark retains all previous modes and adds captured-pcu-ce. Selection,
skipped counts and 1..256 repetitions retain their existing meanings. Its
independent expectations and timing boundaries are documented in staged-copy.txt.
cacheless-plan-reference.json records qualification and paired controls. No
whole-instrument throughput, full ISA or realtime qualification follows.

In ten alternating processes, CE-on captured median old/new ratios are
8.841/7.824/8.933 for MAC/ADD/XOR. All other mode controls range from
0.894 to 1.021; their regressions and raw variation are retained. Both workspace
native queues were held, one CPU affinity inherited, and no workspace native
worker/compiler was present before/after each child. Host background activity
and frequency remain uncontrolled. This is a component observation only.
