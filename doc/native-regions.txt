Guarded native RAM regions

Design recorded before implementation

IIR's current sustained deficit is almost entirely in native execution, with
only 48001 general retirements among 274416000 instructions per input second.
Investigate generic decoded traces, not an application-specific biquad pattern.
No guest program/fixture change, reordering, speculative memory or SIMD claim.

Admit a contiguous native-only trace with at least eight RAM transfers. Allow
data-register transfers and RAM absolute, no-update and unit-postincrement
forms. Reject control, R/N/M assignments, other AGU forms, unknown moves and
any store through a memory span aliasing P. Require existing numeric and native
retirement admission. Ordinary modulo profiles must match current M low16;
linear profiles also require a current-M guard. Read-only no-update R does not
depend on M. Register banks still use their existing exact representations.

State/value              Placement                  Proof/checkpoint
R/M and RAM geometry     entry + loop-header guards  no effects before admission
linear R accesses        current R < min(bound-k)   every accessed offset in RAM
ordinary unit ring       matching M; R in full ring ring upper <= each RAM bound
old A/B/X/Y operands     existing GPR/XMM snapshots unchanged instruction ordering
A/B and status           existing held values       canonical at every return
R updates / RAM writes   original ordered locations no speculative writes
PC / progress / exclusions existing deferred fields exact full-call/prefix state

Ring guards prove current R lies in its logical M+1 span, excluding unused tail
coordinates. Whole-ring bounds prevent RAM/I/O faults for every unit update;
linear guards bound every read before its postincrement. Recheck on every loop
backedge, before any next-body effect. A header guard miss after completed
iterations returns exact canonical progress/state; dispatcher reentry uses the
ordinary path. Final LC<=1 cleanup and changed saved loop targets remain precise.

Generate an ordinary version plus a guarded version behind an initial read-only
selector. Guard rejection enters the original native/general path. Within the
proved region, omit per-transfer bounds/helper branches and observation barriers,
allow ordinary flag liveness across RAM operations, derive retirement from the
native count and publish PC/exclusion only at required boundaries. Preserve
every sticky overflow/limit/scaling effect and all rounding/transfer semantics.

No public CPU/context layout or option is needed. Both versions increase code
storage: measure page bytes, compilation scope and cache tradeoffs. Independent
tests must qualify actual guarded bytes, every failed guard, ring/linear edges,
same-code changed M/R/N, paired ports/aliases, old operands, flags, partial/fault
state, budget tails, backedge rejection and callback invalidation in fallback.
Retain all existing archives and compare all three continuous scenarios with
the saved parent executable. Full ISA and wider application goals remain open.

Implementation and independent qualification

A host-independent planner records each R bank's advances, minimum linear
entry limit, accessed RAM bounds and low16 modifier profile. Contiguous PC,
numeric and loop coordinates must agree. Existing all-native/packed admission
is an additional requirement. Absolute addresses are checked statically. The
x64 selector and every guarded loop header test capacity before effects; header
rejection returns completed iterations canonically. The ordinary version keeps
its original transfer helpers, flags, PC publication and invalidation behavior.

The guarded version preserves ordered transfer capture/commit and instruction-
local old-input snapshots. It holds A/B/status as before, omits proved-dead flags
across RAM, derives common progress from R15 and defers private exclusion-field
stores to publication points. R updates and RAM writes remain in original order.
No public register/context layout changes or new consumer options are introduced.
RegionMode is a private compiler control for ordinary/automatic/guarded tests;
guarded_region reports a generated route, not a runtime execution counter.

The new native-ram-regions test passes 79082 independent checks per build. Actual
guarded RX bytes are tested with six numeric modes, every initial CCR byte,
linear/ring boundaries, unused ring tails, changed/high M bits, irrelevant N,
no-update reserved M, loop LC=0/1, backedge rejection, qword progress wrap,
paired ports, clipping/old operands and physically shared X/Y data. Complete
registers and both backing spans are compared with independent ordered models.
Warm Core prefixes, eager interrupt/exclusion boundaries and same-PC I/O guards
check canonical state. Callback P edits invalidate successors; rejected ordinary
reads retain the existing callback-provided partial destination without ALU or
retirement and remain fail-stop. This qualifies that library fault contract,
not physical chip bus-error behavior or every numerical mode/encoding.

All 117 tests pass in release (108.48 s, two CTest processes) and strict ASan/
UBSan (250.90 s, three), without skips. All six release variants match complete
independent state for each of the three streams. Their concurrent timings are
correctness evidence only. Strict bench passes all three report-only state
checks. All 128 C++ translation units retain required nonrecovering sanitizer
flags, all 167 C++ sources/headers pass format/tidy/Werror, and all 48 binary
archives remain unchanged. Structural ISA audit passes; all 118 rows remain
partial and the complete-ISA gate still fails. No fuzzing was run.

Matched continuous comparison

Parent and candidate use identical fixture bytes, release settings and CPU2
affinity. Each scenario runs parent/candidate/candidate/parent, one natural
input second warmup then one measured input second in the same DSP. No project
build/test/format job overlaps. No overhead is subtracted. External scheduling
and frequency remain uncontrolled; all complete states pass. Retain both runs:

Scenario   Parent CPU s         Candidate CPU s      Mean reduction
FIR        0.263384..0.264852    0.269985..0.270016   2.23% increase
IIR        1.393240..1.393360    0.694454..0.696435   50.09% decrease
spectral   0.951154..0.952828    0.944487..0.949045   0.55% decrease

IIR uses approximately half the CPU at the same reference load: about 2.00 times
CPU throughput. Candidate wall is 0.705970..0.728525 s, 376.67..388.71 actual
guest MIPS. FIR and spectral results are mixed/small and must not be presented
as general speedups. Additional FIR user-counter captures retain the observed
regression: about 1.69% more whole-process cycles with essentially equal host
instruction/data-load counts. Layout/clock effects are not isolated; no claim
is made that FIR executes additional guest work or uses the guarded path.

The independent default release gate passes all three packages: FIR 0.277051
wall / 0.269510 CPU s (982.35 MIPS), IIR 0.722809 / 0.694084 (379.65 MIPS), spectral
0.999916 / 0.945180 (256.73 MIPS). The spectral package has only 84 microseconds
of observed margin. All final states pass. Three FIR blocks, ten IIR blocks and
fifteen spectral hops miss their input budgets; maxima are 4.377 / 4.944 / 16.913
ms. Package acceptance is not block-hard-realtime qualification. Spectral also
remains below the 275-MIPS optimization reference in these host conditions.
No passing package replaces those limitations or the broader open objective.

Page-rounded IIR code storage grows 45056 -> 53248 bytes; FIR/spectral remain
32768 / 344064. Native/helper/move/batch/AVX2 retirement counts are unchanged.
The improvement removes host work inside already-native execution; it neither
skips guest instructions nor adds DSP arithmetic SIMD or multicore execution.

IIR host counters and cache tradeoff

Four extra perf captures use the same alternating order/affinity and report
100% running time for all five user-mode counters. Whole-process scope includes
fixture setup, oracle, compilation, natural warmup, measured work and checks.
It is not isolated region or measured-interval attribution. All states pass.

counter               Parent / candidate range                    Mean change
user instructions     28.07953 / 16.47209 billion                  41.34% fewer
user cycles           10.38183..10.41194 / 5.17191..5.18243 billion 50.20% fewer
L1 data loads         3.24530 / 2.36045 billion                    27.27% fewer
L1 data misses        0.98349..0.99317 / 0.79999..0.81375 million   18.36% fewer
L1 instruction misses 5.36888..5.54314 / 24.62481..25.18904 million 356.50% more

The work reduction is real in this capture, with a substantial instruction-cache
tradeoff despite fewer cycles overall. Do not claim full cache locality or energy
savings. Entry/header alignment, shared cold fallback and smaller generated code
are candidates for further measurement. Register/AGU holding, additional AGU
forms, DSP SIMD/multicore lifting, wider application scenarios and complete ISA
qualification remain active work; the current package gate is not completion.
