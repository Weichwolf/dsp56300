Parallel partial accumulator writes

OR/EOR/AND/NOT and one-bit LSR/LSL/ROR/ROL operate only on accumulator bits
47:24. A concurrent native MOVE to EXT or LSP must survive outside that word.
Previously EOR X0,B with Y0->B0 produced the correct main word/CCR but discarded
the actual new B0. The core now computes from original latched operands and
merges only the ALU-written word into the live native MOVE result. Logical shifts
likewise restore only their original main input before applying the word shift.

Independent qualification checks 58757 assertions across 19584 cases: all eight
operations, four binary X/Y source views, both accumulators, alias/nonalias raw
EXT/LSP destinations, six main patterns, three payloads and both carry inputs.
Reference, cached, JIT helper and optimized configurations are exercised. A
literal EOR anchor fixes the original failing full-state expectation separately.
Five affected groups pass ASan/UBSan and separate TSan. Each profile audits 74
C++ contexts, 64 instrumented CPU archive members and five protected executables;
68 prior contexts retain exact object/source/recipe identity. The 24 original
red controls pass with the same producer object and unchanged expected values.
No manufacturer/application program or fuzz input is used.

  cmake --build build/strict --target dsp56300_partial_accumulator_test -j2
  ctest --test-dir build/strict -R '^partial-accumulator-moves$' --output-on-failure

Use the thread preset/directory for separate TSan. These tests establish
functional register/flag results, not the additional logic/EXT-LSP interlock
cycle documented in FM3.5.2.1. Calibrated phase timing, all combined-destination
legality, arbitrary numerical modes and overlapping instructions remain open.
The ROR carry expectation follows the operation description and diagram (old
bit24 to C); its bit47 condition-code bullet contradicts that description.
