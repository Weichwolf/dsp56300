Objective audit: incomplete

Authority and current scope

The original objective and current clarifications are in doc/objective.txt.
The user explicitly removed hardware virtualization. Its runtime, tests,
benchmark and setup documentation are removed; direct native JIT execution is
the compiler target. Independent CPU implementation, complete ISA, fixed-point
precision, general integration, performance, SIMD/multicore research and explicit
memory/event/I/O contracts remain active. Earlier hardware-backend requirements
are superseded, not pending completion criteria.

Optimization targets all usual DSP56300 application domains, including audio,
image/video, communications, measurement and control. Cross-domain workloads and
regression comparisons are required; the current FIR and FFT programs establish
only an initial subset of application validation, not general optimization.

Original code remains GPL-3.0-only. No dsp56kEmu build/API/test/runtime dependency
is permitted. Neighboring application/firmware repositories stay read-only. Manufacturer
programs/manuals/source extracts and private analysis stay ignored. This library
contains no board/peripheral emulation; derivative integration belongs to the
consumer through explicit contracts.

Native translation: partial implementation and continuing optimization

The Linux x64 JIT emits real machine instructions into bounded memory, publishes
RX pages and enters them through the production SysV bridge. Code executes
natively in the host process. The ordinary Core API hides executable storage
and compilation. Selected arithmetic, single-bit ASR, rounding/addition, data-register and guarded X/Y transfers
and loop continuation/backedges use emitted code; other operations/modes use
general helpers. This is a partial native compiler, not fully translated arbitrary
DSP programs. See doc/jit.txt for exact guards, boundaries and execution counters.

Native paths preserve old-input ordering, 24/48/56-bit coordinates, sticky flags,
exact instruction budgets and canonical callback/fault/exit state. P writes,
including overlapping X/Y storage and extensions, invalidate translations.
Active-loop keys and LC/SP/frame/saved-start guards prevent stale assumptions;
final cleanup remains general. Architectural cache state is separate from host
code caches; CE-enabled execution uses the explicit general fallback.

The guarded retirement optimization packs adjacent host instruction/base-cost
counters with SSE2 at observable boundaries. Internal regions derive a common
count from R15D. Transfer-capable regions retain a pending pair, materialize it
before every general move callback and restore SIMD state afterwards. Non-unit
costs remain exact. Admission requires supported native operations and useful
straight-run length or a loop ending; general helpers, empty plans, zero costs
and aliased-program stores retain scalar retirement. PC checkpoints remain at
transfers, loop guards, dirty exits and returns. CPU/register/runtime layouts
are unchanged. This combines bookkeeping fields, not DSP voices or samples.

104795 directed native retirement checks pass in release and strict builds: qword carry/wrap,
mixed one/two-cycle costs, repeated entries, 24-bit PC wrap, zero-retirement and
partial-loop exits, saved targets/SP slots, literal SSE2 encodings, MOVD width
and neighboring fields. Warm RAM paths are reused for I/O slow branches;
callbacks check complete registers/progress, clobber SIMD state, invalidate P
or reject requests. Prior arithmetic/retirement cannot be replayed or doubled.
Native-only regions now also retain SR in R14D. Helpers and exits receive
canonical SR; helpers' sticky transfer effects are reloaded before continuation.
Old parallel-ALU inputs remain separate. All 196874 new status/old-input/callback
assertions pass, including every initial CCR byte, six numeric modes, clipped
stores, paired loads and partial failures. See doc/native-status.txt.

Native single-bit ASR and the 36 register combinations among X0/X1/Y0/Y1/A/B
now avoid general execution. Pure register moves preserve clipping/sticky flags
and old parallel operands without memory/I/O observation barriers. All 6758417
directed ASR/register assertions pass; no ISA catalogue row becomes complete.
See doc/native-shifts.txt for guards, witnesses, measurements and remaining work.

Performance and realtime: reference target not established

The user raised the reference to 275 MIPS and replaced replay benchmarks with
continuous one-second work packages. Each representative program must process
one real input second near full 275 MHz DSP capacity in at most one host second,
with minimum process CPU demand and bounded block latency. Instruction counts
and documented base cycles are separate: multi-cycle instructions need not
retire at one instruction per DSP clock. Per-scenario shortfalls stay visible;
an average cannot qualify a failing program. This is a baseline, not a ceiling.
The base-cycle model excludes pipeline/bus/peripheral stalls and is not a
calibrated derivative clock. Device realtime and energy remain separate claims.

The continuous IIR bank now processes 92 channels with four causal biquads per
channel and a normalized mix at 48 kHz. Registers, histories, input/output rings
and loop frames persist over 96000 frames: one input second warmup, then one
input second timed in 750 blocks. Its independent producer predicts complete

274416000 guest instructions and 274704000 base cycles (99.8924% reference load).

profiled-modulo.txt and continuous-bench.txt; no target-achieved claim is made.

SIMD, parallelism and cache locality: research remains open

General DSP arithmetic lowering is scalar x64. The guarded MAC loop additionally
uses four-lane signed64 AVX2 products with exact ordered prefix state; it runs
one DSP instance. SSE2 holds instruction-local old inputs and packs two host
retirement fields. The separate native FFT reference checks scalar/AVX2 and
persistent workers with fixed-point data agreement, without DSP state
reconstruction. Its speed exposes computation headroom, not automatic lifting.
Dependence/alias/flag proof, ordered commit, admissible event windows, general
fallback and actual DSP integration remain required. More workers do not
inherently reduce latency or energy. See doc/compiler-research.txt.

Register-bank packing, broader register/flag holding, fewer helpers, compact
regions and code/data locality remain candidates. Recorded Clang 19 x64 sizes
are Cpu=384, native entry context=128 and owner=131648 bytes. Layout/allocation
is not L1/cache-miss evidence;
executable mappings are not measured hot instruction-cache occupancy. More
working-set and cache evidence on real programs is required.

Memory, events and integration: explicit contracts, incomplete integration

Consumers use ordinary DSP56300 headers, caller-owned buffers or MemoryArena,
events and synchronous I/O. Bounds, word masks, aliases, host writes and code
invalidation are explicit. Peripheral replies/reset acceptance are not invented.
Single-thread ownership/stopped mutation remains required; a register view alone
is not a cache/REP/vector checkpoint. See doc/io.txt for callback/fault state,
reentry, mutation, ordering and ownership contracts.

The CPU-only library does not supply DSP56371 board clocks, DMA/serial/host-port
peripherals, pin timing or a synthesizer. Installed package consumption,
integration fixtures, full timing/events and general whole-program/device
operation remain outstanding. Faster host completion must not advance emulated
time or bypass observable event boundaries.
