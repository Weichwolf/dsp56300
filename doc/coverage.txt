Complete ISA: not achieved

DSP56300FM Rev.5: 0 missing, 0 without dedicated independent tests, 118 partial,

Zero missing mnemonics does not qualify every encoding, operand, mode or effect.

Native translation: partial implementation and continuing optimization

The Linux x64 JIT emits real machine instructions into bounded memory, publishes
RX pages and enters them through the production SysV bridge. Code executes
natively in the host process. The ordinary Core API hides executable storage
and compilation. Selected arithmetic, rounding/addition, guarded X/Y transfers
and loop continuation/backedges use emitted code; other operations/modes use
general helpers. This is a partial native compiler, not fully translated arbitrary
DSP programs. See doc/jit.txt for exact guards, boundaries and execution counters.

Native paths preserve old-input ordering, 24/48/56-bit coordinates, sticky flags,
exact instruction budgets and canonical callback/fault/exit state. P writes,
including overlapping X/Y storage and extensions, invalidate translations.
Active-loop keys and LC/SP/frame/saved-start guards prevent stale assumptions;
final cleanup remains general. Architectural cache state is separate from host
code caches; CE-enabled execution uses the explicit general fallback.

The guarded retirement optimization packs adjacent host instruction/base-cost
counters with SSE2 at observable boundaries. Internal regions derive a common
count from R15D. Transfer-capable regions retain a pending pair, materialize it
before every general move callback and restore SIMD state afterwards. Non-unit
costs remain exact. Admission requires supported native operations and useful
straight-run length or a loop ending; general helpers, empty plans, zero costs
and aliased-program stores retain scalar retirement. PC checkpoints remain at
transfers, loop guards, dirty exits and returns. CPU/register/runtime layouts
are unchanged. This combines bookkeeping fields, not DSP voices or samples.

76931 directed native retirement checks pass in release and strict builds: qword carry/wrap,
mixed one/two-cycle costs, repeated entries, 24-bit PC wrap, zero-retirement and
partial-loop exits, saved targets/SP slots, literal SSE2 encodings, MOVD width
and neighboring fields. Warm RAM paths are reused for I/O slow branches;
callbacks check complete registers/progress, clobber SIMD state, invalidate P
or reject requests. Prior arithmetic/retirement cannot be replayed or doubled.
Native-only regions now also retain SR in R14D. Helpers and exits receive
canonical SR; helpers' sticky transfer effects are reloaded before continuation.
Old parallel-ALU inputs remain separate. All 196874 new status/old-input/callback
assertions pass, including every initial CCR byte, six numeric modes, clipped
stores, paired loads and partial failures. See doc/native-status.txt.

All 96 direct-only tests pass in both release (166.93 s) and strict (469.07 s),
with no skips. Strict builds instrument all 99 C++ translation units with
nonrecovering address/undefined/integer checks. All 133 project C++ source/header
files pass clang-format, and the 40 public binary archives are byte-identical
to the parent. The structural ISA audit passes; full ISA qualification still
fails as intended. See doc/native-retirement.txt for the bounded optimization,
independent boundary evidence, matched control and performance tradeoffs.

Performance and realtime: reference target not established

The target remains at least 270 million actual emulated DSP instructions/s per
host core on representative full-semantics work, with minimum host CPU time/load
and latency at that reference load. It is a baseline, not a stopping criterion
or throughput cap. Native execution alone does not establish capacity: DSP
precision, flags, parallel transfers, addressing, loops and helpers cost host
instructions. One DSP instruction is not one x64 opcode. Distinguish guest
retirement, estimated base units, native algorithm work and device clocks.
Neither a family peak nor isolated arithmetic proves full-device realtime.

Private fixtures execute source-built Blofeld filter/complete LP12 and demanding
effect routines. Own DSP FFT programs independently qualify 16/64/256/1024-point
integer transforms, complete registers/frames/RAM and output ordering. Warm
initialized replay restores input outside the timer and excludes compilation;
full expected results and progress remain checked. Native/helper/transfer counts,
code mappings, raw trials and artifact identities establish the measured scope.
A gain in one routine cannot establish a general gain. See doc/fixtures.txt.

Alternating parent/control/candidate status-holding measurements on nine workload
cases show roughly 2.4%/3.4% shorter ordinary filter/LP12 calls against b415608,
wide filter nearly flat, wide LP12 about 0.9% shorter and reverb about 0.9% longer.
FFT16/64 calls are about 0.9-1.2% shorter, FFT256/1024 about 2.5%/1.9% longer.
The admission-disabled control retains identical other compiler objects. Its
filter/LP12 results support modest status-holding gains; its FFT/reverb results
are nearly flat against the candidate. Parent/control/layout gaps prevent a
blanket whole-change speedup claim. See doc/native-status.txt for the full table
and doc/native-retirement.txt for the previous retirement-only comparison.
These are noisy shared-host observations, not statistical or fixed-load proof.
Actual candidate throughput is about 30-100 MIPS in these cases, substantially
below the 270 MIPS reference target. General helpers, dispatch and exact state
bookkeeping remain material costs. An initialized call is not continuous audio, all
voices/effects, derivative I/O or complete synthesizer host consumption. Full
representative execution, sustained realtime and fixed-load CPU/latency tests
remain mandatory. Energy requires measured joules per audio block; GHz/core
count alone cannot establish an energy benefit.

SIMD, parallelism and cache locality: research remains open

DSP arithmetic lowering is scalar x64; SSE2 counter packing updates two host
bookkeeping fields. The separate native FFT reference checks scalar/AVX2 and
persistent workers with fixed-point data agreement, without DSP state
reconstruction. Its speed exposes computation headroom, not automatic lifting.
Dependence/alias/flag proof, ordered commit, admissible event windows, general
fallback and actual DSP integration remain required. More workers do not
inherently reduce latency or energy. See doc/compiler-research.txt.

Register-bank packing, broader register/flag holding, fewer helpers, compact
regions and code/data locality remain candidates. Recorded Clang 19 x64 sizes
are Cpu=384 and owner=131648 bytes. Layout/allocation is not L1/cache-miss evidence;
executable mappings are not measured hot instruction-cache occupancy. More
working-set and cache evidence on real programs is required.

Memory, events and integration: explicit contracts, incomplete integration

Consumers use ordinary DSP56300 headers, caller-owned buffers or MemoryArena,
events and synchronous I/O. Bounds, word masks, aliases, host writes and code
invalidation are explicit. Peripheral replies/reset acceptance are not invented.
Single-thread ownership/stopped mutation remains required; a register view alone
is not a cache/REP/vector checkpoint. See doc/io.txt for callback/fault state,
reentry, mutation, ordering and ownership contracts.

The CPU-only library does not supply DSP56371 board clocks, DMA/serial/host-port
peripherals, pin timing or a synthesizer. Installed package consumption,
integration fixtures, full timing/events and actual Blofeld whole-program/device
operation remain outstanding. Faster host completion must not advance emulated
time or bypass observable event boundaries.

Build, validation and publication

C++23, LLVM 19, CMake/Ninja, hardening, strict warnings, clang-format/tidy and
nonrecovering ASan/UBSan/integer instrumentation remain required. No checks are
weakened or suppressed. No fuzz testing is authorized or run. Binary fixtures
encode explicit portable fields; independent producers do not use emulator
snapshots or another DSP emulator as expectations. Manufacturer assets remain
local. Verified increments are committed locally. The latest repository
instructions do not authorize publication. Local account names stay out of
tracked instructions/code/docs.
The full active objective remains incomplete and must be audited against every
requirement above, including those that current tests do not yet establish.
