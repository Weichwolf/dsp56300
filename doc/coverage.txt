Objective audit: incomplete

Build/setup: C++23, CMake/Ninja, LLVM19, inherited strict diagnostics,
clang-format/clang-tidy and ASan/UBSan setup. Release and strict builds/tests pass
for the current instruction and binary fixtures, including REP base-cost checks.
The strict executable runs with ASan/UBSan and additional integer/conversion checks.
The CPU entry point is src/Core/core.cpp, included in formatting and diagnostic
coverage. Binary fixture reader/writer interfaces use a compile-time concept
with explicit integer widths; native instruction emission remains Linux SysV
x86-64. Concepts do not establish support for other native calling conventions.
Internal sources are organized under src/Core, src/Jit, src/Jit/X64 and
src/Memory; public headers remain under include/dsp56300.

Independence: production/test targets contain only this project's own DSP
implementation and compiler/standard-library facilities. No external DSP core
or JIT library is built or linked. Neighbor checkouts remain read-only.

Framework: caller-owned P/X/Y spans, architectural register view, left-aligned
A/B, synchronous I/O, explicit faults, individual instruction execution and a
paged decoded-word cache. Optional MemoryArena reserves complete address
spaces without touching cold RAM pages.

ISA: partial. Selected multiply/MAC, add/subtract, logical/unary operations,
parallel moves, AGU paths, basic control, DO/REP and admitted interrupts have
initial code. Coded forms are not all qualified. Independent tests currently
cover the manual MAC example, old-register latching on a parallel move,
REP/LC restore and fail-stop diagnostics through all three execution paths.
9447 synthetic binary cases independently cover all eight signed product input
pairs with MPY/MPYR/MAC/MACR sign/accumulation variants, A/B destinations, ABS/NEG and
internal transfer sources, ADC/SBC carry and RND ties. They cover all three
scaling modes and both rounding modes where relevant. Cases compare
complete visible register and memory state, progress and interrupt admission.
The expectation generator does not link or execute the emulator; generated
bytes must match the checked-in fixture. Host-sequence tests also cover a
latched REP body after a P-memory write, sequential REP interrupt exclusion
and rejection of a control-flow body. Broader move, AGU, loop and interrupt
expectations remain required. See doc/fixtures.txt for format and local assets.

Bit/integer instruction extension: single-bit and immediate/register-controlled
ASL/ASR and LSL/LSR, ROL/ROR, shifted ADDL/ADDR/SUBL/SUBR, and CMPM now have
implementations. 4175 additional synthetic binary cases pass all three backends in
release and ASan/UBSan builds, with byte-for-byte regeneration. A separate
finite-width bit model generates directed binary
expectations for both accumulators, zero and boundary shift counts, aliased
control/source registers, discarded bits, intermediate sign changes, scaling
flags and preserved state. Defined shifts use constant-time host operations;
out-of-range counts and currently unsupported numerical modes fault explicitly.
REP can execute these single-word shifts and reevaluates register shift counts.
The model uses wrapped 56-bit magnitudes for CMPM; its minimum-negative corner
still needs independent hardware qualification. No hardware reference was used.

Bit access/control extension: BCLR/BSET/BCHG/BTST and JCLR/JSET/JSCLR/JSSET,
BRCLR/BRSET/BSCLR/BSSET now execute for registers, ordinary X/Y memory and
both I/O short ranges. 30539 access fixtures and 55012 branch fixtures compare
complete visible state, RAM, progress and interrupt boundaries on all backends.
They cover all 24 bit positions, scaling/limiting of full accumulator sources,
SR's special Carry behavior, register-field widths, SSH read versus in-place
modification, always-updated EAs, relative wrapping, saved return frames, DO/REP
and explicit invalid/address/stack/I/O failures. Shared raw-register expectation
code is used only by fixture generators; it never executes or links the core.
20754 host checks verify single bit callbacks for every I/O port, all twelve
instruction families, failed actions, P invalidation, reentry rejection and
guest SR changes before mode-specialized native code. See doc/io.txt.
No hardware reference was used. Full-accumulator modifying forms follow the
manual's shifter/limiter description, whose A/B field lists are inconsistent;
those forms still require hardware qualification. The BRSET pre-update cost
uses the same EA rule as BRCLR/BSCLR/BSSET. Rev.5 table A-1 puts a BRSET +pru
marker on qq instead of ea; independent timing qualification remains open.

Conditional/immediate extension: Jcc/JScc, BRA/BSR/Bcc/BScc (short, long,
register-relative), Tcc and IFcc/IFcc.U now execute alongside short/long
immediate ADD/SUB/CMP/AND/OR/EOR. 38035 new binary cases pass release and
ASan/UBSan execution with exact fixture regeneration. Independent truth-table fixtures cover all
16 conditions and all 128 combinations of the seven relevant flags. They
check always-updated jump address registers, return frames, signed/wrapping
displacements, internal full-width transfers, conditional CCR preservation,
partial logical writes, immediate sign extension and numerical flags. Directed
sequences also check real subroutine returns and condition reevaluation in REP.
Parallel encodings have a statically checked disjoint fast decode before the
more specific rules. This does not establish complete control/interrupt timing.

Local source-built workload qualification: 512 binary fixtures for the ordinary
and wide/rounded Blofeld sixteen-sample filter routines pass all three backends in
release and ASan/UBSan builds. Directed inputs cover both RM values, in-place
and separate output, signed corners and limiting. Independent integer recurrence
expectations check complete visible state/memory and instruction base costs.
Manufacturer program bytes, preparation/analysis and fixture manifests remain
ignored. These direct-core cases do not qualify coefficient preparation,
arbitrary aliases, interrupted calls, continuous streams or complete device
execution.

Additional complete LP12 workload qualification: 2400 local source-built calls
pass all three backends in release and ASan/UBSan builds. Independent equations
prepare coefficients from directed cutoff/resonance and synthetic curve pairs,
then evaluate the fixed-point recurrence. Cases include both RM choices, linear
modifiers, N0=1/3, negative damping, the cutoff-dependent floor, the strict wide
branch and equality at its boundary. Poisoned initial coefficient scratch,
all visible registers and RAM, exact output/history words, original return,
instruction counts and estimated base costs match. Other coefficient callbacks,
arbitrary entry modes, interrupted calls and device behavior remain unqualified.

Demanding effect-stream qualification: 94 additional local source-built Reverb
fixtures pass reference, cached and JIT execution in release and ASan/UBSan builds.
90 successful fixtures describe 2700 complete ready-state calls per backend;
four required memory-read faults check the declared host-memory boundary.
An independent integer model checks complete visible registers, hardware stack,
all supplied RAM, exact retirement and estimated base costs. Directed cases
cover both rounding modes, limiting and sticky flags, circular-buffer wrapping,
diffusion and feedback stages, retained feeds, aliased parallel moves,
and streams up to 256 blocks with independently witnessed prior-block feedback.
Compact and unrolled callers have independently derived stack/loop expectations
and matching audio results. Metamorphic cases check overwritten read values and
retained workspace, while forced ties and clipping exercise transfer precision.
Fixtures explicitly provide ordinary host X/Y RAM. Restricting X memory must
fault at an actual unused source read; no peripheral result is synthesized.
This qualifies initialized CPU execution, not board mapping, setup/clear-to-ready,
interruptions, acoustic quality or complete device behavior. Source assets,
models, witness counts, hashes and reproduction manifests remain ignored.
Reverb is one validation example; further workload selection follows semantic
coverage and measured optimization value rather than an effect priority.

Modes: ordinary 24-bit arithmetic, three defined transfer-scaling modes and
two rounding choices have initial code. Compatibility, double precision,
sixteen-bit arithmetic and arithmetic saturation reject at parallel execution;
these required modes remain to be implemented and tested.

Nonparallel transfers: MOVEC short/long immediate, register and X/Y short/EA
forms, MOVEM short/EA and MOVEP register/X/Y/P forms now execute through the
general executor on all three backends. 20158 independently generated binary
cases cover the 47 register selectors, 19 control selectors, ordinary scaling,
raw accumulator fields, transfer limiting, preserved flags, SSH/SSL effects,
linear address updates, base costs and directed rejection/fault cases.
Writing SSH preserves the other half of the newly selected stack entry.
The Class-II mask now excludes MOVEP encodings, and its forbidden long
address/immediate forms fault before performing a transfer. Directed Class-II
cases verify the remaining parallel transfers.
1607 synthetic host-boundary checks exercise every high/low X/Y port, masking,
memory and immediate transfers, REP, guest SR changes and guest MOVEM/MOVEP P
writes that invalidate a planned JIT successor. I/O uses explicit scripted host
responses; no peripheral state or device results are fabricated. Qualified data
moves use ordinary numeric modes; other modes remain explicitly restricted.
Updated-address/source aliases, extended hardware stack operation, pipeline
interlocks and undefined instruction sequences remain unqualified.

AGU extension: 31656 independent synthetic binary cases qualify directed linear,
reverse-carry, normal-modulo and multiple-wrap calculations on all eight address
registers. They include ignored modifier high bytes, 24-bit boundaries, signed
normal offsets, whole-buffer strides beyond the modulo length, the positive
reverse-carry N=$800000 endpoint, X/Y effective-address accesses, guest modifier
replacement and repeated updates. The reference model uses integer ring
coordinates and a serial carry/borrow circuit rather than the executor's address
algorithm. Whole-buffer strides now move linearly to the corresponding position
in another buffer; reserved multiple-wrap encodings fault explicitly. No hardware
reference was used. Normal-modulo offsets beyond the length which are not whole
buffer strides, initial pointers in gaps between modulo regions, and timing of
address-register/source aliases remain unqualified.

Guarded AGU optimization: linear effective-address arithmetic now avoids the
general update call. The guard checks the current low sixteen M bits; nonlinear
modifiers use the general calculator. N is read only for offset forms. No-update
and absolute/immediate forms return before address arithmetic. 2904 additional
host checks exercise changing modifiers/offsets/pointers through set_registers,
code-cache clearing and reset, across all three backends. Guest modifier
replacement and REP sequences remain covered by the independent binary fixtures.

Timing: documented base costs are being added for implemented forms. Pipeline
interlocks, IRQ entry/return qualification, exact event admission and external
waits remain open. A complete checkpoint API is pending; Registers omits hidden
REP/interrupt continuation. Instruction budgets now have identical guest
retirement semantics on all backends; failed DO cleanup does not consume
instructions or base cycles. Host callback execution/reset/register/interrupt
reentry is rejected while memory access and P invalidation remain permitted.

Performance: a binary-fixture replay benchmark now provides a warm scalar
reference/cached baseline for the qualified source-built Blofeld filters.
One DSP instance per backend, host restoration outside the execution timer,
64 warmups and a median/range of nine 4096-call trials. Complete results are
checked after warmup and each trial. This measures initialized call replay,
including timer/retirement-check overhead; it is not continuous audio or device
performance. An initial independent scalar x64 JIT now emits MPY/MPYR/MAC/MACR,
RND/CLR/ABS/NEG/TFR, ADD/SUB/CMP, ADC/SBC and NOP, with guarded general helpers
for other operations and parallel memory moves. It has exact budgets, numerical mode keys, deferred P
invalidation, bounded executable storage and immutable RX mappings. Shared
fixtures cover all three backends; host tests check ABI/boundary behavior and
native/helper counters expose actual lowered execution. See doc/jit.txt for
instrumentation scope and remaining native work. All twenty-five CTests pass in release
and strict builds, including exact fixture regeneration. SIMD is not implemented
in VM execution; the separate native FFT research comparison uses AVX2.
Earlier isolated arithmetic experiments do not establish emulator speed.
More source-built workloads, register-bank SIMD
measurements, guarded independent-voice batching and code/cache evidence remain
required before a final performance claim.

Demanding effect baseline: one warm replay run on the i5-10400 measures about
79/70/67 microseconds per initialized sixteen-sample stereo block for
reference/cached/JIT execution. A sixteen-block JIT fixture measures about
66 microseconds per block. Each run uses the nine-trial protocol above; these
are baselines, not an established optimization gain or device-capacity result.
About 40% of retired guest instructions use native ALU code in this case;
the remainder use general helpers. Native parallel transfers still use helpers.
The benchmark now permits selecting one backend for separate profiling.
An isolated JIT process profile identifies address generation, parallel moves
and dispatch among visible execution costs. It also includes substantial host
RAM-restoration time outside the execution timer, so its sample percentages
must not be interpreted as execution-region percentages. Parallel moves,
native address lowering and dispatch remain optimization candidates, subject
to guarded semantic coverage and before/after measurements across multiple
qualified workloads.

Native addition extension: ADD/SUB/CMP register and short/long immediate forms,
plus ADC/SBC with X/Y long operands, now use emitted x64 arithmetic in supported
numerical modes. Host flags match the aligned 56-bit result, including Carry
injected through low padding for ADC/SBC. 51612 additional independent binary
cases check both accumulators, every admitted register source, scaling,
carry/borrow, signed overflow, extension/normalization boundaries, sticky state
and parallel transfers that overwrite sources or destinations. The generator
uses signed sums and unsigned raw-56 inequalities rather than host flags or
padding injection. Comparison preserves a parallel transfer to its accumulator.
Existing condition fixtures qualify immediate forms. Expanded native-boundary
tests perform 793 checks, including actual native/helper-only retirement for
every addition form, unsupported modes, I/O program changes, failed moves,
DO restoration and repeated ADC with reevaluated Carry. Native carry/borrow
chains also cross a general budget tail and a subsequent native block with
identical final state and exact accounting. All twenty-one CTests
pass in release and strict builds, including exact fixture regeneration and the
source-built workload expectations. CMPM, shifted additions and REP bodies
retain general execution; no new ISA/mode completeness claim follows.

Measured native-addition benefit: three runs compare the qualified parent at
6a2d341, the final emitter, and a local control with exactly the final hot host
layout but the new arithmetic lowering disabled. Retirement counters verify
the control, and all replay outputs/state remain independently checked.
The ready effect case improves JIT medians by about 10% against either baseline;
259 additional arithmetic instructions per call use native execution. Published
executable mappings grow from 52 to 64 KiB and compiled blocks from 13 to 15.
Complete LP12 cases improve by about 2-3% against the matched-layout control,
with three additional native operations and one extra executable page per call
shape. Their cross-build parent comparison establishes no clear improvement.
Direct filter mixes/code sizes are unchanged; their final cross-build medians
regress by about 2%, while matched-layout differences are below 1%. Host code
placement remains a performance concern. An initial inlined-classifier control
was rejected by its unchanged retirement counters and is excluded from evidence.
Artifacts, controls, hashes and raw runs remain local. The replay protocol and
its warm-call/device limitations above apply; no general speedup follows.

Realtime capacity is not established for a fully loaded DSP or complete synth.
The user's throughput target is now 270 million emulated DSP instructions/s per
host core. This is unachieved: current directed cases require approximately
8-10 times higher throughput to reach it. Qualification must retain full state,
precision, memory/event boundaries and representative workload execution.
Current directed JIT cases execute about 26-35 million guest instructions/s on
the i5-10400. At an explicitly assumed 48000 frames/s, a 16-frame LP12 call at
4.35 microseconds projects to about 1.3% of one host core; 24 identical calls to
about 31%. A 59.2-microsecond effect stereo block projects to about 18%. These
are arithmetic projections from isolated initialized fixtures, not measured
continuous audio or whole-device CPU consumption. Other voice stages, mixing,
I/O and scheduling are excluded. Comparing estimated guest base-cost throughput
with a nominal 216-MHz target suggests roughly 6-8 host-core equivalents for a
fully busy DSP at these instruction mixes. Guest costs are not calibrated
pipeline time, and a single DSP cannot simply use that many host cores. Full
original-program execution, physical clocks and sustained load measurements
are required for an actual realtime-capacity claim.
The 216-MHz comparison is a local setup assumption, not a confirmed board clock
or device specification. NXP's DSP56371 Rev.4.1 datasheet specifies 181 MIPS at
181 MHz. The family also includes the DSP56321, specified at 275 MHz/275 MMACS;
neither a family peak nor our throughput target proves whole-device realtime.
References: https://www.nxp.com/docs/en/data-sheet/DSP56371.pdf
            https://www.nxp.com/docs/en/data-sheet/DSP56321.pdf

FFT/compiler-headroom experiment: 112 project-authored scaled radix-2 DIF FFT
fixtures cover 16/64/256/1024 complex inputs, both RM choices, sticky state,
clipping and reverse-carry output ordering. The independent integer model checks
all visible registers, nested-loop frames, complete RAM and exact progress on
all three backends. Low-amplitude cases also match an independent direct DFT
within 2.35 output LSBs; CPU/model agreement itself remains bit exact.
No manufacturer FFT or optimized hardware-peak claim is involved.
Three runs on the i5-10400 measure approximately 55-61 MIPS for these own DSP
programs, versus 26-35 MIPS in the previously qualified Blofeld cases. The 270-MIPS
target remains unmet. A 1024-point transform retires 157810 guest instructions
and 164100 estimated base units, with a JIT median of 2.596 ms.
Its separately qualified native algorithm takes about 140 microseconds scalar,
43.6 microseconds with single-core AVX2 and 31.1 microseconds with two AVX2
workers. Six AVX2 workers take about 57.0 microseconds. Smaller transforms favor
one worker. The experiment exposes substantial mathematical-computation
headroom and a synchronization/granularity cost; it is not a transpilation or
multicore VM performance claim. Native algorithm tests pass for every fixture
with 1/2/3/6 workers and scalar/AVX2, including ASan/UBSan and ThreadSanitizer.
Plans, worker startup and input restoration are excluded from native timing;
output ordering and synchronization are included. Three-run medians, all raw
trials, affinity/governor settings and artifact hashes remain local. RAPL energy
counters exist but are root-readable, so energy/frequency claims remain untested.
Automatic lifting, dependency proof, register/flag state mapping, ordered commit
and guarded VM integration remain required. See doc/compiler-research.txt.

Measured native improvement: on four directed ordinary/wide filter and complete
LP12 cases, the first scalar JIT reduces warm execution medians by 23-24%
relative to cached execution in the same release binary on the i5-10400.
Three runs per case use the replay protocol above; compare the median of run

Native ALU still calls parallel-move helpers, and cold compilation is excluded.
