Continuous one-second benchmarks

bench is a CMake target with its own CTest tree under build/<preset>/bench.
It runs independently authored continuous programs using the same binary-fixture
format and independent expectations as correctness tests. Microfixtures and
replays of completed programs no longer qualify as throughput benchmarks.

  cmake --preset release
  cmake --build --preset release --target bench
  ctest --test-dir build/release/bench --show-only
  ctest --test-dir build/release/bench -R '^iir-stream$' --verbose

Configuration, analogous to CTest selection:
  DSP56300_BENCH_FILTER    workload-name regex; empty selects every registered set
  DSP56300_BENCH_CASES     all (default), sample, or one zero-based numeric index
  DSP56300_BENCH_BACKEND   jit (default), jit-scalar, jit-avx2, jit-unbatched,
                          cached, reference, or all
  DSP56300_BENCH_ENFORCE_DEADLINE  ON (default); fail when a package exceeds 1 s

The current continuous list contains FIR, IIR and overlapping spectral analysis.
All three shapes are described in continuous-bench.txt. Old single-output FIR
and FFT replay fixtures remain correctness/latency diagnostics outside the qualifying target.
Each current continuous archive has one full-duration case, so sample and all
select the same case within each set. A numeric out-of-range index, invalid
backend or an empty filter fails.
DSP56300_BENCH_REPLAYS does not control the continuous target. The target executes
serially. Compare release binaries with the same fixture and host conditions;
use external affinity when desired. No host clock policy is imposed here.

Each backend/case initializes one DSP and caller-owned P/X/Y buffers exactly
once. One real input second warms the program naturally, including compilation.
The next input second is measured in the same instance. Hardware loops, filter
feedback, buffers and counters continue across the boundary. The host never
restores RAM, registers or PC between samples or blocks. Work is not padded with
NOPs. The runner does not sleep to manufacture an input duration or subtract
harness overhead. A one-second package must complete in at most one host second.

The IIR program is a 92-channel, four-section causal filter bank and
normalized mix at 48 kHz. It retires 274416000 instructions and 274704000 documented
base cycles per input second: 99.8924% of a 275 MHz reference. This excludes
pipeline/bus stalls and derivative peripherals, so it is not a calibrated
DSP56371 board simulation. The first outer DO adds one instruction/five cycles
before warmup. The measured interval uses 750 calls of 64 audio frames each.

The FIR program filters eleven 48 kHz channels with 507 triangular taps. It
retires 272160000 instructions / 274560000 base cycles per input second, 99.84%
reference load. Overlapping linear histories, shared coefficients and an output
ring continue over both seconds. The guarded one-instruction MAC batch handles
qualified inner tap loops. It does not transform filter samples into independent
time lanes. Full state and short-case direct-dot checks are in fir-stream.txt.

The spectral program analyzes fifteen complex streams with periodic Hann windows,
1024-point FFTs, natural-order permutation and mean I/Q power. A 480-sample hop
represents 10 ms of input, repeated 100 times in the measured second. Its
256704500 instructions / 266161100 base cycles use 96.7859% reference load;
sixteen whole streams would exceed capacity. Cursors and a sixteen-spectrum
output ring remain live. The exact oracle, DFT probes and region counters are
in spectral-stream.txt. The old standalone FFT calls remain diagnostics.

Metric                    Meaning
wall_s                    full measured execution interval, including run/checks
process_cpu_s             CPU used by all process threads over that interval
equivalent_cores          process CPU seconds per real input second
realtime_factor           real input duration divided by measured wall duration
MIPS                      actual retired DSP instructions / wall time / 1e6
base_cycles/reference_load qualified base units and fraction of the 275 MHz budget
max_block_s/late_blocks    worst block latency and count beyond its input budget
cold_warmup_s             unmeasured first input second, including cold compilation
native/helpers            ALU retirement categories, not a count of all helper calls
batch/avx2                actual guest instructions processed by compiled batches
code_bytes/new blocks     compiled storage and additional measured-interval blocks
full_state                independent complete registers, P/X/Y and control checks

One measured package is the acceptance unit. Block latency is reported separately;
passing the package deadline does not promise every block met a consumer deadline.
Process CPU includes future worker threads; this is not a device or energy
measurement. Initialization, fixture loading, expected-memory construction and
final-state checks are outside the measured interval. Every measured block must
retire exactly its budget; cumulative counts and all final memory/registers must
match independently generated expectations. A mismatch always fails, including
in report-only mode. No slow or unexpected case is skipped.

The default deadline gate applies in optimized builds. Sanitized bench runs use
report-only mode: they verify correctness and expose timing without treating
instrumentation overhead as release performance. A local diagnostic invocation is:

  build/release/dsp56300_continuous_bench iir test/fixtures/iir-stream.d56 all jit report

Backend=all compares six concept-constrained implementations in one executable.
Reference/cached are comparison engines; if deadline enforcement is selected,
every selected backend/case must pass. Requested AVX2 does not imply that the
host or this causal program uses vector batches. The ordinary fallback remains.
Results stay in bench/Testing/Temporary/LastTest.log. The broader ISA, application,
SIMD/multicore, sustained performance and energy objectives remain incomplete.
See replay-diagnostics.txt for superseded single-call experiments.
