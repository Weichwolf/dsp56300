Captured instructions and externally owned effects

Core(Io&, Options) constructs a CPU with externally owned instruction effects.
The owner supplies known InstructionWords to begin_instruction or explicitly
starts Core-owned logical program reads with begin_fetch. Construction allocates no implicit RAM and executes nothing. Ordinary run can
execute through this same bus at instruction boundaries; active staged ownership
rejects it until actual retirement. instruction_fetch reports the actual
next normal/vector address, native exception-vector ownership and existing REP
opcode latch. A handler coinciding with a vector address is still a normal
fetch once native vector ownership ends. begin_instruction
verifies supplied address, widths, extension count and latch before computing
one instruction; that captured-word route performs no program read. Neither
route establishes physical fetch clocks or interrupt acknowledgement.

Default boundary        Observable state / action
begin_instruction       Computes until a real memory/reset effect or retirement
pending_instruction     Owner-bound ticket, effect/context, observed native prefix/result
advance_instruction     Performs exactly the stored bus effect, or publishes retirement
registers/progress       Retain their pre-instruction values until retirement
checkpoint/restore      Include accepted responses and the pending computation
request_interrupt       Retains admitted vector/priority and genuine normal resume PC

With pcu_updates, retirement_delta(ticket) observes the actual computed Progress
increment while that owner's genuine retirement ticket remains pending. It
neither publishes results, performs I/O nor allocates a candidate checkpoint.
Earlier effects, other publication modes, faults, foreign/stale tickets and
completed instructions reject the query. Restore preserves the native increment
but requires a newly obtained ticket. An external scheduler can hold the real
retirement until its instruction budget expires without committing it early.
The reported units exclude pipeline interlocks, interrupt-entry overhead and
external bus waits; this API establishes no hardware clock or bus timing.

Instruction starts reset the logical accepted-effect prefix, retaining its bounded
storage. Only [0, used) is readable; computation replaces all instruction scratch
before publication. Capacity, ticket generations and checkpoint contents keep
their existing contracts. The staged gate exercises sequential read/NOP/write/NOP
on all three backend selections and six publication modes, including 18 pending
NOP snapshots and 36 original/fresh continuations. Previous responses/stores must
never become the next instruction's effects or replay after restore.

Staged program-cache hits use retained cache data; misses, program writes and
X/Y word accesses use the supplied Io, including ordinary low RAM. Caller-supplied
instruction words are already fetched and cause no implicit P read or cache fill.
RAM bit instructions use a genuine read followed
by a native modified-word write, or just a read for TEST. Only addresses in the
upper peripheral window (0xffff80..0xffffff) use atomic Io::bit transactions.
This transport correction applies to every CPU publication policy.
RESET requires an actual reset_peripherals acknowledgement. Rejection is a
visible fault with operation class, address and PC; no successful value is
invented. Accepted responses are recorded in a bounded instruction log. Native
recomputation verifies and consumes that log without repeating external effects.
A copied PendingInstruction is an observation; changing it cannot alter the
stored operation or computed result used by its ticket.
Its optional opcode identifies the actual captured instruction. It is absent
while an owned opcode fetch or its cache fill is pending, then known at later
extension, operand and publication effects; explicitly supplied words are known
immediately. This is provenance only, not a physical pipeline or atomicity claim.
Checkpoint restoration preserves the same observation and rebinds the ticket.

Core-owned logical program reads

begin_fetch(publication) starts the actual next instruction using owned
fetch_opcode/fetch_extension tickets through the supplied Io. Accepting a ticket
performs the genuine P read; native decoding determines whether an extension is
needed. Extension addresses wrap modulo24, and a real read refusal reports its
actual address, operation and instruction PC. No dummy word or host-created CPU
fault replaces the missing read. Accepted words remain in the owned continuation
and checkpoint; replay never rereads them. REP uses its genuine native opcode
latch after the first body execution. Fully supplied begin_instruction words
retain their strict original width/latch checks and perform no implicit fetch.

interruptible_opcode accepts only the known opcode for REP-tail eligibility;
this read-only metadata query needs no invented/speculative extension. The full
interruptible(words) interface retains complete-word validation. Neither query
acknowledges a device or advances a guest clock. Logical read tickets do not
calibrate physical F1/F2, architectural cache prefetch or vector/IRQ bus timing.

At the first Core-owned exception-vector fetch, fetch_extension obtains the
second vector word even when the first opcode is one word. Both accepted words
precede the first opcode's operand/effect execution. The remaining vector slot
then uses its native opcode latch, including after program writes and trusted
restore. Its instruction_fetch still reports exception_vector until that slot
executes. The consumer's second-read acknowledgement may complete earlier;
it does not terminate CPU vector ownership. Fully supplied begin_instruction
words keep the no-implicit-fetch contract and must match any existing latch.

Directed logical-read qualification passes 1503 assertions per profile under
ASan/UBSan and separate TSan: real opcode/extension refusal, modulo24 wrapping,
REP-latch reuse and 72 cross-backend/boundary restore cases. The unchanged eleven
selected complete ALU archives also pass through genuine reads. Native ALU
result publication has its own bounded qualification in alu-publication.txt;
neither qualification establishes physical fetch clocks or overlapping execution.

Optional native address publication

begin_instruction(words, InstructionPublication::address_updates) additionally
suspends when it computes an automatic native R writeback. For memory operands,
this is before the following data access.
The default retirement policy retains the preceding interface behavior.
An EffectKind::address_update contains AddressWriteback {index, previous, value}
and the actual computed EA in address. space is unused; this is a CPU boundary,
not an Io transaction. Its owner-bound ticket publishes only that native R value.
PC, data/ALU results, status/stack state and retirement counters remain held.
The observed computed registers cannot substitute for the stored native update.

Accepted publication values join the bounded effect continuation. Recomputation
uses the original instruction inputs, verifies accepted update descriptions and
never repeats publication as an external operation. Checkpoints retain which R
updates are visible as well as pending updates; restore invalidates old tickets.
An ensuing bus rejection preserves an already accepted R update. Reset cancels
the continuation and resets CPU state. Pure U and post/pre-update addressing
produce these boundaries. Indirect, indexed, absolute/extension addressing and
explicit MOVEs to R do not invent an automatic writeback.

The additional move_updates policy also exposes native MOVE storage effects;
see move-publication.txt for its producer, mask and checkpoint contract. This
extension does not calibrate physical pipeline clocks or implement overlap.

The unit_updates policy includes native automatic-R/MOVE/ALU results and adds
bit, control-byte and explicit LRA/LUA results. Its source-side SSH pop/limiting
boundary precedes a later PCU branch/call; ordinary bit results follow the real
Io operation. This scope passes 257730 directed assertions per sanitizer profile
and all twelve selected regressions, including four complete unchanged archives.
See unit-publication.txt for the qualified scope and actual storage/flag-mask
contract. PCU and hidden retirement are not unit_update effects.

This is value-level automatic R publication, not calibrated AG2 timing, general
early MOVE/ALU publication or overlapping instructions. Paired address updates
have separate native tickets; their physical cycle/grant relationship remains
the timing integration's responsibility. No automatic processor clock advance,
physical bus operation or acknowledgement is implied by accepting a CPU ticket.

At 1abd8b4, directed automatic-address qualification covers 26528 assertions
per profile under ASan/UBSan and separate TSan: sixteen independent linear/modulo/reverse
arithmetic cases over all R indices, X/Y and load/store directions; pure U,
non-updating/explicit destinations, old parallel ALU operands, rejected data
access/reset and paired restore at five boundaries across nine backend pairs.
The pre-decrement base-cost expectation includes the FM Appendix A +pru cycle.
All fourteen affected groups qualify. After the test-only cost correction,
thirteen strict results retain exact source/object/recipe/ELF identity; TSan
runs all fourteen groups once. Each profile audits 81 C++ contexts, the complete
64-member CPU archive, the instrumented fixture-format dependency and seven
protected executables. There is no whole-suite, calibrated-stage or device claim.

Core::run, register initialization and conflicting debug/interrupt controls cannot
replace a pending staged owner. Reset cancels CPU continuation, not earlier
external writes. A healthy checkpoint must be paired with external memory/I/O
state by the consumer. Restored pending effects receive new owner/generation
tickets; abandoned or foreign tickets do not authorize another access.

The external constructor requires this explicit execution route. Ordinary buffer
construction/run retain their existing ownership contract. Staged computation
uses the general ISA executor for every backend option; native JIT compilation
of these boundaries is not yet implemented. Capture/restore, cold setup and the
internal suspension mechanism belong outside a real-time audio callback.

The existing staged qualification covers 690 assertions
per profile: literal arithmetic/full state, P data vs opcode capture, X/Y address
updates, four paired transfer directions across all backend restore pairs,
foreign/stale/tampered views, native fast/long vectors and RTI, REP latches,
rejected second effects with persistent external prefixes, atomic bit carry,
and accepted/rejected RESET with post-acknowledgement restoration. At 669e223,
thirteen unchanged caller results retained exact ELF/source/recipe identity
after test-only controls. No fuzzing or manufacturer programs are involved.

Single-instruction staged CE/cache execution has bounded direct coverage for
fetch, bursts, refusal, flush, program writes and checkpoint continuation.
Physical cache timing and all cache-control combinations remain unqualified.
Other native unit phases, calibrated AGU/MOVE/ALU phase clocks, overlapping instructions, physical RMW
phases, complete pipeline/cache/IRQ timing and realtime throughput remain
required integration work. computed is an observation, not permission to patch
visible registers.
The consumer owns physical F1/F2 receipts, derivative arbitration, selected-source
ACK, memory resources, clock edges and devices. Faster host execution cannot
advance those emulated clocks. This interface is not complete device acceptance.


The pcu_updates mode adds native PC/stack/loop publication and sparse hidden
retirement; see native-pcu-publication.txt for its pending qualification and
remaining clock/overlap limitations. PCU results are CPU writes, not Io requests.

Core::instruction_outcome reports only an actually retired staged instruction:
instruction count, captured address/opcode and a native control-transfer flag.
Taken jumps, calls, returns, bit branches, DO redirects and vector transitions
set the flag at their actual CPU assignments, even for a sequential target.
REP opcode-latch rewinds do not count as control transfers. Consumers must pair
the receipt with their admitted instruction and distinguish their own queued
program samples from later memory. No condition is re-evaluated by the consumer.
All publication policies provide the receipt after retirement; pending work,
faults and speculative candidate checkpoints provide none. Actual checkpoints
preserve it, including a stop after retirement before consumer synchronization.
Reset, successful register initialization and nonzero atomic run invalidate it.
The receipt supplies control-flow semantics, not calibrated branch timing.

Native REP fetch rejects a non-repeatable or two-word body immediately after
its actual opcode read, before offering an extension transaction. Missing
extension storage cannot replace this invalid-instruction fault. The native
fetch gate covers known/absent extensions, all six publication modes, three
backend selections and restored owners; valid opcode latching remains separate.
