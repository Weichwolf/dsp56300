Binary instruction fixtures

test/fixtures/arithmetic.d56 contains only synthetic instruction cases authored
for this project. It contains no Blofeld program or extracted manufacturer data.
The 9447 checked-in arithmetic cases include all eight signed product selectors
with MPY/MPYR/MAC/MACR variants, both accumulator destinations, three scaling
modes and both rounding choices. Directed RND/zero-product MACR cases check
half ties, adjacent values and 56-bit wrap/overflow with seeded sticky flags.
The generator uses signed integer arithmetic and quotient/remainder rounding
expectations; it does not link or execute the emulator implementation.
Fixture regeneration is explicit, never part of normal test execution:

  cmake --preset release
  cmake --build --preset release
  build/release/dsp56300_generate_arithmetic build/arithmetic.d56
  cmp build/arithmetic.d56 test/fixtures/arithmetic.d56
  ctest --preset release

The reproducibility test independently regenerates the bytes and compares them
with the checked-in file. Review the model and binary change together when
updating expectations. Never replace independent expectations with a snapshot
captured from the emulator under test.

test/fixtures/bit-operations.d56 is generated by dsp56300_generate_bits. Its

constant-time host shifts. It checks carry, every intermediate left-shift sign
change, 24-bit partial writes, register/source aliases, scaling flags, shifted
sums, wrapped-magnitude comparisons, REP and explicit rejection boundaries.
Regenerate it explicitly and review it with test/generate_bit_operations.cpp.

test/fixtures/bit-fields.d56 is generated by dsp56300_generate_bit_fields,
which links only the fixture-format library. Its per-bit boolean model builds
56-bit results independently of the executor's shifts/masks and count-leading
intrinsic. The 54488 cases check EXTRACT/EXTRACTU, INSERT, MERGE and CLB;
all immediate width/offset pairs with width 1..56 for signed extraction, 0..56
for unsigned extraction and 0..24 for insertion (offset + width <= 56), all
legal register selectors, source/control/destination aliases, both polarities and every leading-bit count,
the all-zero CLB exception, preserved accumulator words, six numerical modes,
SM bypass and initial status choices. Directed INSERT cases additionally force
zero results, sign/extension boundaries and all-one destinations/data. MERGE's
twelve-bit halves are distinguished from the inconsistent eight-bit pseudocode. CLB follows the bit-55 description.
REP cases reread modified source/control registers; DO endings include control
extensions and wrapped saved frames. Mixed native/helper sequences check every
nonempty prefix, complete flags and dirty accumulators. Missing extensions,
two-word REP bodies, undefined ranges and unimplemented-mode diagnostics are
explicit cases. Signed zero-width EXTRACT is currently an unsupported-mode gap,
not a qualified hardware exception. Sixteen-bit/compatibility/double-precision
semantics and full pipeline/event qualification remain open. A separate optional
authoring assembler confirmed all 156 legal opcode forms (176 program words);
it is not a build, regeneration, execution dependency or semantic oracle.

test/fixtures/fft.d56 is generated by dsp56300_generate_fft. It contains 112
project-authored scaled radix-2 DIF transforms of 16/64/256/1024 complex samples,
followed by a reverse-carry permutation into natural frequency order. The
butterfly words correspond to test/programs/fft_butterfly.asm; no manufacturer
program is reused. The input authoring assembler is not a build/test dependency.
The independent model uses integer half-sums/differences, quotient/remainder
rounding and complex products. Both RM choices, sticky flags, clipping,
poisoned state, complete RAM and residual nested-loop stack frames are checked.
The fixed Q1.23 coefficients were calculated with 70-digit decimal Taylor sums.
The low-amplitude cases additionally have a maximum observed error below 2.35
output LSBs against a direct normalized complex DFT, with a separate 32-LSB
mathematical guard bound. The CPU must match the quantized model bit exactly;
the DFT tolerance is not relaxed CPU precision.
The current corpus witnesses 84640 half ties and 16 clipped transfers.

The generic runner executes each case through reference, cached and JIT backends.
Successful cases compare all visible registers, all supplied P/X/Y words,
dispatch/instruction counts, estimated base cycles and interrupt admission.
Expected memory starts as a copy of initial memory; only explicit after-blocks
change it. This detects unintended writes outside expected output ranges.
Fault cases compare diagnostics and progress but do not assert partially
committed register/memory state. No peripherals are fabricated by the runner.
Native/helper retirement accounting is checked separately; native ALU retirement
can still include instrumented move fallback as described in doc/jit.txt. The
native-move counter separately records successful emitted transfer instructions.
API sequences involving host writes or interrupts between execution steps stay
in C++ tests. Registers alone do not capture hidden REP/IRQ continuation, so
these files describe initialization and expectations, not resumable CPU snapshots.

Private workload fixtures

Assemble manufacturer programs outside the tracked tree, then construct local
.d56 inputs with independently calculated expectations in build/ or doc/local/.
Preparing these inputs can require an assembler; running them does not.
Additional fixtures can be passed directly:

  build/release/dsp56300_fixture_test build/workloads/filter.d56

Or register a semicolon-separated list with CTest through a local CMake setting:

  cmake --preset strict -DDSP56300_PRIVATE_FIXTURES=/absolute/path/filter.d56

Do not add private fixture paths to tracked presets. Test binaries, generators
and the fixture format are not part of the installed public CPU interface.

Warm single-instance benchmark

  taskset -c 2 build/release/dsp56300_fixture_bench build/workloads/filter.d56 0

The optional case argument selects a zero-based case. An additional backend
argument selects all (the default), reference, cached or jit. For example:

  taskset -c 2 build/release/dsp56300_fixture_bench build/workloads/filter.d56 0 jit

An optional REPLAYS argument after BACKEND selects calls per trial in [1,1048576],
default 4096. The benchmark prints the actual count. Use smaller trials for a
complete long program, for example:

  taskset -c 2 build/release/dsp56300_fixture_bench test/fixtures/fft.d56 108 jit 16

Select one backend when profiling its execution independently. Each backend
owns one DSP instance. The benchmark warms 64 calls, then reports the median
and range of nine trials of the selected replay count. It restores host RAM/register initialization
outside the instruction-execution timer, without flushing program decoding.
Execution includes the clock-pair and retirement-check overhead, with no
subtraction. Host preparation is reported separately. Results describe warm
emulator execution, not arithmetic alone, a continuous audio stream or device
performance. Calls must end without a fault, outside DO loops, at an admissible
interrupt boundary with qualified visible state and unchanged program memory.
Initial and terminal state are checked; progress is checked after each trial.
ASan/UBSan builds validate the harness but are not performance measurements.
External perf counts cover the entire process, including host preparation;
they must not be presented as counters for the timed execution region alone.
One replay is one fixture execution: a fixture may contain several complete
DSP routine calls. Report that count when comparing per-call or per-sample costs.

Native FFT research comparison

  taskset -c 2 build/release/dsp56300_fft_native_bench test/fixtures/fft.d56 108 1 512
  taskset -c 0-5 build/release/dsp56300_fft_native_bench test/fixtures/fft.d56 108 2 512

Arguments are FILE CASE [WORKERS [REPLAYS]]. This runs a separately authored
native integer algorithm, not DSP instructions or the VM. It preserves the FFT
model's quantization/clipping and checks every data/output word. It does not
produce DSP registers, stack, flags, progress, code invalidation or event state;
its speed cannot be reported as emulator throughput. Plans/twiddle layouts and
persistent worker creation are outside timing. Input restoration is on the main
thread outside timing; its cache-sharing effects remain. The output permutation
and all stage synchronization are timed. A CPU-feature guard selects AVX2;
scalar fallback remains available. Generic compiler vector arithmetic expresses
four signed32-to-signed64 products, rounding and clipping without suppressing
the portability check. LLVM 19 emits the selected AVX2 operations.
fft-native-algorithm checks every fixture with scalar/AVX2 and 1/2/3/6 workers.
The same comparison passes ASan/UBSan and a separate ThreadSanitizer run.

Wire format D56F, version 1

Every integer is unsigned little-endian. u32/u64 always occupy 4/8 bytes.
No native structures, pointers, padding, enum layout or SIMD state are dumped.
An internal FixtureArchive concept constrains the shared reader/writer algorithm
to explicit u32/u64, text, bounded counts and completion operations at compile
time. Reader/writer scalar templates accept unsigned integral values. Concrete
archive types let the compiler resolve calls statically; wire compatibility is
defined by the explicit encoding below.
Lengths count elements, not bytes, except string lengths. Strings contain their
literal bytes without a terminator. The file ends immediately after its cases.

Header:
  u32 magic 0x46363544 (ASCII D56F), u32 version 1, u32 case_count.

Each case, in order:
  u32 name_length, name bytes;
  three u32 memory sizes in words (P, X, Y), initially zero-filled;
  u32 guest-instruction budget, u32 expected retired instructions (legacy dispatch fields);
  u64 expected retired instructions, u64 expected estimated base cycles;
  five u32 expected fault fields (kind, space, address, value, pc);
  u32 expected interruptible (0 or 1);
  initial register record, expected register record;
  before memory-block list, after memory-block list.

Register record:
  four u64 (X, Y, A, B), with unshifted raw 48-/56-bit values;
  eight u32 R, eight u32 N, eight u32 M;
  ten u32 (PC, SR, OMR, LA, LC, SP, SC, SZ, EP, VBA);
  sixteen u64 stack entries (raw 48-bit values).

Memory-block list:
  u32 block_count; each block is u32 space, u32 address, u32 word_count,
  followed by word_count u32 values, each limited to 24 bits.
  Space numbers are P=0, X=1, Y=2. Blocks apply in listed order.
  Fault kind numbers follow the documented FaultKind order in core.hpp.

Limits: 65536 cases, 256 name bytes, 1024 blocks per list, and 2^24 words
per address space/block. Zero-sized address spaces, unknown versions, invalid
enums, truncated files and trailing bytes are rejected. Files are trusted local
test assets; the reader is not an untrusted network input service. A schema
change, including enum numbering, requires a new format version.
