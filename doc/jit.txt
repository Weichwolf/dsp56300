Native x64 execution

Select Options.backend=Backend::jit on Linux x86-64. The default remains cached.
This is an independent scalar SysV x64 emitter. No external DSP emulator,
assembler, LLVM runtime or JIT library is linked. SSE/AVX lowering, block linking,
native reverse/ordinary-modulo AGU lowering and general register allocation remain
future work; this first backend is not the final performance objective.

Core::run has the same exact guest-instruction budget on every backend. One REP
iteration counts as one guest instruction. RunResult.dispatches retains its
legacy field name but counts retired guest instructions, never native blocks.
Progress excludes a failed instruction, including failed DO cleanup. A short
budget tail may use the general executor. Block length is bounded by
Options.instructions_per_block in [1,256]. The former unused prototype options
for block links and DO dispatch batching have been removed.

The emitter translates signed MPY/MPYR/MAC/MACR variants, RND, CLR, ABS, NEG,
ADD/SUB/CMP, ADC/SBC, internal TFR and NOP retirement. ADD/SUB/CMP include
short/long immediate forms. Native flags use full left-aligned 56-bit
accumulator coordinates, with distinct ordinary/down/up scaling specializations
and sticky state preservation. Other supported instructions execute through the general
executor. Options.optimize=false exercises generated helper-only blocks without
native ALU lowering. Unsupported ISA/modes still report the existing explicit
faults; selecting this backend does not implement the remaining ISA.

Rounding specializes both RM choices and all three supported scaling modes.
Convergent ties use the retained result's parity; two's-complement ties round
toward positive infinity. MACR combines accumulation and rounding overflow for
V/L while preserving C and previous sticky state. The independent fixture model
uses signed quotient/remainder rounding instead of the emitted bias-and-mask
sequence. Mode keys include RM, so a host RM change cannot reuse stale code.

Addition uses x64 ADD/SUB flags at the left-aligned accumulator's bit boundaries.
ADC/SBC must apply guest Carry at host bit eight. With C=1, the emitter fills
the addition destination's or subtraction source's eight low padding bits with
ones and sets x64 CF. ADC/SBB then produces the required extra +/-256, leaving
zero padding and exact full-operation OF/CF. Input signs remain unchanged by
the padding fill. CMP updates flags from old operands while preserving any
parallel transfer to the compared accumulator. Independent signed integer sums
and unsigned 56-bit inequalities qualify carry, overflow and scaling flags;
they do not reproduce the emitted padding technique. CMPM and shifted additions
still use the general executor.

Single X/Y memory transfers for X0/X1/Y0/Y1/A/B and all ordinary paired X/Y
transfer directions now have a host-independent transfer plan and native x64
lowering. Short/absolute/immediate, no-update and linear or valid multiple-wrap
pre/post/indexed forms are admitted. Updating/indexed forms check current low
sixteen M bits on every execution; no-update and absolute forms ignore M.
Every RAM address is checked against its supplied span and the I/O boundary
before any architectural effect.
Failed guards use the same instrumented move helper as before, without duplicate
address updates, callbacks or writes. Stores to any bank overlapping P use that
helper conservatively, preserving program invalidation. Other transfer classes,
PCU register transfers and conditional IFcc forms retain general execution.

Multiple-wrap guards require M-low16 in [$8000,$c000), a nonzero low-fourteen-bit
mask q and q&(q+1)=0. Thus the ring length is a power of two from 2 to 16384.
With old cursor r and raw offset n, the prospective update is
r XOR (((r +/- n) XOR r) & q); upper cursor bits stay fixed. Raw and signed
24-bit N give the same ring coordinate because their difference is a multiple
of every admitted ring length. Linear updates instead mask to 24 bits. Neither
form changes DSP flags. Ordinary modulo, reverse carry and reserved masks return
to the general helper; unsupported modifiers keep its explicit diagnostics.

SI/DI stage prospective X/Y R values while CX/R8 retain effective addresses.
Only after both ports pass modifier/span/I/O guards do R updates commit once;
SI/DI can then capture data. Indexed forms compute the effective address without
writing R, and predecrement uses the already checked prospective value.
Nonlinear validation and its pointer calculation are emitted after all block
returns, keeping linear fallthrough separate from that cold code. Ordinary
modulo/reverse modes branch directly to their helper before any internal call
or R/N load. An internal leaf check is shared within the block;
CALL/RET balances the native stack and
returns its verdict in host ZF, with the valid mask in AX. It clobbers only AX,
R9 and host flags, preserving both ports' staged addresses/updates. Each cold
continuation retains its own bound fallback offset, independent of the emitter's
temporary label lifetime. No additional CPU state or aligned memory is required.
Repeated port/index/address-mode combinations also share a cold update routine;
its verdict returns in ZF before the caller selects its own continuation or
fallback. This routine additionally clobbers only its own port's address and
prospective update. M, R and N remain dynamic on every call; data-register
selectors, RAM limits and fallback targets stay at each transfer site. Sharing
generated code establishes no independence between guest operations or samples.
These internal routines never call C++ or observers and preserve cached A/B;
they do not require the materialization boundary of a runtime helper.

Native moves preserve old register banks that an ALU reads and a transfer can
overwrite, update both AGUs, capture both port values, then commit X before Y.
The host-independent dataflow analysis describes A/B/X/Y effects; unknown move
classes conservatively clobber all banks, and unknown ALU forms read all banks.
Unmodified ALU inputs read current state without an old-value snapshot. This
register-bank analysis does not discard flags or assume independent loop iterations;
a separate bounded flag-liveness pass is described below.
Physical X/Y storage overlap and shared
register destinations retain the existing ordering. Full A/B stores implement
scaling, clipping and sticky S/L directly; accumulator loads sign-extend correctly.
Exact four-byte guest words avoid overreads and mask raw caller-owned data to
24 bits. A native_move_instructions diagnostic counts each successful fast
transfer instruction once, including paired and immediate forms. Pure move
instructions can retire natively too. Overwritten ALU inputs use the old snapshot.
Continuing DO endings execute natively when the current LC exceeds one: decrement
LC, read the saved 48-bit frame through the current masked SP and select its
24-bit loop-start PC. No frame is popped on a continuing iteration. Final LC=1
and malformed LC=0 cleanup return to general execution before any side effects,
so stack cleanup and fault rules remain authoritative. An admitted body ending
in a native instruction can branch directly back to its generated header. The
saved loop-start PC must equal the block's first PC, code must remain valid and
the remaining call budget must cover another complete body. Otherwise execution
returns with the canonical continuation state. Short tails keep the general
fallback. A loop that reloads LC cannot exceed the host instruction budget.
Full instruction helpers inside the body retain their sequential-PC, numeric
mode, LA/LF, REP and invalidation checks before generated execution continues;
faults or changed context exit immediately. The ending instruction's transfer
also checks invalidation before any native backedge. Bodies ending in a general
instruction still return through the existing helper path.
Each backedge materializes dirty A/B before reentering a header compiled with
empty caches. This avoids assuming loop-carried register allocation that has
not been proven. Flags, PC, progress, dynamic LC/SP/frame reads, callback ordering
and fault observations keep their per-instruction semantics. The optimization
reduces dispatcher/entry/exit work, not guest retirement or elapsed DSP time.
REP bodies use their original latched general execution path.

Within a native block, RBP/RBX retain A/B. Native ALU writes update these host
registers and mark them dirty instead of storing every result to Cpu. Reads do
not warm a cache speculatively: only native writes establish live host values.
Native
transfer sources and old-input snapshots read the current cached values when
present. Transfer writes invalidate affected copies after fast/fallback merging.
Unclassified/full helpers conservatively invalidate both copies. Fast transfer
branches do not establish new cache-valid values, so their slow branches cannot
skip initialization. Each new native entry starts with no cached values.

Every runtime helper call materializes preceding dirty results before C++ execution
or callbacks. Loop guards, invalidation exits and normal/partial-budget returns
use shared epilogues for the four possible dirty A/B combinations. This restores
complete canonical accumulator state before the host or general executor can
observe it. A failed move helper exits through an already-materialized epilogue
and preserves the helper's own partial fault state; it never writes stale cached
operands over that state. PC and retirement remain materialized per instruction.
No deferred result survives a native block return.

A backward flag-liveness pass now omits ordinary ALU flag values only when a
later admitted native instruction overwrites them before any possible observer
or exit. ADC/SBC declare incoming Carry; MPY/MAC, rounding, TFR and NOP retain
the proper Carry dependencies. Sticky L still records every overflow, including
an early overflow followed by a non-overflowing result. Sticky S and numeric
mode bits keep their existing transfer/mode rules. SR merges use register
masking and one store instead of an additional memory AND followed by a load.

Every general helper, parallel transfer, loop-ending guard and block exit is a
conservative full-status boundary. Transfers can fault/call observers before
their ALU or invalidate code after it; loop guards can exit before an ending.
Both sides retain complete flags. TFR/NOP never count as flag overwriters.
Short budget tails retain complete prefix state through ordinary compilation
or the general fallback. There are no deferred flags to reconstruct at an
exception or callback: only values proven unobservable before replacement are
omitted. Liveness does not yet cross RAM/AGU guards or general helpers.

Native entry preserves the extra nonvolatile register and SysV stack alignment.
R14 keeps the old-input pointer; R8 is the Y address during transfers and becomes
available to ALU flag code after transfers finish. X/Y and old overwritten inputs
remain memory-backed. This is bounded accumulator allocation/materialization,
not a general SSA register allocator. The bounded flag pass does not establish
independent iterations or vectorize the guest.
MOVEC/MOVEM/MOVEP use the general helpers. Guest SR writes exit on changed
numerical mode, and guest P writes exit on invalidation before executing a
previously planned successor. Directed host sequences exercise both boundaries.
The separate short/long Rn-displacement MOVE forms also use full general helpers.
Their legal control-register writes retain the same materialization boundary:
guest SR changes cannot enter a successor specialized for the old numerical
mode, and current M values remain visible to following native transfer guards.
Displaced stores through data banks overlapping P invalidate planned successors;
warmed P-extension replacement through X/Y aliases invalidates the preceding
decode page as well. There is no displacement-specific native or SIMD speed claim.
Bit access and bit control-flow instructions currently use general helpers too.
Bit SR writes and I/O-bit callback program changes use the same mode/invalidation
exits; no new native-ALU or SIMD performance claim follows from this ISA extension.

Blocks are keyed by guest PC, seven numeric mode bits and active loop address.
An inactive-loop sentinel distinguishes LF=0 from active LA=0. These coordinates
fit injectively in 56 key bits; LC, SP and stack data stay dynamic. Planning stops
at a known loop end. Native instructions away from that end need no repeated
LF/LA loads; the ending instruction checks current LC. Every full helper exits
on a changed LF/LA context before another specialized instruction can execute.
The general loop boundary test masks both the last word and sequential PC to
24 bits, including an extension word wrapped through P:0.
Planning reads only available P RAM and causes no guest fetch fault for
instructions not executed. A helper exits its block on changed PC/mode/loop
context, REP entry, a fault or P invalidation. All host
P mutations must use Core::load/write. Program changes from a synchronous I/O
callback finish the already fetched instruction, then discard the successor
translation. Invalidation defers destruction until executing code and embedded
instruction metadata have returned. Callbacks may inspect state and read/write
memory, but cannot reenter run/reset/set_registers/interrupt. Host initialization
and interrupt admission require stopped execution.

Executable mappings are written as RW and published as RX; published code is
immutable and never RWX. The current cache caps published executable storage at
8 MiB and drops cached translations when full. Metadata is separate host storage.
Code generation and cold compilation can allocate; warm replay reuses blocks.
Native entry/return preserves SysV nonvolatile registers and stack alignment.
The entry has ENDBR64. A small assembly tail bridge enters generated code without
inventing compiler-emitted UBSan function-type metadata.

In strict builds, all project C++ (including code generation, allocation and
memory/I/O helpers) keeps the ASan/UBSan options. No checks or functions are suppressed.
Generated machine instructions and the assembly bridge are not compiler
instrumented; guarded RAM accesses, constant offsets, ABI boundaries and arithmetic
require their own validation. Clang's function check applies to compiler-typed
indirect calls; the bridge uses the explicitly implemented native calling ABI.
Reference: https://clang.llvm.org/docs/UndefinedBehaviorSanitizer.html

JitStatistics reports compiled blocks, published executable bytes, P
invalidations and successful native-ALU/helper retirement. The native ALU count
can include instructions whose parallel transfers still call the move helper;
it also includes pure moves/NOPs and must not be interpreted as fully native RAM/I/O
execution. native_move_instructions overlaps that count and records only complete
transfers executed by emitted code, not helper fallback or failed instructions.
These counters make fallback use visible in correctness tests and benchmarks.

The shared binary fixtures run through reference, cached and native backends.
Directed host tests verify exact/partitioned budgets, numeric mode changes,
stale-code replacement, I/O invalidation of executing code, failed memory moves,
DO restoration, failed cleanup and callback reentry rejection. Manufacturer
programs/fixtures stay local. Benchmarks distinguish initialized warm calls
from arithmetic-only experiments, continuous streams and whole-device behavior.

Selection/control helper boundaries

MAX/MAXM, NOT/TST and ANDI/ORI use general executor helpers, with no new native
lowering or SIMD claim. MAX/MAXM select old raw A/B despite parallel loads;
TST preserves any parallel result while deriving flags from its old source.
Independent native/helper/native tests exercise dirty A/B materialization,
changed Carry feeding ADC, MR writes selecting the next rounding mode, and a
parallel pointer load consumed by subsequent native RAM access. The exhaustive
ANDI/ORI test constrains blocks to one instruction and checks actual translated
helper execution, rather than qualifying only short-budget general tails.
Accepted/rejected I/O callbacks observe canonical native state and exact retired
progress. Callback P edits invalidate the successor before native continuation.
Rejected transfers execute no following ALU and retire no guest instruction;
existing partial-transfer effects and fail-stop semantics remain authoritative.
These tests qualify helper integration only; other numerical modes, full ISA,
pipeline/IRQ behavior and workload performance remain separate requirements.

Extended MOVE qualification

Immediate-short, L: and Class I/II X:R/R:Y moves continue through general move
helpers. No native lowering, new CPU state, SIMD or throughput claim is added.
Independent fixtures test every legal standalone bus-field encoding with six
supported numeric-mode choices, plus raw/partial-field precision and old-input
parallel ALU witnesses. Native prefix/suffix cases check materialization and
fresh Carry/data consumers. Host tests separately require actual native ALU
execution around long/mixed I/O helpers and after successor P invalidation.
A parallel native CMP must use old inputs, followed by an ADC consuming its
new Carry/input state; rejected transfers execute neither ALU operation.
Guest X/Y stores sharing the same P word must execute the final stored successor,
including the second L: half winning a shared X/Y word. Wrapped P extensions
resume normal instruction budgets and subsequent arithmetic. Explicit unsupported
numeric modes and unqualified IRQ/pipeline/event behavior remain gaps.

RTI boundaries

RTI uses a general executor helper after dirty native values are materialized.
Successful return restores the raw PC/SR and reselects numeric specialization;
independent tests warm the foreground under an old mode, execute actual native
MAC/MAC before RTI, then require native ADC/rounding under restored Carry,
scaling and RM. Zero budgets preserve the existing post-return exclusion.
Failed returns do not load fabricated zero PC/SR. Failed long interrupt entry
stops before service-state/retirement changes; existing EA effects survive a
subsequent failed push. Host-injected vector instructions execute generally,
contributing architectural retirement/base costs but not native JIT counters.
Binary interrupted-DO/nested-frame tests qualify their own successful state
subsets; complete extended stacks, exceptions, numerical side effects and
sequence/IRQ/event/pipeline behavior remain open. No throughput claim follows.

Software-exception boundaries

Explicit ILLEGAL/TRAP/TRAPcc use general execution and terminate native blocks.
A pending request blocks native dispatch until its bounded vector completes or
enters a long handler. REP ILLEGAL defers/coalesces that request until REP ends.
Conditional traps read canonical current flags, including flags just produced
by native arithmetic. Cache clearing invalidates translations while preserving
pending vector state. After long entry and RTI, normal mode/loop keys select
code for the new/restored state. Tests require actual native MACs and Carry/
rounding consumers across these transitions, including warm old-mode code and
short/long vector calls; backend agreement alone is insufficient evidence.
The controller is private owner state; Cpu and generated-code offsets remain
unchanged. Clang 19 x64 layouts show Cpu=384 and Core::Impl=131648 bytes before
and after; the new 16-byte controller fits prior owner padding. This does not
measure cache misses, latency or throughput. No native exception lowering,
SIMD or benchmark result is claimed in this increment.
Full vector/mode/event/pipeline qualification remains open; doc/exceptions.txt
records the software-exception conventions and unresolved manufacturer details.

Architectural cache and native execution

Guest cache state is independent from decoded/native host caches. clear_code_cache
must preserve DSP tags/valid words/locks. Host backing-RAM writes invalidate
translations but may leave instructions cached in the DSP. JIT compilation from
raw RAM is therefore disabled whenever SR.CE is set; the common executor performs
actual fetch/fill/LRU/PMOVE actions within the exact budget. A helper that sets
CE exits its block even if numeric mode and PC otherwise match; clearing CE
flushes DSP cache state and permits native execution. Directed witnesses require
two actual native arithmetic instructions around four general instructions across
that transition. This guard is temporary general fallback, not a performance
optimization of cache-enabled programs. A future native cache-enabled backend
must preserve architectural fetch order and cached data instead of speculatively
using raw P or letting translation lookahead alter replacement state.
Cache storage/geometry is separate cold owner state; Cpu/generated-code offsets
stay unchanged. Exact memory-layout results and the current semantic gaps are
recorded in doc/coverage.txt and doc/program-cache.txt. No throughput/cache-miss,
SIMD, host-load, energy or whole-device improvement is claimed in this increment.

Processing-state boundaries

WAIT/STOP terminate blocks and successful helpers stop native continuation
when the CPU enters sleep. Every dispatch checks the state before more guest
work. Sleeping run calls return immediately, including zero/maximum budgets,
and cannot consume successor instructions or interrupt exclusions. Wake/resume
then uses the existing mode/loop keys and exact instruction budgets. RESET uses
the common instrumented helper and requires a real host acknowledgement; it can
continue a block when state/mode/PC/code remain valid. Callback P changes still
invalidate and end continuation before modified successors. Tests require actual
native arithmetic before/after RESET and wake/RTI under warm old-mode code.
The state byte uses prior Cpu padding, keeping every existing generated-code
offset and Cpu size unchanged. RunResult.state uses prior result padding; Io
has an extended callback interface and consumers rebuild. This is a layout
result, not a speed/device/isolation claim. Full pipeline/clock/event and
physical reset/debug qualification remains open; see doc/processing.txt.

DEBUG/DEBUGcc boundaries

Both debug operations terminate blocks even though the functional single-word
REP model admits them. Helpers materialize fresh flags, evaluate conditions and
either halt, queue an IME request or continue untaken. Pending debug blocks native
dispatch until its budgeted vector is admitted after REP/active-vector completion.
Debug halt stops all retirement; explicit resume preserves continuations, edits
and mode keys. Actual native warmup, prefix, handler and continuation witnesses
qualify state rather than inferring native execution from Backend::jit selection.
The logical IME/SWO/pending byte uses Cpu padding; cached generated-code offsets
remain subject to the layout audit. This introduces no debugger-loop execution,
trace engine, native/SIMD lowering or protected backend. Complete OnCE/pipeline,
mode/sequence/timing and performance qualification remains open.

Retirement checkpoints

Guarded native regions can defer instruction/base-cost publication and internal
PC stores until transfer, loop-guard and return boundaries. Pure regions derive
both common increments from the existing per-call R15D retirement count. Regions
with possible transfer helpers use pending SSE2 qword lanes, materializing them
before calls and reinitializing caller-saved temporaries afterwards. Numerical
DSP arithmetic remains scalar x64. General helper blocks, short straight runs
and aliased P stores keep scalar retirement. CPU and runtime layouts are unchanged.
See doc/native-retirement.txt for exact admission, callback/fault/wrap tests,
measured filter gains and FFT tradeoffs. This is not full-program native lowering
or evidence that representative 270 MIPS execution has been achieved.
