Guarded ordinary modulo postincrement

The continuous IIR stream repeatedly traverses a 20-word coefficient ring.
The existing native linear/multiple-wrap transfer path falls back to the C++
move helper for ordinary modulo. That publishes live accumulators, status,
retirement and old operands around each access. The new continuous benchmark
makes this overhead visible; its first unpinned run is not a final speed claim.

At native compilation, take a transient snapshot of the eight M registers.
For postincrement by one with a snapshot M in [1,32767], compile the known ring
length and enclosing power-of-two span as immediates. Every execution guards
that the current low16 M still equals that snapshot. A mismatch uses the
existing dynamic linear/multiple-wrap/general fallback. No M assumption enters
the code-cache key, and instructions earlier in a region may freely change M.

Value            Placement                 Lifetime/observation
M low16          AX                        exact runtime guard before updates
old R            CX (X) or R8 (Y)          memory address, unchanged by guard
prospective R    SI (X) or DI (Y)          committed only after all port guards
ring upper       R9                        temporary, no architectural state
wrapped R        AX                        temporary candidate for CMOV
old ALU inputs   existing XMM snapshots    captured after both address guards

For length L=M+1, span mask S=bit_ceil(L)-1:
  upper = (old_R & ~S) + L
  next = old_R + 1
  if next >= upper: next -= L
  next &= 0xffffff
This matches the independent ordinary one-wrap contract, including an R in the
unused tail of its enclosing span and a carry across the 24-bit boundary.
There is no assumption that R starts inside the logical ring. The lower-bound
case cannot occur for a positive unit step. N is not read. Reverse carry,
multiple-wrap, non-unit updates and an unmatched modifier retain the fallback.

The optimization changes neither transfer ordering nor ALU/CCR behavior.
RAM/I/O bounds, P aliases, paired port capture and partial-failure handling use
the original checks. Test same-code reuse with changed M/R/N, power-of-two and
non-power-of-two rings, low16 masking, tail addresses and the top word boundary.
Qualify full independent architectural fixtures and continuous final states,
then compare identical sustained input with the saved baseline binary.

The implemented power-of-two length case uses the equivalent masked update.
Both hot cases fall through to the existing bounds/capture logic. Mismatch
linear and multiple-wrap checks remain out of line with the general helper.
The eight modifier values exist only in the temporary compiler object; CPU,
NativeContext, owner state, executable ownership and public headers are unchanged.
Additional code bytes and slow paths are reported rather than hidden.

The dedicated boundary matrix exercises seven initial M values, all eight
address registers, X/Y load/store, changed high M bits, changed ordinary/reverse/
linear/multiple-wrap modes, N values that must be ignored for unit increment,
valid/tail/end-of-RAM cursors and exact same-code reuse. It compares complete
registers, memory, progress and native-transfer counters with the independent
coordinate oracle. Rejected bounds run the existing partial-state/fault contract.
Existing paired transfers, alias/I/O and event-boundary suites remain required.

Controlled continuous comparison

The final paired run, with identical two-second input and one-second measured
packages, gives 3.091567..3.103887 s baseline versus 1.266911..1.267666 s candidate
on one pinned core. Process CPU is 3.091720..3.104073 versus 1.266997..1.267733 s.
This is about 2.44 times throughput (88.4..88.8 to 216.5..216.6 actual guest MIPS)
and 59.1% less CPU per input second. Both binaries pass complete independent
final-state checks. Candidate code storage increases 40960 to 45056 bytes;
CPU/NativeContext/public layouts stay unchanged. The deadline remains unmet.
See continuous-bench.txt for the workload, alternating order and limitations.

Both complete 107-test configurations pass after the final code, including all
78446 native-move assertions and unchanged original fixture archives. The full
continuous case matches its independent expectation in all six release variants
and the strict production JIT. Format, clang-tidy/Werror, hardening and sanitizer
policies remain unchanged. Complete ISA and sustained realtime remain open.
