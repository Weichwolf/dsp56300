Bounded captured CPU-result continuations

The captured pcu_updates route can compute up to eight CPU publications ahead.
It uses the ordinary executor and records each writer plus its exact intermediate
computed registers. A CPU writer has no external input operand. Reads, writes,
bits and reset remain real owned Io boundaries; no response is predicted.

Boundary                 Visible CPU                  Private continuation
compute                  accepted prefix only         CPU writers and next boundary
accept CPU writer        that writer's mask only      remaining writers, same ordering
accept Io                one real operation           replay with its recorded response
accept retirement        native hidden fields/deltas  instruction finished

Tickets keep their original accepted-prefix ordinals. Checkpoints include the
unaccepted queue and subsequent boundary; stale/cross-owner tickets still fail.
Candidate checkpoints require the actual retirement boundary. Copies of pending
observations cannot alter stored writers. Memory mutation between publications
is sampled only at the real read; accepted operations are never replayed to Io.

Guards require captured words, PCU publication, no cache/active REP, vector or
pending debug entry. DO/DOR setup, explicit loop control, cache and system
opcodes retain general replay. Ordinary instructions inside an active DO loop
can plan their CPU writers, including a real loop rewind or final frame pops.
LF alone does not prohibit planning; a current CE bit still stops collection
before that publication. Filling
the bounded queue stops at the next boundary, rather than publishing or failing
early. The overall accepted-effect capacity remains unchanged.

A native fault/exception after an unaccepted CPU writer discards the private
plan and replays without planning for the rest of that instruction. The original
first publication, accepted prefix and fault/exception order are retained.
No external operation has happened in the discarded suffix. Cache guards retain
existing cache visibility and host-mutation contracts. This changes host work,
not instruction base costs, processor clocks, overlap or hardware timing.

Targeted checks:

  cmake --build --preset strict --target dsp56300_cpu_continuation_test dsp56300_cpu_plan_storage_test dsp56300_alu_fixture_test dsp56300_external_run_test
  ctest --preset strict -R '^(bounded-cpu-|captured-pcu-publication-|external-memory-execution$)'

Repeat with the thread preset for separate TSan instrumentation. The 15 captured
archives retain their independent full register, flag, memory, fault and progress
expectations across three backend selections. Captured words come from the real
fixture program; exception vectors, cache-enabled execution and unavailable
words retain owned fetch. The existing --pcu archives use owned fetch and do not
exercise the captured planning path. Neither scope is complete ISA coverage.

Run each diagnostic workload/mode in a fresh process to avoid sanitizer allocator
carryover; the bench reports selected/skipped workloads and modes:

  build/strict/dsp56300_external_run_bench audio-mac captured-pcu

Workloads: audio-mac, image-add, communications-xor. Modes: synchronous-batch,
synchronous-step, staged, captured-pcu. Either selector also accepts all.
