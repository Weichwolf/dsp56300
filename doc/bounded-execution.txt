Bounded native execution and owner boundaries

Core::run(RunBudget{.instructions = n, .cycles = c}) retires at most n guest
instructions and at most c documented instruction base cycles. Both limits
apply. These costs exclude pipeline/IRQ-entry latency and derivative/bus wait
states; the board owner retains its clocks. RunResult progress is cumulative;
BoundedRunResult.cycles is the actual call-relative base-cycle delta.

The bounded entry executes instructions proved free of unowned peripheral and
unqualified control effects, including explicitly granted ordinary RAM. It returns
external_effect before the entire boundary instruction: no ALU, effective-address update, PC change,
data callback or partial transfer from that instruction has occurred. Known P
inspection is pure metadata under the Io code-view contract. Eligible direct
RAM windows are described in memory-windows.txt. Unknown reads, unsuitable
permissions, unsupported address forms and other owner effects retain an explicit
whole-instruction boundary, including failed second-port admission.

RunStop distinguishes instruction_budget, cycle_budget, external_effect,
unknown_code, control_event, state, yielded and fault. A cycle_budget stop may
leave unused cycles when the next instruction cannot fit. Debug/vector/cache
transitions return control_event rather than guessing their ownership. Ordinary
Core::run(n) retains unrestricted execution and its existing result contract.

At a stopped running boundary, pc identifies the genuine next fetch address;
it can be a vector address while Registers.pc still holds the interrupted PC.
When a complete instruction is genuinely known, next and next_cycles expose
its words and base cost, including at either budget limit or a zero budget.
The query prefers actual REP and accepted vector-pair latches over newer backing
P bytes. Unknown code/extensions and unqualified debug admission stay explicit.
A preview does not fetch a vector pair or acknowledge an interrupt. The owner
must retain the actual begin_fetch/advance protocol for those bus effects.

For an ordinary owner-handled instruction, begin_instruction(*result.next) can
latch this code snapshot before events/clocks advance. Subsequent P edits do not
silently change the already accepted instruction. This remains the existing
captured single-instruction path, not native clocked effect publication. The
owner must process its genuine effects and timing before admitting another CPU
region. The bounded API alone is not a connected scheduler.

Native translation records cumulative base costs and the admitted prefix
once at compilation. Entry caps both limits without a per-instruction budget
callback. Shorter warm prefixes receive bounded cached native translations;
they no longer fall back merely because an existing block is longer. Prefix
pages count against the same 8 MiB executable bound. Hardware-loop backedges
retain live LC/SP/frame guards and whole-body costs, with a native tail when
needed. Unqualified operations/modes retain explicit general execution/faults.
Short absolute JMP outside a loop ending now uses native PC retirement, preserving
all CCR/numeric-mode bits and its three-cycle base cost. Loop-ending control
restrictions remain unchanged.

Qualification is scoped in bounded-execution-reference.json. Authored tests use
independent arithmetic/BFU/register expectations, actual native/helper counters,
zero/REP/vector previews, accepted/refused owner effects, snapshot P mutation,
mixed-cost loops and cache-capacity eviction. They do not establish physical
clock timing, complete ISA, connected firmware startup or instrument throughput.
