Arithmetic shifts in saturation mode

Scope and specification

General 56-bit ASL/ASR accept SM in single-bit parallel and immediate/register
forms. Single-bit parallel results enter the existing three-bit limiter. The
multi-bit immediate/register forms use the BFU and bypass arithmetic saturation,
even for encoded count one or zero. This distinction corrects the earlier
qualification, which incorrectly limited BFU results. See saturated-normalization.txt.
Carry is the last shifted-out original bit, cleared at zero count. Raw left-shift
sign changes set V/L; a single-bit limiting event also sets V/L. Result flags
use the stored value. Sticky S/L and unrelated state remain intact.

Primary evidence is DSP56300FM Rev.5 sections 3.1.5 and 3.2.3/table 3-1 and the ASL/ASR
entries (13-14..17):
https://www.nxp.com/docs/en/reference-manual/DSP56300FM.pdf
Manufacturer copies/extracts remain ignored. No manufacturer program, other
emulator implementation or board behavior is used.

Defined counts 0..55 are admitted. Existing diagnostics for undefined larger
counts remain explicit software contracts, not claims that hardware traps.
SA/SC/DM, reserved scaling and logical-shift/other unqualified SM forms retain
unsupported-mode diagnostics. NORM/NORMF now admit their distinct SM paths; DIV SM remains unsupported. SM native
shift admission is also unchanged: the JIT uses exact general execution while
ordinary eligible single-bit ASR retains emitted x64. Public state/API/layouts
and instruction costs are unchanged. No new speed claim for SM shifts is made.

Independent witnesses

The producer links only the fixture codec. Its independent raw56 array moves
one bit per iteration; it does not reuse the executor's multi-bit host shifts.
It applies the action table only for single-bit forms; BFU forms retain raw
results. This corrects the original erroneous all-forms limiting expectation.
52632 new cases compare complete registers, all memory, exact costs and fault/
execution contracts through reference/cached/JIT, yielding 1473697 assertions.
Matrices include all immediate counts, source/destination pairs, all six legal
control selectors with high bits ignored and aliases, every initial extension
byte/MSP sign with selected counts, every initial CCR byte, six scaling/RM
choices, individual/complemented raw bits and three-iteration REP. REP tests
separately require dynamic A1 count reevaluation and saturation after each step.
These are explicit finite matrices, not exhaustive full-ISA qualification.

The 2016 additional host checks exercise both optimizer settings, block limits
1/64 and all three backends: same-PC ordinary/SM/ordinary reuse, every mixed
mode prefix, exact native/helper retirement, all undefined immediate/X0 counts,
canonical synchronous callbacks, old parallel B despite an incoming B load,
rejected-load partial state, fail-stop no replay and P edits to the next shift.
The failed transfer retains the loaded destination but no shift/retirement.

Exactly two obsolete SM negative records in bit-operations.d56 become successes.
Every input register/block stays byte-identical, every unrelated record stays
byte-identical and the other fifty old archives stay unchanged. The new archive
brings the total to 52; exact regeneration is registered in CTest. No expectation
is obtained from executing the DSP, and no fuzzing or publication is performed.

BFU reference-review correction

The first SM shift qualification misclassified the multi-bit forms. Section3.1.5
places them in the BFU; section3.2.3 bypasses SM for every BFU operation. The
current compiler-independent producer now distinguishes forms explicitly, even
when counts match. Original inputs, case counts and all unrelated records stay
unchanged. Old timing captures remain historical; green old expectations do not
prove the formerly assumed semantics. See saturated-normalization.txt for the
new mode/normalization matrices, complete-record audit and final qualification.
