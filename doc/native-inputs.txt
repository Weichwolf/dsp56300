Native parallel-input snapshots

Implementation and state mapping

Parallel moves commit before the native ALU but the ALU consumes old operands.
The existing dataflow mask identifies only banks overwritten by the move and
read by that ALU. Snapshot lifetime ends with that instruction; this is not a
persistent SIMD register-bank cache or the final adaptive region allocator.

Bank     Representation       Temporary    Source on guarded fast path
A        aligned raw56        XMM3 low64   dirty RBP or canonical A
B        aligned raw56        XMM4 low64   dirty RBX or canonical B
X        raw48                XMM5 low64   canonical X
Y        raw48                XMM6 low64   canonical Y

Allocate only banks in the old-input mask. Arithmetic extraction, scaling,
rounding and flags retain their existing lowering. SSE2 is an x64 baseline.
No ABI, canonical layout, public option or guest instruction admission changes.

Transition                 Required action
all transfer guards pass   capture old live banks before any move commit
register-only move         capture before source conversion/destination write
guard/general transfer     helper records authoritative pre-transfer snapshot
helper success             reload every needed SIMD snapshot from that record
helper failure             exit without consuming/clobbering partial fault state
next guest instruction     no snapshot live; allocate its own mask independently

Keep the memory snapshot path for local matched controls and general execution.
Qualification must include both accumulator banks, X/Y aliases, all word lanes,
helper SIMD clobbers, reject/fault/dirty exits and loop/budget boundaries. Compare
independent FIR, FFT and other fixture sets with the same execution scopes.
Do not infer a speedup or complete adaptive allocation from this design alone.

Lane and backend qualification

The emitter constrains scalar transfer LaneBits to 32 or 64 at compile time;
32-bit MOVD zero extension is distinct from the full MOVQ snapshots. Geometry
and core contracts are documented in backend-contracts.txt. The same fixture
test/bench executables instantiate reference/cached/JIT typed cores together.

native-input-snapshots performs 66495 directed checks: all 64 single bits and
complements across eight low/extended source/destination GPRs, four XMM slots
and both transfer widths; typed backend selection despite conflicting options;
host-word validation and P mutation; and all six data-register destinations,
six numeric modes, helper clobbers, rejection and P invalidation across backends.
Existing retirement observers additionally clobber XMM0..6. Independent ASR,
register/memory transfer, status, dataflow, loop, FIR and FFT tests retain their
full original expectations. All 41 binary fixture archives are unchanged.

a matched control with only admit_cached_inputs disabled. The other 41 archive

The 270 MIPS reference load, realtime/energy and broad application optimization
remain unestablished. Restoration, cold compilation and warm scopes are separate.

A diagnostic three-way sweep checked 304 uniform samples over all 41 archives;
three archives remain explicitly correctness-only for warm timing. Some tiny
unchanged-code cases varied by 6-12% in one sweep. Nine rotating-order rechecks
reduced the largest parallel-MOVE outlier from 12% to about 0.5%; mixed-MOVE and
bit-access differences remained around 1-2%. This is host/harness variability
evidence, not proof that every other workload has zero regression. Keep raw
results and investigate meaningful changes on longer representative programs.


Closed-loop residency follow-up

The snapshot format above remains the ordinary/helper-path format. Proved
helper-free RAM loops can experimentally retain current X/Y in XMM5/XMM6 and take old X/Y
snapshots in XMM0/XMM1; old A/B retain XMM3/XMM4. Those temporaries are free
during helper-free retirement, with explicit admission and canonical exit
publication. See loop-residency.txt for the proof and independent witnesses.
The measured SSE2 format is slower and remains a private experiment; automatic
mode retains canonical X/Y. The full adaptive allocator remains open.
