Arithmetic saturation: independently qualified first domains

Scope and manufacturer evidence

DSP56300FM Rev.5 section 3.2.3 and table 3-1 describe a saturation decision using
EXT[7], EXT[0] and MSP[23] of the rounded 56-bit result. This is not equivalent
to comparing the full signed 56-bit value against a numerical 48-bit range:
noncanonical middle extension bits do not participate in that table. Existing
raw fixed-point coordinates, 56-bit carry/overflow and sticky transfer flags
remain explicit. Original manual copies/extracts stay in ignored storage.
Reference: https://www.nxp.com/docs/en/reference-manual/DSP56300FM.pdf

State                       Representation             Observation
A/B result                  existing aligned56-in64    saturate after rounding
three decision bits         existing raw positions     no middle-EXT clamp assumption
rounding RM / S0 / S1        existing instruction state constants independent of scaling
E/U/N/Z and V/L              canonical flags            recomputed for limited result
C and sticky S               raw arithmetic / transfers saturation does not replace them
parallel operands           existing old-input latches callbacks precede selected ALU
PC/progress/frames/RAM       existing core contracts    every budget/return/fault boundary

Positive limiting uses the 48-bit positive maximum, and negative limiting uses
the sign-extended 48-bit minimum. When a rounded instruction limits positively,
its entire low24 word is cleared, independently of scaling. A limiting operation
sets V/L and computes the ordinary result flags from the stored value; raw56
overflow and sticky L remain retained. C comes from the original 56-bit arithmetic.
These are software witnesses derived independently from the manufacturer model,
not physical hardware qualification of every unusual operand/pipeline sequence.

Current implemented SM domains

- Ordinary parallel ADD/SUB/ADC/SBC, signed MPY/MAC and rounded variants, RND,
  CLR, ABS and NEG use the new qualified SM path. Immediate ADD/SUB and raw-LSB
  INC/DEC are included. Normal CMP and shifted add/subtract remain unqualified.
- Immediate signed products and positive power products n=1..23 saturate after
  arithmetic/rounding. DMACss saturates after its existing signed right shift and
  accumulation. MACsu/uu, MPYsu/uu and DMACsu/uu bypass arithmetic saturation.
- TFR, Tcc and pure parallel MOVE families retain their distinct transfer or
  bypass behavior. MOVE A,A can limit and set L without setting V. Existing CMPU
  and BFU bypass semantics remain available.
- SC/SA/DM combinations, reserved scaling, shifts/normalization/division, other
  SM ALU forms and unqualified nonparallel/count transfers are still rejected
  explicitly. The full SM numerical mode is not claimed complete.

The x64 compiler still rejects SM native lowering. Qualified SM instructions
execute through the general implementation with exact mode keys and publication.
Ordinary native code remains available before/after an SM change. No CPU/context
layout, public option, board behavior or other-emulator dependency is introduced.

Independent qualification

A new deterministic binary producer uses unshifted raw56 arithmetic, an explicit
three-bit action model, independent quotient/remainder rounding and existing
independent full-state models. It never executes or links the emulator to obtain
expectations. The new archive contains 65536 cases. It includes every extension
byte with both MSP signs and accumulators; every CCR byte for representative
arithmetic; six scaling/RM choices; all 128 signed multiply/MAC encodings; every
positive power n=1..23 and source/destination/round/subtract selection; immediate
boundaries; all sixteen mixed-product operand pairs and signedness/bypass forms;
aliases, raw56 overflow and sign/rounding boundaries. Tcc additionally samples
every old CCR with all legal data selectors/destinations and both polarities
of every condition. Conditional MACR tests IFcc versus IFcc.U publication.
Existing instruction costs and complete architectural state remain checked
through all three backends.

All 65536 new cases pass complete-state checks in each of the reference, cached
and JIT backends (1835009 fixture assertions). The separate host boundary test
passes 9774 independent checks per build.

Host boundary tests require actual ordinary native / SM general / native
execution. They check same-PC mode reuse, every call prefix, exact instruction/
base-cost publication, old parallel operands, aliased X-before-Y stores, MOVE's
V/L behavior, synchronous I/O observation, P changes during callbacks and rejected
requests' partial destination/fail-stop state. Unqualified SM operations and
combined numerical modes reject before ALU or RAM effects. Full mode/sequence,
interrupt/pipeline/timing and physical hardware qualification remain open.

Exactly 77 old unsupported-SM records are promoted to independently calculated
successful cases across six archives: immediate MOVE 28, long MOVE 16, mixed
MOVE 20, integer 4, immediate/power products 4, mixed/DMAC products 5. Their
initial registers and input memory/program blocks are byte-identical. Every
other record in those archives is byte-identical; the other 42 old archives
are wholly unchanged. The new saturation archive brings the total to 49.
This replaces obsolete diagnostics without dropping their stimuli or weakening
checks. All unqualified modes retain explicit independent negative tests.

Initial full sweeps retain one obsolete negative expectation: the native-shift
test grouped SM register MOVE with still-unqualified SM shifts. Its original
MOVE stimulus now requires exact independently calculated transfer state and
general-only execution, while the shift/other-mode rejection checks remain.
Final sweeps pass all 121 tests in release (104.56 s, two CTest processes) and
strict (234.69 s, three), with no skips. All eighteen complete ordinary-stream/
backend combinations match independent state. Strict bench validates all three
full states in report-only mode, retaining late packages. All 49 archives
regenerate, all 133 strict C++ units retain required nonrecovering instrumentation
and all 173 C++ source/header files pass format/tidy/Werror. Structural ISA audit
passes; all 118 catalogue rows remain partial, and require-complete still fails.
No fuzzing or publication is performed.

Ordinary-workload cost and fast-path correction

The first implementation adds general helper calls even with SM clear. Matched
parent/candidate/candidate/parent captures retain its FIR CPU regression of 2.47%
and spectral regression of 1.20%, with essentially unchanged IIR. All packages
pass; these observations are not discarded. The final version skips saturation
calls when SM is clear and keeps ordinary numeric admission on its original
helper, entering SM classification only for an active SM bit. This preserves
all specified effects and avoids the extra ordinary-mode calls.

A fresh matched comparison uses the same verified parent and final candidate
on CPU2, one natural input second warmup plus one measured input second in the
same DSP. No register/RAM restoration, completed-program replay, overhead
subtraction or build/test/format task from this repository. External host
activity/frequency/scheduling remain uncontrolled. All twelve states pass.

Native/general/move/batch/AVX2 counts and page storage stay unchanged in all
three ordinary scenarios (32768 / 49152 / 344064 bytes). This is a semantic
extension with regression checking, not a new general throughput/cache/energy
claim. The new single-instruction SM fixtures are not throughput benchmarks.
SM continuous capacity/native speed remain unqualified.

This increment does not complete full ISA, SM native performance, all application
domains, cache/energy, SIMD/multicore, adaptive allocation or sustained realtime
objectives. The original objective remains active and unchanged.
