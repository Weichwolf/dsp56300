General executor paths in JIT mode
=================================

Requirement: legal instructions must execute natively in JIT mode. Host I/O,
event delivery and explicit fault reporting are separate from instruction
interpretation. Correctness-preserving fallbacks currently remain open native
coverage; this record does not qualify complete ISA or application performance.

The x64 emitter has three general-helper call sites and two callback targets:

Site                                Target                 Current triggers
----------------------------------  ---------------------  ---------------------------
x64/jit_emitter.cpp generate_body    Core::Impl::jit_execute lowerable() rejects the form
x64/jit_moves.cpp general_moves     Core::Impl::jit_moves   Unsupported or guarded MOVE
x64/jit_loops.cpp loop_setup        Core::Impl::jit_execute Insufficient stack capacity

Paths are relative to src/jit/. jit_execute calls step_decoded; jit_moves
calls the general moves implementation. An emitted wrapper around either
callback is not native instruction implementation.

MOVE triggers include unplanned transfer forms, stores to program-aliasing
memory, non-linear pure AGU updates, unsupported modulo/reverse addressing,
failed bounds/known-memory/window guards and peripheral accesses. The existing
native arbitrary-modulo specialization covers only selected post-increments;
other legal modifiers/modes remain gaps. A rejected native address must retain
its exact AGU update, first fault, alias, code invalidation and I/O ordering.

Direct interpretation also occurs outside emitted code:

- Core::run falls back to step() if native dispatch retires nothing or if a
  real instruction cache, vector or debug condition prevents native admission.
- Impl::run_bounded falls back to step_decoded for an admitted owner-free
  instruction when native dispatch cannot run it. External effects return to
  their owner instead of silently performing I/O.
- REP bodies can run natively, but unsupported bodies and final DO cleanup
  still return to general execution. DO ending guards also leave the emitted
  block before final cleanup.
- Staged compute_attempt calls step() while reconstructing captured/owned
  effects. Its CPU-result plan avoids some replay but is not native emission.
  Accepted effects, partial publication and checkpoints must survive a native
  replacement unchanged.

Current direct-emitter instruction-family admission is limited to NOP, short
JMP, selected immediate DO setup, immediate ADD/SUB/CMP and selected parallel
ALU/MOVE forms. These five families are context-guarded and mostly partial.
The public shape enum declares 76 kinds, including unsupported; the other 70
recognized kinds have no direct instruction body in lowerable(). REP native
body execution does not imply native implementation of its setup instruction.

Missing direct families include effective jumps, calls/returns/interrupt return,
control-register logic, other loop/repeat forms, immediate/register shifts,
address calculations, DIV/NORM/NORMF/VSL, other product families, INC/DEC/CMPU,
extract/insert/merge/CLB, conditional/relative branches/transfers, control/
displacement/program/peripheral MOVEs, bit operations/branches, traps, cache
operations, RESET/WAIT/STOP and debugging operations.

Within the admitted parallel family, IFcc/IFcc.U and several ALU selectors
still fall back. Numerical-mode exclusions, unsupported scaling combinations,
SM admission and compatibility-mode DO endings are additional entry guards.
An instruction family being listed here is not a complete opcode census.
Explicit optimize=false rejects native bodies as a diagnostic setting; host
and build admission can also prevent generated execution. Neither configuration
establishes normal native coverage.

Qualification must compare independent registers, RAM, flags, progress,
publication, faults and checkpoints, then require actual native counts for
each claimed path. helper_instructions measures whole interpreted retirements;
the transfer helper does not increment it. A zero helper count alone therefore
does not prove native transfers. Require native_move_instructions and inspect
emitted call targets as appropriate. Staged computation is also a distinct
measurement scope.

Recheck the inventory with:
  rg -n 'helper\(|general_moves\(|runtime_\.(execute|moves)' src/jit
  rg -n 'step_decoded\(|step\(' src/core.cpp src/core/bounded.cpp src/core/staged_compute.cpp
  rg -n 'lowerable|is_loop_setup|is_addition|is_logic|is_right_shift' src/jit/x64

Priority: replace common instruction/transfer fallback bodies with native
emission, qualify dynamic guards and state boundaries, then remove the general
JIT callbacks after every legal path has an independently tested replacement.
Do not remove correct execution, weaken guards or relabel counters to claim
completion. No complete-native or connected-instrument milestone is achieved.
