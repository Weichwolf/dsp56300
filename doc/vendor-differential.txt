Deterministic vendor-software differential qualification

The reference is the local TASKING sim563.dll 6.3.1, configured for DSP56371,
SHA256 2b0eb4712275527a5af9775eee2fe541b6463ea9eb21e63f49b7f9bf9f22b36a.
It is a separately executed proprietary software reference, not a physical chip
or a production dependency. Only our authored programs and numerical snapshots
are distributed. The DLL, its bridge/captures and manufacturer assets stay local.

The first matrix takes 384 fixed evenly spaced positions per authored archive,
then records explicit adapter-domain exclusions. It executes 15936 cases across
46 archives. The second pairs 20188 ordinary/SM single-instruction inputs, with
reserved Mn high bits cleared while retaining the $FFFFFF linear reset state.
These are deterministic structured tests, not fuzzing or exhaustive operands.
Reference reset occurs before every case. All 44 mapped register fields, 16 raw
stack slots and complete 1024-word P/X/Y windows must read back exactly before
stepping. GDI debugger SSH/SSL windows were separately checked to preserve SP/SC.

The three Core backends produce byte-identical actual results in ASan/UBSan and
separate TSan profiles. Final exact matches are 13864/15936 and 18389/20188.
The candidate has no refusal in these matrices, and no previously matching,
accepted baseline case regresses. Remaining 1321/1171 numerical/state differences
and 751/628 setup mismatches remain findings, not automatic Core failures.
The vendor cannot establish every debugger-seeded REP/DO/exception continuation;
forbidden duplicate parallel destinations and unpredictable modulo inputs do
not define portable expectations. Reserved bits, 16-bit register views, valid
modulo-stride boundaries and stack/exception behavior need further adjudication.
The vendor's DSP56371 relocation model already conflicts with documented maps;
its peripheral, memory-profile and timing behavior is not a hardware oracle.

The frozen 2433 CPU-domain and 20 loop/count cases select formerly rejected SM
inputs whose ordinary control agrees between independently executed Core and
reference. Both initial readbacks and reference steps must succeed. Selection
and expected snapshots use no candidate-Core result. The manifests record
parent archive hashes, predicates, exclusions and capture hashes. Their finite
scope is defined by the actual inputs, not every possible form of each mnemonic.

Implemented domains now include CMP/CMPM, TST, MAX/MAXM, immediate CMP, DIV,
address calculations, displaced/program/control/peripheral transfers, bit
operands, VSL and count inputs under SM. TST/CMP limit a virtual result for flags
without writing operands. DIV limits its stored result, sets V/L on limiting,
and preserves S/E/U/N/Z and the pre-limiter quotient Carry. A suppressed NORM
shift still passes the limiter while retaining its exponent. Other mode guards
remain explicit; there is no blanket SA/SC/DM or reserved-scaling admission.
MOVEP has independent authored exact-I/O/scaling/limiting tests in addition to
software-reference CPU cases; this does not validate any derivative peripheral.

Fifty scoped native groups pass across both sanitizer profiles: codec-only
fixture generation, arithmetic/transport/staged/SM boundaries, old arithmetic
regressions and the new dispatched/owned/captured cases. Every child exits zero
and is reaped. A pinned prior-core negative control exits one on the new cases.
The independent producers correct 5472 NORM result states and 32 CMPM flags;
all input registers, programs, memory, counts and other record metadata remain
unchanged. Fast normalization's 50240-case archive remains byte-identical.
