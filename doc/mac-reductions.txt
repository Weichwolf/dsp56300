Overflow-free MAC reduction windows

This extends the admitted MAC/paired-linear-load loops described in
mac-batching.txt. Instruction decoding, host memory/event contracts and entry
admission are unchanged. A scalar or AVX2 kernel selects its working
representation at a checkpoint from the accumulator value and remaining span.
No application signature or preset workload size participates in admission.

Representation             Maximum extent   State needed between checkpoints
four ordered prefixes      4 MACs           signed56 A, old X0/Y0, L, final V
four independent sums      16 or 64 MACs    four signed64 sums, initial A and L
canonical CPU              whole batch     final A/X/Y/R/LC/SR and retirement

Proof before reassociation

One signed24 fractional product, including subtract and minimum*minimum, has
magnitude at most P=2^47. For N admitted MACs let D=N*P. An entry accumulator in
[-2^55+D, 2^55-1-D] cannot overflow at any ordered prefix of those N instructions,
regardless of the data. Therefore no new sticky L can arise and terminal V is
zero. Incoming L remains unchanged. Four independent signed64 product sums may
be reduced in any order; for N<=64 their final fractional delta has magnitude
at most 2^53. Both reduction and accumulation fit signed64, with final A in
signed56. Other final flags still use the ordinary canonical commit rules.

Prefer 64 instructions if their span and proof hold, otherwise 16. When neither
larger reduction is admitted, process up to 16 instructions using the previous
four-prefix algorithm, retaining every intermediate overflow and wrapped
terminal step. Retry the larger proof at the next checkpoint. This amortizes
failed proof checks near the accumulator boundaries without assuming that a
later accumulator stays there. A final 4/8/12-instruction tail uses that same
prefix path. Existing entry validation reserves scalar loop cleanup and
prevalidates every consumed address and budget unit.

The pipeline is unchanged. Reduction term zero uses the old data registers;
terms 1..N-1 use RAM[0..N-2]. New X0/Y0 come from RAM[N-1]. In AVX2, the first
quad inserts the old inputs. Later quads load four contiguous preceding words,
sign-extend them, multiply with VPMULDQ and accumulate with VPADDQ. A horizontal
reduction occurs once per proven window. Independent lanes are partial sums of
one DSP instance, not voices or concurrently emulated DSPs. Signed24 masking,
24/48/56-bit state, transfer ordering and all general fallbacks remain exact.

Qualification

All 101 release and strict correctness tests pass with no skips (117.70 s and
448.08 s). All 112 C++ translation units retain nonrecovering ASan/UBSan/integer
instrumentation; all 148 project C++ sources/headers pass formatting. No policies,
dependencies or public architectural layouts change. All 41 archives remain
byte-identical. All 10368 FIR backend/case combinations and both 41-set bench
targets pass, with the same three explicit correctness-only skips (304 sampled
cases over 38 sets). No fuzz tests run. The ISA catalogue stays 118 partial rows;
a green structural audit does not establish full instruction qualification.

Directed tests perform 316526 batch/admission checks and 1680 observation checks.
Additional witnesses cover the exact 16/64-step interior endpoints, one unit
inside/outside, both accumulators/signs, full-scale minimum products, changing
window sizes, 16/64-step boundaries, mixed 124-instruction paths and 128-step
runs. Long warm JIT entries preserve exact budgets and scalar tails. Original
six-mode independent expectations remain unchanged. RAM faults, I/O acceptance,
rejection and P invalidation now also occur after 19/67 steps, including proven
larger windows. Complete callback state, original prefetched execution and
non-replay of completed prefixes remain required.

Working-set tradeoff

Clang 19 emits real YMM VPMULDQ and VPADDQ operations, followed by VZEROUPPER.
The AVX2 kernel's text grows from 512 to 2046 bytes; grouped prefix fallback is
unrolled by the compiler. Canonical Cpu (384 bytes), native entry context (128)
and owner (131648) retain their previous layouts. Neither these sizes nor a
small arithmetic loop proves that an arbitrary DSP program resides in L1.
General adaptive allocation and persistent register-bank caching remain open.

Controlled comparisons

One DSP instance per case, pinned to CPU 2, Clang 19 release, seven rotating
repetitions of parent dec7089, automatic, scalar, AVX2 and unbatched controls.
Archives and per-case replay counts match; each uses 64 warmups and nine trials.
No own compiler/test process runs concurrently; no other compiler load was
observed at the start of this final capture. Host governor remains unchanged. Nanoseconds are warm execution per
call, including timer/retirement-check overhead. MIPS count actual DSP retirement.

does not supply accepted absolute throughput.

A separate preset near-limit accumulator experiment stresses failed proof checks,
using an independently modeled, originally authored biased dot-product loop.
The initial per-quad admission attempt regressed about 10%. The final grouped
prefix fallback runs the three near-limit cases about 2-3% faster than parent;
it still checks every ordered prefix. This private diagnostic does not replace
public fixture qualification or establish representative audio throughput.

The diagnostic 304-case/38-set sweep passes all expected state/progress checks.

automatic on recheck; the FFT outlier measures 9707.54 vs 9742.28 ns. Short
timer/layout/frequency effects remain relevant. No zero-regression promise
or aggregate score hiding individual workloads is made.
