Host I/O contract

The embedder supplies derivative peripherals through Io. Guest X/Y accesses in
0xffff80..0xffffff are dispatched to that interface; P accesses use the supplied
program RAM. The CPU library supplies no peripheral register values or board
behavior. Without an accepting host callback, guest I/O stops with an explicit
fault and the instruction does not retire.

read/write exchange a 24-bit word. Returned read data is masked to 24 bits and
outgoing writes contain only 24 significant bits. The pc argument identifies
the accessing guest instruction, including each iteration of a REP body.

bit performs one host bit action. The CPU calls it once with the space, address,
instruction PC, bit index in [0,23] and BitAction. previous receives the bit's
value before the action. test observes without modification; clear, set and
change request read/modify/write as one indivisible action owned by the host.
The CPU does not synthesize this operation from separate read/write callbacks.
Conditional bit jumps and branches request test. Their tested bit does not
replace the DSP Carry flag. A rejected bit callback reports FaultKind::io_bit;
Fault.value contains the requested bit index. Invalid bit numbers fault before
address updates or callbacks.

VSL snapshots the old raw accumulator fields and requests an X write followed
by a Y write at the same effective address. It applies the normal per-space I/O
contract to each half; these are two synchronous callbacks, not an atomic pair.
Its address update is visible to the first callback. A rejected X half prevents
the Y request. A rejected Y half does not undo the accepted X write or the
address update. The instruction does not retire on either failure, and a later
run call does not replay it. This ordering also defines the final value when
X/Y spans alias. It is a library transfer/error contract; chip-specific bus
arbitration and peripheral side effects remain unqualified and must not be
inferred from it. Ordinary guest stores require no fabricated peripheral data.

Short/long displaced MOVE samples its effective address from the old R/M state
without implicit R/N writeback. A successful read then writes the explicit
destination, including an aliased address/modifier/control register. A rejected
read does not write that destination. Stores capture the source after address
calculation; a source SSH pop is visible to the callback and is not rolled back
on a rejected write. A failed pop prevents the write request. Stack overflow on
a destination SSH push is reported after its read, without modifying the stack.
Failures do not retire the instruction and later run calls do not replay it.
Callbacks observe the advanced PC, pre-retirement progress and any already
performed source effects. This is the library's explicit fail-stop contract,
not a qualification of chip bus-error arbitration or rollback.

L: long MOVE uses one effective address and requests X before Y. Both outgoing
words and their transfer flags are captured before the first write callback.
A rejected X half prevents the Y request. Long loads commit their register
result only after both reads succeed; no rejected half supplies destination
data. A rejected Y store does not undo the accepted X write. The computed AGU
update and already computed sticky transfer flags remain visible on failure.
No failure retires the guest instruction, and later run calls do not replay it.
Immediate and reserved EA-extension selectors are invalid for L: memory.

Class I X:R/R:Y MOVE snapshots the secondary accumulator source before the
primary transfer overwrites any accumulator/input register. It then commits
the destinations only after its memory read/write succeeds. Class II snapshots
the old accumulator and old X0/Y0, stores the accumulator, then commits X0/Y0
to that accumulator only on success. Address failures prevent bus activity;
rejected transfers preserve the already computed AGU/transfer flags and do not
commit the later register move or a parallel ALU. Both classes remain stopped
without replay after failure. Class II prohibits EA extensions; Class I permits
immediate data as a source only. These are the explicit synchronous library
transfer/error contracts, not hardware bus-error rollback or arbitration.

All callbacks run synchronously on the CPU execution thread. The host can inspect
state and read/write/load supplied RAM, including P, or clear code caches.
Host Core::read/write/load access the supplied spans directly. Program mutations
must use Core::write/load so decoded and native caches are invalidated. A P
change in a callback finishes the already fetched instruction, then fetches its
successor from the modified program. Register views during a callback can
reflect an in-flight instruction; they are not complete checkpoints.

Supplied RAM spans may overlap. X/Y writes that address the same host word as
program RAM invalidate both decoded instructions and native translations,
including an opcode preceding a changed extension word. This applies to guest
stores and host Core::write/load. A guest alias write finishes its fetched
instruction before a modified successor is fetched. Direct host mutation of an
X/Y word that aliases P is a program mutation too and must use Core::write/load.
The core tracks storage aliases without inventing a derivative memory map.

run, reset, set_registers and interrupt admission require stopped execution;
callback reentry into these operations is rejected. Io methods are noexcept;
the host must handle its own failures and return false to reject an access.
Core is owned by one execution thread. Synchronization with other host threads
and atomicity of peripheral/shared-memory operations belong to the embedder.

Instruction budgets count retired guest instructions on every backend. Progress
reports retired instructions and documented base costs, excluding calibrated
pipeline, IRQ-entry and external wait timing. The host admits interrupts at
stopped instruction boundaries; derivative arbitration and timed peripheral
events remain host responsibilities. Exact pipeline/event timing remains open.
Complete stopped CPU continuation uses Core::checkpoint/restore; the caller
separately restores matching memory/I/O. This opaque in-process handle is not an
external serialized state format. See doc/checkpoints.txt for layout checks,
fault recovery and allocation boundaries.

Stack returns and interrupt entry

Failed RTI/RTS pops stop before replacing PC/SR with an error return value.
The normal attempted-instruction PC advance remains visible on these library
faults; it is not a hardware stack exception model. Long interrupt entry checks
instruction fetch, the ordinary control EA and its push before changing PC/SR
or counting the JSR. A valid EA update already performed before a failed push
remains visible. Prior accepted vector instructions retain their effects and
retirement. Faults remain stopped without replay. Extended stacks, SE/UF and
automatic stack-error exceptions remain unimplemented/unqualified.
Successful injected vector instructions now contribute their documented base
costs to Progress. This fixes the previous zero-cost vector bookkeeping and does
not supply calibrated interrupt-entry, pipeline or external wait latency. JIT
native/helper counters describe generated run execution; host-injected vector
instructions use the general executor. Use architectural Progress for overall
guest retirement. The existing post-RTI/fast-service admission exclusion lasts
until one foreground instruction retires; run(0) cannot consume it. It remains
an explicit library policy pending full hardware pipeline/event qualification.

Pending software exceptions

Explicit ILLEGAL/TRAP/taken TRAPcc retire the request before vector execution.
Subsequent run budgets count each injected instruction, including one two-word
fast instruction; zero budgets cannot enter or advance a vector. A first vector
word may finish while the second remains pending. The callback pc identifies
the vector instruction; visible register PC is the selected foreground resume
address during a fast service. Canonical registers, prior vector/AGU effects and
pre-retirement Progress are observable. Callback P edits/cache clearing follow
the normal mutation contract and cannot discard pending work. Rejected I/O or
invalid/missing vector operands stop without replay or fabricated retirement.
Earlier accepted effects are retained; no transactional rollback is promised.
Host interrupt admission cannot overwrite pending work. Level three is accepted
even at IPL3 subject to the library's stopped-boundary/exclusion policy; long
entry clamps IPL at three. reset cancels hidden continuation. Register views
alone do not serialize pending/partially executed vectors. Internal instructions
run through the general executor and count as JIT helpers when run retires them;
synchronous Core::interrupt instructions count in architectural Progress only.
No derivative arbitration, automatic hardware fault source or calibrated IRQ
pipeline model follows from these contracts. See doc/exceptions.txt for details.

Architectural instruction-cache memory contract

Options declares one external cacheable P interval and the sector size. Default
eligibility is empty; no board map is inferred. With CE set, instruction fetch
and guest P data transfers use the separate DSP cache model described in
doc/program-cache.txt. Guest P writes are write-through on a sector hit; PMOVE
reads hit valid words without allocating or changing LRU. Host read/write/load
always access backing RAM. Host P-alias writes and guest data-space alias writes
invalidate translations but do not make DSP instruction storage coherent.
clear_code_cache preserves DSP cache contents/locks, just as it preserves pending
vector work. CE clearing and reset discard architectural cache state. Requests
outside supplied spans still fail; optional burst fills stop at interval/span
boundaries rather than accessing unavailable host memory or fabricating data.
This is a functional RAM contract, not a calibrated external bus or speculative
burst failure model. Derivative cache/PRAM remapping stays with the embedder.
Run budgets count retired guest instructions; CE-enabled general execution does
not prefetch/retire successors through JIT lookahead. No new I/O
reply or native dependency is added.

Sleep/wake and guest RESET

RunResult.state and Core::processing_state distinguish running, waiting and
stopped. WAIT/STOP retire once then return early, without advancing successors
or idle Progress. A valid unmasked Core::interrupt wakes WAIT. STOP rejects IRQ
admission until the host has modeled IRQA/clock stabilization and calls
resume_from_stop; it can then admit any highest enabled source or continue with
no IRQ. This completion is rejected in WAIT/running/faulted/reentrant execution.
All calls stay on the owning execution thread. run(0), cache clearing, host RAM
accesses and register initialization do not wake a sleeper; library reset does.

Io::reset_peripherals(pc) handles guest RESET synchronously, resetting the
consumer's peripherals/interrupt priorities before returning true. Its default
is false. No Io or rejection gives FaultKind::host_event at the instruction PC,
with no retirement/replay or fabricated reset registers. CPU/cache state stays
preserved in the functional model. Pre-retirement canonical registers/progress,
advanced foreground PC, vector pc arguments, P edits and the existing callback
rules apply. resume_from_stop is also prohibited callback reentry. Every legal
REP iteration requires its own acknowledgement. Accepted prior host/vector
and loop effects are retained after later failure. See doc/processing.txt for
exact budgets, fault context, clock ownership and unresolved hardware details.

Debug interface

ProcessingState::debugging is a distinct nonfaulted halt. set_debug_interrupt_mode
configures the functional IME selection, debug_status reports qualified IME/SWO,
request_debug completes a host DE/JTAG request, and resume_from_debug explicitly
leaves the halt and clears SWO. These mutations require stopped host execution;
callback reentry is rejected. Host clocks/security/JTAG signaling are not invented.
A host request from running/WAIT/STOP retires nothing, while IME-selected pending
vectors consume later positive budgets. Requests never replace active vectors;
repeat/partial-vector state and cache contents survive a debug halt or cache clear.
External requests do not set software occurrence; taken guest DEBUG/DEBUGcc do
so only when actually entering Debug mode. Configuring IME cannot erase a halt
cause or alter an already queued request. All debugger edits obey normal memory/
register mutation rules; they are not full OnCE pipeline/checkpoint restoration.
See doc/debugging.txt for queue identity, rejection, timing and qualification gaps.
