Native retirement checkpoints

The direct x64 JIT executes generated machine code in the host process. The
hardware virtualization experiment was removed at the user's explicit request.
This optimization reduces host bookkeeping in existing native regions; it does
not vectorize DSP audio samples or extend the qualified instruction set.

Admission and representation

Packed retirement requires optimization enabled, a nonempty region containing
at least four straight operations or a native loop continuation, every operation
already lowerable, and every instruction base cost nonzero. Moves require a
nonempty native transfer plan. Stores through X/Y aliases of P reject admission.
Other regions retain the scalar progress and PC publication path.

Helper-free regions already count successful instructions in R15D. At return,
MOVD zero-extends that count and PUNPCKLQDQ duplicates it into independent qword
lanes. A single unaligned load/PADDQ/store adds the pair to adjacent Cpu fields
instructions/cycles. Non-unit instructions add their extra cycles separately.
R15D is bounded by the existing 32-bit dispatch budget. The architectural qword
counters retain modulo-64-bit addition, including carries and wrap.

Transfer-capable regions keep the pending pair in XMM0 and a unit pair in XMM1.
Every successful native instruction adds one to each lane. Before a general
move helper, generated code materializes progress and dirty accumulators. After
the call it initializes both caller-saved SIMD temporaries before testing the
result. A rejected transfer therefore preserves its partial fault state and
the completed prefix without counting its unsuccessful ALU or replaying work.
Native RAM transfers avoid this callback checkpoint. Callbacks may freely
clobber XMM0/1/2. SSE2 is part of the x64 baseline; no AVX feature is required.

PC stores remain at transfers, before loop-ending guards, at the final operation
and on loop continuation. Native guard failures and dirty-code exits retain
canonical progress, PC and accumulator state. Existing repeat/interrupt exclusion
clearing still occurs per retired instruction. No Cpu, owner, NativeContext or
public interface layout changes are introduced. Single-thread ownership and the
existing memory/event contracts remain necessary; see doc/io.txt.

Independent evidence

The retirement-only qualification at b415608 performed 76794 directed assertions
in release and strict builds. An independent raw-56 arithmetic model supplies
full registers, frames and counts for mixed one/two-cycle bodies, six numerical modes, empty
entries, straight/loop regions, exact budgets, LC exit boundaries, stack slots,
saved same/other loop targets and 24-bit PC wrap. Initial counters cross 2^32,
2^63 and 2^64 independently. Literal SSE2 byte expectations are checked against
the encoder; a separate native stub proves MOVD zero extension through the
32-bit sign boundary and preservation of neighboring fields.

Actual Core tests warm native RAM paths before redirecting addresses to I/O.
Callbacks compare every register and both progress fields, destroy SIMD
temporaries, optionally invalidate the next P instruction, or reject either
access. Subsequent execution must preserve committed results without replay.
Negative admission tests include general helpers, unsupported numerical modes,
zero synthetic costs and aliased P stores. These are directed tests, not fuzzing.

At b415608 both complete direct-only suites passed all 95 tests without skips:
release 161.45 s and strict 499.22 s. All 40 public binary fixtures remain unchanged.
The structural ISA audit passes, while the complete-ISA gate still fails with
118 partial catalogue entries and zero complete entries. These tests qualify
the change's stated domains, not the complete DSP56300 architecture.

Single-instance workload measurements

Host: Intel Core i5-10400, Clang 19 release, CPU2 affinity, powersave governor
with dynamic frequency. The host is shared with other work; no exclusive-core,
fixed-frequency, energy or statistical-confidence claim is made. Each executable
uses 64 warmups and nine trials. Three process runs rotate parent/control/after
order. The table is the median of their three trial medians, in ns/call.

Parent is commit 5c7f4c8 and the retirement candidate is b415608. The admission-
disabled control uses the candidate compiler and runtime layouts, changing only
the positive admission return.
All 37 other core archive objects are byte-identical to the candidate. This
controls the selected optimization but does not equalize host text addresses
with the parent. Raw trials, hashes and control provenance remain ignored local
analysis. Both comparisons are necessary to expose a whole-change regression.

FFT calls are about 0.5-2.6% longer against the parent. The candidate beats
its admission-disabled control in these median results, but that does not
cancel a whole-change regression. Small differences on a shared host and
host text-layout effects require further controlled work.

These four cases execute one actual Core using the project's own independently
modeled DSP FFT. Core::run and timer/retirement checks are inside timing; host
RAM/register restoration and compilation are outside. Expected complete state,
RAM and progress are checked against the same public correctness fixtures.
No application or manufacturer program is required.

Throughput counts actual retired DSP instructions, not base-cost estimates or
host arithmetic. The representative 270 MIPS reference target is not achieved.
Continuous audio, full voices/effects, derivative I/O, whole-device realtime,
fixed-load CPU consumption and joules per audio block remain unqualified.
