KVM translation execution experiment

This is a Linux x86-64 test harness, not a public VM backend. It uses the
existing DSP JIT emitter, not a separate arithmetic implementation, to generate
native arithmetic regions. No guest OS, board emulation or external emulator
dependency is involved. The normal library/API is unchanged.

The test creates a VM/vCPU, a 2 MiB shared backing mapping, identity-mapped
long-mode page tables and a guest stack. Before enabling long mode it explicitly
installs the KVM-supported CPUID model and requires its long-mode feature.
The model disables x2APIC, TSC deadline and PV_UNHALT because this experiment
does not create an in-kernel local APIC. Generated code receives guest addresses
for the ordinary private CPU/runtime ABI and returns to an HLT boundary. All
runtime pointers remain null: the selected no-move operations require neither
host helpers nor latched-input storage. Guest addresses are never dereferenced
by host C++. An unbacked physical read is tested in a separate VM and must exit
as MMIO; the harness supplies no invented read result and never resumes it.

Qualification matrix: 1500 arithmetic runs cover all ten nonempty prefixes of
a MPY/MAC/add/negate/absolute/round/compare/transfer chain, three scaling modes,
two rounding modes and five signed-24 boundary values for each input bank.
Each run compares all architectural registers with the independent raw-56
sequence model, checks exact retirement/progress, hidden continuation fields
and the return/halt boundary. Actual release/strict execution of this matrix is
qualified below; it does not cover general DSP programs or the full ISA.

Build and run with the ordinary LLVM 19 release/strict presets:
  cmake --build --preset release --target dsp56300_kvm_translation_test
  ctest --preset release -R '^kvm-translation-experiment$' -V
  cmake --build --preset strict --target dsp56300_kvm_translation_test
  ctest --preset strict -R '^kvm-translation-experiment$' -V

KVM group access has been granted. Existing agent processes may retain their
previous groups; run the CTest command through `sg kvm -c '...'` in that session.
Do not hardcode a local account name. A transient named-user device ACL vanished
between early probes; the granted group membership works for both configurations.

Missing/inaccessible /dev/kvm produces exit 77 and an explicit CTest skip;
other setup or execution failures fail the test. A skipped test is not a
successful VM trial. CTest imposes a 60-second external timeout. The host C++
uses all normal warnings, hardening, format/tidy and strict sanitizers. Generated
guest instructions are not compiler-instrumented with ASan/UBSan.

Initial host evidence (2026-10-27): both configurations built, but executions
skipped on EACCES before any VM/vCPU or translated guest code could run.
Access follow-up (2026-10-28): granted group access allows VM/vCPU creation.
The first accessible runs failed at KVM_SET_SREGS with EINVAL. Installing the
explicit supported CPUID model fixes that setup failure. That increment passed
4501 assertions per test: 1500 translated arithmetic runs with three assertions each,
plus the separate unbacked-memory MMIO exit. CTest wall times are 0.11/0.23 s
for release/strict, including VM setup, generation, state checks and teardown.
These are correctness-test durations, not guest throughput or a JIT comparison.
The existing public arithmetic emitter and independent model are unchanged.

Prepared-entry follow-up: Guest::prepare installs code once, enter executes it
without reinstalling, and run(code) preserves the prior combined interface.
Automatic entry uses KVM_CAP_SYNC_REGS GPR exchange when available, with an
explicit SET/RUN/GET ioctl path as the control/fallback. Both paths now execute
the original 1500-case matrix and memory-exit test, plus preparation boundaries:
9016 assertions per configuration. A companion concept-checked direct/KVM
region experiment passes 864 checks over six supported modes and repeated
guarded loop entries. It also measures identical emitted code with fixed
affinity and three runs. See doc/kvm-performance.txt for protocol, measured
entry costs, the remaining long-region gap and the exact limits.
Unhandled non-HLT exits and failed entries make the guest terminal; reentry
or preparation is rejected instead of implicitly completing a pending MMIO
transaction. Only a completed HLT boundary permits another prepared entry.

Scope limits: this checks a small helper-free arithmetic region and one memory
exit only. General DSP programs, RAM-transfer plans, protected code pages,
helper/event/I/O exits, code invalidation, general budgets/interrupts and the transparent
consumer backend remain unimplemented in KVM. This harness is neither a sandbox
security qualification nor a realtime workload benchmark. In particular it
does not show a KVM speedup or host-load reduction at the 270 MIPS reference load.

API reference: https://docs.kernel.org/virt/kvm/api.html
CPU-model references: KVM_GET_SUPPORTED_CPUID, KVM_SET_CPUID2 and their local
APIC feature restrictions in the same official API documentation.
