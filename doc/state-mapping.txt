DSP state mapped to host resources

This is the state inventory and next compiler design, not a claim that adaptive
allocation or SIMD register-bank caching is already implemented. Current native
code holds dirty A/B in RBP/RBX and, in admitted regions, SR in R14D; SSE2
combines retirement counters. X/Y and AGU values still use canonical memory.

Architectural aliases, unshifted DSP bit coordinates

Bank      Low field          Middle field        High field
A         A0: bits 0..23     A1: bits 24..47      A2: bits 48..55
B         B0: bits 0..23     B1: bits 24..47      B2: bits 48..55
X         X0: bits 0..23     X1: bits 24..47      zero padding
Y         Y0: bits 0..23     Y1: bits 24..47      zero padding

Aliases share storage. A partial write preserves the other fields. A full A/B
bus read is scaled/clipped to a word; it is not a raw 56-bit copy. A full-word
accumulator write sign-extends into the middle/extension coordinates. Internal
A/B arithmetic shifts these 56 significant bits left by eight so host OF/CF can
describe full arithmetic. Any alternate representation needs exact adapters.

Registers alone are not a checkpoint of REP, vectors, sleep or cache state.
The general executor remains authoritative for still-unqualified cases. Full
hardware modes, extended stacks, pipeline/events and complete OnCE state remain
unqualified or unimplemented; this inventory does not close those ISA gaps.

Current Clang 19 x64 sizes/offsets (measured, not a cache-miss result)

Registers=296 bytes; alignas(64) Cpu=384; NativeContext=104.
Each row below is one 64-byte Cpu cacheline:

Line  Byte range  Contents
0     0..63       X/Y/A/B (32 bytes), R[0..7] (32)
1     64..127     N[0..7] (32), M[0..7] (32)
2     128..191    ten PCU/control words (40), first 24 bytes of frames

Frequently touched state is small, but the full owner, program/data working set
and generated hot code are separate. A virtual mapping/allocation size does not
establish L1 residence. Measure actual working sets and misses when available.

Pattern-dependent candidate mappings

Pattern           Prefer GPRs for       Prefer SIMD for       Canonical cold state
MAC/FIR           live A/B, active R/N   X/Y words, old inputs frames, unused AGU
IIR/feedback      recurrence A/B, R      live inputs/coeffs    inactive sections
FFT butterfly     A/B, active cursors   X/Y/product pairs     outer setup/control
address-heavy     active R/N/masks       other AGU banks       unused arithmetic
short selection   pointers, predicates  candidate values      untouched state
control/IRQ       PCU/frames as needed  little persistent     authoritative owner

These are candidate roles, not fixed register numbers. Host RSP and runtime
pointers/counts consume part of the GPR file; SIMD values also require scratch
lanes, extraction, sign extension and ABI save/reload work. Packing every Cpu
byte into SIMD simply because it fits can make ordinary operations slower.

Two X/Y formats to compare (one conceptual bank)

Format             SIMD low-to-high words            Benefit / conversion cost
raw48              [X0 bits24 | X1 bits24 | zero]    cheap full48, word extraction
signed-word lanes  [sx24(X0), pad, sx24(X1), pad]    signed products, full48 adapter

The second format can feed signed widening products, but it requires explicit
packing at canonical boundaries and cannot change quantization. SSE/AVX feature
guards and a baseline path remain required. Product pairing, helper frequency,
live ranges and shuffle/extract pressure decide which form wins for a region.

Example parallel MAC dataflow

Phase             X/Y input to MAC      Newly fetched words    A
entry             old X0, old Y0        not committed          old A
guards            unchanged            addresses validated    unchanged
capture           old values retained  prospective X0/Y0      unchanged
commit move       old snapshot live    new X0/Y0 visible      unchanged
ALU/retire        consume old snapshot next instruction uses  wrapped/flagged sum

The snapshot may be a register copy rather than an owner-memory store. A slow
helper must reconstruct the same old-input relation. Clipping S/L, Carry and
numeric-mode dependencies belong in the effect graph, including indirect aliases.

Adaptive allocation pipeline (remaining implementation work)

  decode/effects -> basic region and live ranges -> candidate representations
       -> register pressure/shuffle/spill/helper cost -> native code + guards
       -> observed execution mix -> bounded recompile/version choice

Selection uses operations and dependencies, not application names or signatures.
Control variants by code version, numeric/loop context, actual memory/alias bounds
and any specialized modifier assumptions. Keep cold compile cost separate from
warm execution. Publish replacements only at a safe owner boundary; never free
currently executing code. Cross-region links need explicit mapping adapters.
The current JIT has mode/loop keys and guards, but no adaptive allocator yet.

First useful allocation experiments

Region trait           Potential use of a scarce host GPR    Required proof
FIR with B unused      reuse B's slot for LC/active cursor    no B read/write in region
FFT with A and B live  keep both arithmetic slots; spill LC   exact helper/loop checkpoints
MAC without observers compute result flags at exits/slowpath live result/overflow retained

These are experiments, not implemented selections. The original FIR fixture
keeps a nonzero unused B, so an accidental spill of a reused host slot is visible
in its independent full-register expectation. SIMD old-input caches and delayed
flags similarly require tests that overwrite the corresponding canonical banks.

Guarded loop-vectorization candidate

For a MAC loop with two read-only contiguous unit-stride input streams and no
intermediate rounding, four ordered products can be evaluated with AVX2.
This is a proposed compiler pattern, not a whole-program signature or a current
native path. Required state adapters include:

DSP effect          Vector representation / proof obligation
old X0/Y0           prepend old word before the next three loaded words
next X0/Y0          retain the fourth fetched word after the four retirements
A and V/L           modulo56 prefix sums; every ordered overflow, not final sum only
ordinary flags      final logical guest result, or a reconstructed stopped prefix
R/LC/PC/counts      exact four-step updates; no final-loop cleanup inside the chunk
memory              prevalidate both spans, modifiers, no-wrap and I/O exclusion

LC and remaining budget must cover the chunk; partial tails, possible I/O,
invalid bounds/modifiers and per-instruction quantization retain scalar/general
execution. MACR cannot use plain reassociation. Mode guards, CPU AVX2 support,
old/new aliases and checkpoints remain mandatory. Compare total flag/adapter
cost against scalar holding before choosing this representation at runtime.

Observation and transition matrix

Transition                  Must be canonical/coherent before observation
ordinary pure operation     live native values; exact eventual flags/progress
parallel transfer           old inputs, ordered effects, address/flag prefixes
failed address guard        no speculative architectural update before fallback
I/O or general helper       SR, accumulators, progress, PC, any new bank cache
helper success              reload changed banks/flags and caller-saved SIMD
helper failure              preserve helper partial state; no stale cache flush
loop continue               LC/current frame/start/budget guards, exact prefix
final loop/stack failure    saved frames/flags, canonical before general cleanup
short/zero budget          only allowed prefix; no invented next instruction
IRQ/vector/debug/sleep     complete admitted architectural/in-flight state
P write/alias/invalidation  current fetched instruction, versions, safe code life
host register/mode change  stop/mutation contract; reject stale specialization

Different mappings are valid only if every applicable row still holds. Tests
must include all dirty-bank combinations, alias directions, boundary values,
helper SIMD clobbers, failures, partial budgets and transitions between mappings.

SIMD evaluation of both branch outcomes (experiment, not implemented)

Value/effect         Candidate A lane      Candidate B lane      Architectural commit
arithmetic value     fA(old inputs)        fB(old inputs)        select by predicate
ordinary flags       flagsA                flagsB                selected flags
sticky S/L           old | additionsA     old | additionsB     selected additions
R/PC/retirement      nextA/countA          nextB/countB          selected exact prefix
memory/I/O           staged or forbidden  staged or forbidden  chosen ordered effects

Both candidates must be safe to evaluate. Unchosen loads cannot fault, perform
I/O or invalidate code. Predicated arithmetic does not break a causal recurrence
y[n]=f(x[n],y[n-1]). A short pure coefficient selection is a different candidate
from a whole feedback loop. Compare extra arithmetic/extract work with measured
branch behavior; predictable counted backedges alone do not justify speculation.
Budget tails, events and unsupported effects retain general execution.
